# Архитектура и границы

SIMAI Framework даёт несколько уровней готовности: от общего визуального языка
до интерактивных частей страницы. Выбирайте самый простой уровень, который
полностью решает задачу; проходить всю цепочку для каждого элемента не нужно.

```text
Токены и Core
  → утилиты
    → компоненты
      → Smart-компоненты
        → комплексные Smart-компоненты
          → блоки
            → секции и Layout
              → страницы
                → backend и Larena
```

## Что делает каждый уровень

| Уровень | Что он добавляет | Чего в нём быть не должно |
|:---|:---|:---|
| Токены и Core | Цвета, размеры, типографику, темы и базовые условия | Данных и бизнес-правил |
| Утилиты | Одно небольшое правило компоновки или оформления | Готового пользовательского сценария |
| Компоненты | Повторяемую структуру элемента интерфейса | Серверных прав и сложной прикладной логики |
| Smart-компоненты | Состояние, поведение, события и программный контракт | Решений о доступе к данным |
| Комплексные Smart-компоненты | Согласованное поведение нескольких элементов | Копий внутренних реализаций дочерних компонентов |
| Блоки | Смысловую единицу страницы, привязку данных, настройки и выбор представления | Повторной реализации поведения Smart-компонентов |
| Секции и Layout | Области, порядок и композицию страницы | Сохранённого HTML как модели страницы |
| Страницы | Конкретный сценарий и состав секций | Внутренних реализаций подключённых уровней |
| Backend и Larena | Данные, операции, права и предметные возможности | Фронтенд-разметки как источника бизнес-правил |

Простой экран может использовать только токены, утилиты и обычные компоненты.
Smart нужен, когда появляются состояние, события или управляемый жизненный
цикл. Блок нужен, когда часть страницы получает собственный смысл, настройки и
источник данных.

## Как проходит работа с данными

Backend передаёт проверенную модель представления в зарегистрированный Smart-
компонент или блок. Затем представление собирается из более простых уровней:

```text
Backend → Page/Layout → Section → Block → Smart
                                      ↓
                         Component → Utility → Token
```

HTML остаётся результатом рендера и форматом примера. Архитектуру страницы,
идентификаторы, порядок и допустимые параметры следует хранить в проверяемых
декларативных данных, а содержание — в предназначенном для него хранилище.

## Smart runtime

Текущая поставка использует общий `smart-base.js` и стандартные Custom Elements.
Публичный контракт Smart-компонента состоит из имени элемента, атрибутов,
состояний, методов и событий. Loader подключает объявленные CSS- и JavaScript-
модули, а базовый класс обеспечивает регистрацию, обновление и освобождение
ресурсов при удалении элемента.

Это целевой декларативный runtime для компонентов, а не новый аналог React или
Vue. Он не берёт на себя маршрутизацию приложения, серверные операции и
предметную модель. Внутренняя реализация может включать поставляемые вместе с
Framework вспомогательные библиотеки, но потребителю не требуется выбирать тот
же прикладной JavaScript-фреймворк.

Конкретные атрибуты и события проверяйте на странице компонента и в его
manifest. Наличие записи в каталоге ещё не означает одинаковую готовность всех
Smart-компонентов.

## Границы продуктов

- **SIMAI Framework** владеет фронтенд-языком: токенами, Loader, утилитами,
  компонентами, Smart-контрактами и правилами их композиции.
- **Docara** применяет этот язык к документации и статическим сайтам. Она
  компилирует Markdown и декларативные структуры, но не становится backend CMS.
- **Larena** продолжает архитектуру на стороне Laravel: владеет данными,
  операциями, правами, пакетами и прикладными возможностями.
- **Bitrix и другие backend-хосты** подключают нейтральные контракты Framework
  через собственные адаптеры. Адаптер не становится владельцем общего
  фронтенд-контракта.
- **AI First** описывает, как ИИ обнаруживает и читает те же знания и контракты,
  что человек. Это не второй ручной каталог и не замена Framework, Docara или
  backend API.

Подключение Framework не требует Larena. Docara и backend-адаптеры являются
потребителями, а не обязательными частями браузерного runtime.

## Действующий контракт и развитие

Публичные классы, токены и API определяются точной установленной поставкой,
registry и страницами справочника. Архитектурное направление может быть шире
текущего runtime. Такие возможности становятся доступными только после
реализации, сборки, проверки совместимости и обновления документации.
