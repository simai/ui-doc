# Адаптивная система размеров

SIMAI Framework использует одну шкалу примитивов A–I и семантические роли,
которые переключают значения между mobile и desktop. Разработчик выбирает
роль, а не пишет отдельные пиксели для каждого экрана.

## Три независимые оси

1. **Viewport mode** — mobile или desktop. Единственная граница режима:
   `960px`.
2. **Semantic size** — роль `1/3`, `1/2`, `1`, `2`, `3` и другие роли
   типографики или интервалов.
3. **Tightness** — `low`, `default`, `high`, `highest`; меняет только
   вертикальную плотность control.

Не используйте tightness как замену размеру и не добавляйте второй media query
в компоненте. Компонент должен читать semantic variables.

## Root и rem

`1rem` сохраняет пользовательский browser default. Framework не уменьшает
корневой размер шрифта на мобильном viewport. Адаптивность задаётся парами
semantic variables, поэтому повторного масштабирования через `html` нет.

Основная типографическая роль назначается на `body` или application shell.

## Typography pair

Размер шрифта и высота строки — разные variables. Они используют одну роль, но
могут ссылаться на разные primitive values. Например, исправление `text-12`
связывает `fontSize` с size variable, а `lineHeight` — с отдельной
line-height variable.

## Высота control

Для Button, IconButton, Input, текстового Select и однострочного Textarea
действует формула:

```text
control-height = line-height + 2 × block-padding
```

Рамка учитывается внутри итоговой высоты. При одинаковых size и tightness
допустимое расхождение между representative controls — не более `0.5 CSS px`.

Точный текущий runtime публикует пять ролей высоты control:

| Роль | Mobile | Desktop | Токен |
|:---|---:|---:|:---|
| `1/3` | `1.5rem` | `1.75rem` | `--sf-ui-1/3--control-height` |
| `1/2` | `1.75rem` | `2rem` | `--sf-ui-1/2--control-height` |
| `1` | `2.25rem` | `2.5rem` | `--sf-ui-1--control-height` |
| `2` | `2.75rem` | `3rem` | `--sf-ui-2--control-height` |
| `3` | `3.25rem` | `3.5rem` | `--sf-ui-3--control-height` |

`1` означает стандартную ступень. Дробные роли меньше стандартной, целые роли
`2` и `3` — больше. Mobile и desktop могут иметь разные физические значения,
но сохраняют один смысловой размер. Конкретный компонент может поддерживать не
все роли: допустимый набор определяется его документацией и manifest.

## Согласованная шкала развития

Архитектура платформы задаёт общую шкалу `1/5`, `1/4`, `1/3`, `1/2`, `1`, `2`,
`3`, `4`, `5`. Она нужна, чтобы разные семейства элементов одинаково понимали
«меньше стандартного» и «больше стандартного».

| Роль | Mobile | Desktop | Статус в текущем Core |
|:---|---:|---:|:---|
| `1/5` | `1.25rem` | `1.25rem` | направление развития |
| `1/4` | `1.25rem` | `1.5rem` | направление развития |
| `1/3` | `1.5rem` | `1.75rem` | доступна |
| `1/2` | `1.75rem` | `2rem` | доступна |
| `1` | `2.25rem` | `2.5rem` | доступна |
| `2` | `2.75rem` | `3rem` | доступна |
| `3` | `3.25rem` | `3.5rem` | доступна |
| `4` | `4rem` | `4.25rem` | направление развития |
| `5` | `4.75rem` | `5rem` | направление развития |

Не используйте ещё не опубликованные роли как CSS-переменные или значения
компонента. Они станут публичным контрактом только после появления в runtime,
registry, Loader и документации одной точной поставки.

## Что система не обещает

Вертикальный контракт не выравнивает между разными компонентами:

- menu nesting и отступ следующего уровня;
- icon/label slots;
- inline padding и horizontal gap;
- container width и gutters.

Эти значения можно выбирать из той же primitive scale, но их совпадение не
является системным invariant.
