# Пример: составной интерфейс

Составной интерфейс удобно проектировать как дерево секций, колонок, блоков и Smart-компонентов. Сначала фиксируют видимые области и поток данных, затем подключают только те типы, чьи контракты уже подтверждены.

## Когда применять

Этот подход подходит для кабинета, панели показателей или рабочего места оператора. Он предотвращает появление одного огромного компонента, который одновременно рисует интерфейс, получает данные и управляет правами.

## Как читать документ

Панель можно разделить на секцию сводки и секцию таблицы. Сводка состоит из проектных карточек показателей. Таблица становится комплексным Smart-компонентом только после регистрации её слотов, свойств и событий. До этого документ хранит проверяемый каркас, а проект подключает данные к подтверждённым узлам.
