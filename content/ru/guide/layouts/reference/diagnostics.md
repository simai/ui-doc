# Ошибки и диагностика

Каждая ошибка содержит код, путь до проблемного значения и понятное сообщение. Путь позволяет редактору подсветить конкретный узел или поле, а код остаётся устойчивым для автоматической обработки.

## Когда применять

Показывайте диагностику рядом с исходным JSON и блокируйте публикацию при ошибках. Не заменяйте подробности одним сообщением «неверный документ»: разработчику и ИИ нужен точный путь исправления.

## Пример

Пример `unsafe-link` в инспекторе содержит `javascript:` в ссылке. Проверка возвращает `unsafe_url` и путь к `href`. Исправление адреса на `/catalog/` делает документ допустимым. Аналогично выявляются повторяющиеся ID, неизвестные типы и слоты, превышение лимитов и отсутствующий способ рендеринга.

```json
{
  "code": "unsafe_url",
  "path": "/root/slots/default/0/data/content/0/href",
  "message": "Схема адреса запрещена"
}
```

По `path` редактор может подсветить точное поле, а по `code` — предложить безопасное исправление.
