# Снимок данных и кеш

Перед сборкой продукт создаёт снимок разрешённых настроек и содержимого. У каждого значения есть происхождение, ревизия и отпечаток. Framework проверяет эти сведения и возвращает список только тех входов и шаблонов, которые действительно участвовали в результате.

## Когда применять

Снимок нужен, чтобы одна страница не смешала старый шаблон с новым содержимым. Список зависимостей нужен кешу: страницу пересобирают, когда изменилось что-то использованное, а изменение неактивного варианта её не затрагивает.

## Пример

При краткой шапке результат зависит от шаблона статьи, фрагмента `header.compact`, настройки `headerMode` и текста статьи. `header.expanded` в список не входит. Повторное обращение к одному входу внутри сборки использует уже прочитанное значение.

```json
{
  "references": [
    { "kind": "template", "ref": "article", "revision": "r1" },
    { "kind": "fragment", "ref": "header.compact", "revision": "r1" }
  ],
  "inputs": [
    { "name": "headerMode", "resolution": "provided" },
    { "name": "body", "resolution": "provided" }
  ]
}
```

Ключ кеша продукта должен учитывать digest готового Document и execution contract. Framework сообщает зависимости, а решение о хранении, сроке жизни и активации кеша принимает продукт.
