# Рабочая область

**Рабочая область** — раскладка экрана приложения: рельс, список, основная
область и панель, например список разговоров, открытый разговор и просмотр
источника. Она следует за шириной своего блока, а не окна браузера, поэтому
работает и внутри чужой страницы, и в боковой панели. Стили лежат в
`core.css`, сценарий — в `core.js`; отдельно ничего не загружается.

## Разметка

Области — прямые дочерние элементы `.sf-workspace` в этом порядке; каждая
необязательна. Порядок в разметке — это порядок чтения и переходов по `Tab`.
Рабочая область занимает высоту родителя, и каждая область прокручивается сама.

- `.sf-workspace-rail` — рельс;
- `.sf-workspace-list` — список;
- `.sf-workspace-main` — основная область, внутри неё кнопка
  `.sf-workspace-back`;
- `.sf-workspace-panel` — панель.

## Как она перестраивается

| Ширина блока | Что на экране |
|:---|:---|
| от широкой (64rem) | рельс, список, основная область и открытая панель рядом |
| от средней (40rem) | рельс, список и основная область; открытая панель выезжает поверх |
| уже | список с рельсом либо основная область; открытая панель выезжает поверх |

Границы задают классы, потому что запрос к контейнеру не читает переменные:
`sf-workspace--split-g6`, `-h0`, `-h2`, `-h4` (32, 40, 48, 56rem; по умолчанию
`h0`) и `sf-workspace--wide-h4`, `-h6`, `-h8`, `-i0`, `-i2` (56, 64, 72, 80,
96rem; по умолчанию `h6`). Средняя граница должна быть меньше широкой.

Ширины областей — публичные переменные:

| Переменная | По умолчанию | Что задаёт |
|:---|:---|:---|
| `--sf-workspace-rail` | `auto` | ширину рельса; без значения — по содержимому |
| `--sf-workspace-list` | `var(--sf-g0)`, 20rem | ширину списка рядом с основной областью |
| `--sf-workspace-panel` | `var(--sf-g1)`, 22rem | ширину панели — колонкой и поверх |
| `--sf-workspace-gap` | `var(--sf-0)` | расстояние между областями |
| `--sf-workspace-divider-color` | `var(--sf-outline-variant)` | цвет линии между областями |
| `--sf-workspace-drawer-background` | `var(--sf-elevation-4--surface)` | фон панели поверх |

Основная область занимает остальное. В документе с письмом справа налево рельс
стоит справа, а панель выезжает слева.

## Состояние

Состояние задают атрибуты на `.sf-workspace`:

- `data-sf-workspace-view="list"` или `"main"` — какую область показывает узкий
  блок; иначе показан список. От средней ширины атрибут не действует.
- `data-sf-workspace-panel="open"` — панель открыта; без него её не видно ни
  при какой ширине. Открытая панель остаётся открытой при смене ширины.
- `data-sf-workspace-list="hidden"` — списка нет при любой ширине, например
  когда в боковой панели открыт один разговор; кнопки «Назад» тогда тоже нет.

## Узкий экран и кнопка «Назад»

`.sf-workspace-back` видна только в узком блоке, когда показана основная
область и есть куда вернуться. Нажатие показывает список, вызывать ничего не
нужно; чтобы обработать нажатие самому, вызовите `preventDefault()`.

Открытую строку списка отметьте `aria-current`: при возврате к списку фокус
встанет на неё. При переходе к основной области фокус встаёт на кнопку
«Назад». Фокус перемещается, только если скрылась область, в которой он был.

## Панель поверх

Ниже широкой границы открытая панель выезжает поверх основной области с
затемнением остальной рабочей области. Пока она поверх, она ведёт себя как
[выезжающая панель](/ru/smart-components/overlays/drawer/):

- фокус переходит внутрь;
- остальные области недоступны (`inert`), `Tab` остаётся в панели;
- `Escape`, если панель — верхний слой, и нажатие на затемнение закрывают её;
- при закрытии фокус возвращается туда, откуда её открыли.

При `prefers-reduced-motion: reduce` панель появляется без движения.

## Сценарий

```js
const workspace = SF.workspace(element);
workspace.show('main');   // или 'list'
workspace.panel(true);    // открыть; panel(false) закрывает, panel() переключает
workspace.view;           // 'list' или 'main'
workspace.panelOpen;      // true или false
workspace.layout;         // 'narrow', 'split' или 'wide'
```

Атрибуты работают так же: ядро следит за ними на каждой `.sf-workspace`.
Рабочая область, вставленная позже с уже открытой панелью, подхватывается при
первом изменении атрибута, первом нажатии или вызове `SF.workspace(element)`;
в таком случае вызовите его сами. Внутри теневого DOM ядро области не
отслеживает.

На элементе всплывают события, каким бы способом ни изменилось состояние:

- `sf-workspace-view` — `detail: {view}`, когда изменился показанный вид;
- `sf-workspace-panel` — `detail: {open}`, когда панель открылась или
  закрылась, но не когда она только перешла из колонки в положение поверх.
