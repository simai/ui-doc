# Обновление блока

На рабочей странице часто есть блок со своими переключателями: график с
периодом «неделя / месяц», таблица со своим фильтром, счётчик. Когда человек
нажимает такую ссылку, достаточно перерисовать один блок, а не всю страницу.
Это делает `SF.FragmentRefresh` из ядра Framework по стандарту
[«Фрагмент интерфейса»](/ru/guide/layouts/building/interface-fragments/)
(`simai.interface-fragment` 1.1.0, контракт 1).

Блок объявляется разметкой; своего кода для блока продукт не пишет. Ссылки и
формы блока остаются обычными `<a href>` и `<form method="get">`: без
JavaScript каждая загружает страницу с нужными параметрами адреса.

## Включение

Оболочка страницы включает обновление один раз:

```html
<script>
  SF.FragmentRefresh.enable({scope: '/admin'});
</script>
```

| Настройка | Что задаёт | По умолчанию |
|:---|:---|:---|
| `scope` | начало пути, под которым работает обновление | `/` |
| `onFullLoad` | функция `(url, reason)` вместо полной загрузки страницы | — |
| `timeoutMs` | сколько ждать ответа, мс | `10000` |

| Член | Что делает |
|:---|:---|
| `enable(options)` | Включает обновление блоков на странице; повторный вызов заменяет настройки. |
| `disable()` | Выключает его и прерывает запросы, которые ещё идут. |
| `refresh(element, url, {history})` | Обновляет блок по адресу из скрипта; `history` — `push` (по умолчанию), `replace` или `none`. |
| `contract` | `1` — версия контракта, которую понимает ядро. |
| `enabled` | `true`, пока обновление включено. |

Объект доступен сразу после выполнения `core.js`, начиная с `core.runtime`
1.69.0, и ничего не делает до `enable()`.

## Разметка блока

```html
<section data-sf-fragment="env.load-history"
         data-sf-fragment-keys="period scale"
         data-sf-fragment-mode="data"
         data-sf-fragment-contract="1">
  <nav aria-label="Период">
    <a href="?period=7d">Неделя</a>
    <a href="?period=30d">Месяц</a>
  </nav>
  <nav data-sf-fragment-history="replace" aria-label="Шкала">
    <a href="?scale=linear">Обычная</a>
    <a href="?scale=log">Логарифмическая</a>
  </nav>
  <sf-chart-line data-sf-fragment-part="network"></sf-chart-line>
  <script type="application/json" data-sf-fragment-data>{"parts": {"network": {"data": []}}}</script>
</section>
```

| Атрибут | Что задаёт |
|:---|:---|
| `data-sf-fragment` | Имя блока, уникальное на странице, с точкой: `env.load-history`. |
| `data-sf-fragment-keys` | Параметры адреса, которые принадлежат блоку, через пробел, до 16. |
| `data-sf-fragment-mode` | `data` — сервер отвечает данными для частей блока; `html` — разметкой блока целиком. |
| `data-sf-fragment-contract` | `1` — версия контракта. |
| `data-sf-fragment-reads` | Параметры другого блока, от которых зависит этот блок; необязателен. |
| `data-sf-fragment-port` | Порт данных блока `<стандарт>@<старшая версия>`; необязателен. |
| `data-sf-fragment-part` | Часть блока в режиме `data`, которой сервер передаёт поля. |
| `<script type="application/json" data-sf-fragment-data>` | Первые данные блока в режиме `data`, в том же виде, что ответ сервера. |
| `data-sf-fragment-history="replace"` | Ссылки группы заменяют запись истории, а не добавляют новую. |
| `data-sf-fragment-sets` | Какие параметры задаёт ссылка или её группа, если это не видно по ссылкам группы. |
| `data-full-load` | Ссылка или форма внутри блока загружает страницу целиком. |

У каждого параметра адреса один владелец. Если два блока объявили один
параметр или одно имя, оба становятся обычными: их ссылки загружают страницу
целиком, в консоли одна ошибка, на документе событие `sf-fragment-conflict`.

## Какие ссылки берёт обновление

Ядро берёт ссылку или форму `GET` блока, только если её адрес на том же
источнике и пути, что страница, и отличается только параметрами этого блока
или других блоков (якорь не считается). Параметр, которого не объявил ни один
блок, принадлежит странице: его смена, другой путь, `POST`, клавиши `Ctrl`,
`Cmd`, `Shift`, `Alt`, `target`, `download` и `data-full-load` остаются
браузеру или [навигации по областям](/ru/guide/layouts/building/region-navigation/).

## Запрос и ответ сервера

Ядро отправляет `GET` по адресу ссылки (параметры других блоков — как на
странице) с заголовками `X-SIMAI-Fragment: <имя блока>`,
`X-SIMAI-Fragment-Mode: data` или `html` и `X-SIMAI-Fragment-Contract: 1`.
Сервер отвечает статусом 200 без перенаправления, возвращает те же
`X-SIMAI-Fragment` и `X-SIMAI-Fragment-Contract`, ставит `Vary` на оба
заголовка запроса и `Cache-Control: private, no-store`.

Ответ в режиме `data` — JSON до 256 КБ:

```json
{
  "fragment": "env.load-history",
  "contract": 1,
  "state": "populated",
  "url": "/admin/servers/12?period=30d&scale=linear",
  "keys": {"period": "30d"},
  "parts": {"network": {"data": []}}
}
```

- `state` — `populated`, `empty` или `no-access`; блок получает
  `data-sf-fragment-state`, части без своего состояния — `data-state`.
- `url` и `keys` — адрес, который применил сервер; ядро записывает его в
  адресную строку.
- `parts` — только части этого блока и только их поля: свойства элемента или
  атрибуты `data-*`.

Ответ в режиме `html` — внешний элемент блока целиком, один корень с тем же
именем блока.

Ответ сначала проверяется целиком и только потом рисуется одним шагом. Затем
записывается адрес: новая запись истории, а для группы с
`data-sf-fragment-history="replace"` — замена текущей. Прокрутка не
сдвигается, фокус остаётся на нажатой ссылке, `aria-current` переходит на
ссылки с применёнными значениями.

## Пока ответа нет и если что-то не так

- На один блок — один запрос: новый прерывает прежний, опоздавший ответ
  отбрасывается.
- Через 150 мс внутри блока появляется скелет; высота блока не меняется.
- Сбой сети, ожидание дольше 10 с или ответ 5xx — внутри блока состояние
  ошибки с кнопкой повтора (`sf-fragment-error`).
- Ответ 4xx, перенаправление, нет или другой подтверждающий заголовок, другое
  имя, корень, часть, порт или контракт, другой тип или неверный JSON —
  страница загружается целиком по этому адресу (`sf-fragment-fallback` с
  причиной). Так сервер сам показывает вход, «нет доступа» или «не найдено».
  Наполовину нарисованного блока не бывает.
- Обновления по таймеру в контракте 1 нет.

## Связанные блоки, «Назад» и «Вперёд»

Блок, который сменил свои параметры, сообщает об этом событием
`sf-fragment-parameters`; каждый блок, который читает эти параметры
(`data-sf-fragment-reads`), обновляется своим запросом. Адрес записывает
один раз владелец параметров.

«Назад» и «Вперёд» между записями, которые отличаются только параметрами
блоков, обновляют эти блоки без перезагрузки страницы. Записи истории ядро
отмечает своей меткой; записи, которые продукт пишет сам, ядро не трогает.

## События

| Событие | Когда | `detail` |
|:---|:---|:---|
| `sf-fragment-refresh` | перед запросом; можно отменить | `{fragment, url, mode}` |
| `sf-fragment-load` | блок нарисован | `{fragment, url, mode, state}` |
| `sf-fragment-error` | состояние ошибки с повтором | `{fragment, url, reason}` |
| `sf-fragment-fallback` | вместо обновления страница загружается целиком | `{fragment, url, reason}` |
| `sf-fragment-parameters` | блок сменил свои параметры | `{type: 'parameters-changed', value, fragment}` |
| `sf-fragment-conflict` | на странице параметр или имя с двумя владельцами | `{kind, name, ids}` |
