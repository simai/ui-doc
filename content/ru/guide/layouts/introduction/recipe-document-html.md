# Recipe, Document и HTML

`Recipe` — это инструкция по сборке страницы. В ней указаны шаблоны, места вставки, настройки и ссылки на содержимое. `Document` — уже собранное дерево: все варианты выбраны, данные подставлены, а узлы получили устойчивые идентификаторы. `HTML` — то, что renderer показывает в браузере.

## Когда применять

Recipe нужен, когда одна страница может выглядеть по-разному. Готовый Document удобно проверять, кешировать и публиковать. HTML создаётся в самом конце и не используется как исходное описание страницы.

## Пример

Для статьи Recipe говорит: «возьми общий шаблон, выбери шапку по настройке и вставь текст статьи». Настройка `headerMode` может быть `compact` или `expanded`. Текст «Одинаковый основной текст.» поступает из одного источника в обоих случаях.

```json
"select": {
  "value": { "input": "headerMode" },
  "cases": {
    "compact": { "id": "chosen-header", "ref": { "kind": "fragment", "owner": "example/library", "ref": "header.compact", "policy": "pinned", "revision": "r1" } },
    "expanded": { "id": "chosen-header", "ref": { "kind": "fragment", "owner": "example/library", "ref": "header.expanded", "policy": "pinned", "revision": "r1" } }
  }
}
```

После сборки Document уже содержит выбранную шапку и текст. Например, при `expanded` его дерево выглядит так: страница → секция с заголовком «Расширенная шапка» и пояснением «Дополнительная строка шапки» → абзац «Одинаковый основной текст.». При `compact` пояснения нет. В Document больше нет команды «выбери вариант»: выбор уже сделан.

В браузере это две обычные статьи. Переключите настройку в работающем примере и откройте «Собранный Document» или «Полученный HTML», чтобы сравнить три этапа на одних данных.

| Представление | Что хранит | Кто с ним работает |
|:---|:---|:---|
| Recipe | правила сборки и ссылки на входные данные | редактор и продукт |
| Document | готовое проверенное дерево интерфейса | Framework и механизм публикации |
| HTML | итоговую разметку | браузер |

Полные Recipe, источники, оба набора настроек и ожидаемые Documents находятся в [проверяемом JSON](/demos/guide/composition-recipe/header-switch.json). ИИ или разработчик может взять его для повторения сборки. Данные и ссылки на источники передаёт проект; Framework собирает дерево и создаёт HTML.
