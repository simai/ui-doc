# Язык

Всё, что компонент говорит людям, лежит в его файлах слов
`lang/<язык>.json` и поставляется вместе с ним. Манифест хранит только
технические имена. Страница описывает файл слов, слова по коду и слова
постоянных списков, порядок выбора языка, нехватку перевода и
множественное число.

## Файл слов

```json
{
  "title": "Список записей",
  "settings": {"collection": "Раздел"},
  "values": {"selected": "Выбрано", "total": "Записей"},
  "events": {"open": {"label": "Запись открыта", "carries": {"id": "код записи"}}},
  "actions": {"refresh": {"label": "Обновить"}, "delete": {"label": "Удалить запись", "with": {"ids": "коды записей"}}},
  "keys": {"chosen": "Выбранная запись"},
  "roles": {
    "search": {"title": "Поиск", "settings": {"label": "Найти запись"}},
    "confirm": {"title": "Подтверждение", "words": {
      "delete": {"one": "Удалить {n} запись?", "few": "Удалить {n} записи?", "many": "Удалить {n} записей?", "other": "Удалить {n} записи?"}}},
    "toast": {"words": {"delete-failed": "Не удалось удалить"}}
  },
  "rules": {"r-open": "Открыть запись"},
  "runtime": {
    "decrement": "Уменьшить значение",
    "inherited": "наследуется",
    "close": "Закрыть",
    "total": {"one": "{n} запись", "few": "{n} записи", "many": "{n} записей", "other": "{n} записи"}
  }
}
```

| Раздел | Что подписывает |
|:---|:---|
| `title` | сам компонент |
| `settings`, `values`, `events`, `actions` | интерфейс: для Студии, документации и журнала |
| `keys` | ключи сборки с хозяином `logic` |
| `roles` | название роли и её слова: постоянных настроек — `roles.<роль>.settings.<настройка>`, по коду из правила — `roles.<роль>.words.<код>`, постоянных списков — `roles.<роль>.items.<значение>` и `roles.<роль>.columns.<ключ>` |
| `rules` | название правила по его `id` |
| `runtime` | собственные слова компонента, которые он говорит на странице |

- Переносимые поля и параметры подписываются словами общего глоссария.
  Студия заполняет параметр из переносимого поля с тем же словом и
  помечает это «подобрано».
- Нет подписи — замечание проверки.
- Имена, которые человек вводит в Студии, пишутся в файл слов сборки:
  название роли и слова постоянных настроек — в `roles`, название правила —
  в `rules`.
- Слово своего глагола компонента (`"own-verb": true`) лежит в
  `events.<имя>.label`, а не в манифесте.

## Собственные слова компонента

Слова вроде «Уменьшить значение», «наследуется» или «Закрыть» живут в
разделе `runtime`, а не в коде.

- Построение регистрирует их в `SF.language`.
- Настройка может взять такое слово значением по умолчанию:
  `"default-from": "runtime.decrement"`.
- Настройка может следовать языку страницы: `"from-page": "lang"`. Числа
  показываются в формате языка страницы, а значение формы — никогда.

## Слова по коду из правила

Правило не передаёт детали готовых слов: оно передаёт код и число
(см. [Правила](/ru/guide/smart-components-2/rules/#правило-передаёт-коды-а-не-слова)).
Слова для кодов лежат в файле слов сборки.

- В словах роли может быть `words.<код>`: одно слово или формы
  множественного числа с `{n}` на месте числа. Формы — те, что даёт
  `Intl.PluralRules`: `zero`, `one`, `two`, `few`, `many`, `other`;
  `other` обязательна, и каждая форма, кроме `zero`, содержит `{n}`.
- Деталь, которую попросили с `code` и `count`, говорит
  `roles.<роль>.words.<код>` из файла слов своей сборки и выбирает форму по
  числу на языке элемента.
- Код — техническое имя в kebab-case, а не слово. Для неизвестного кода
  деталь говорит `message` хоста, затем своё собственное слово и пишет
  предупреждение в журнал.
- У кода, записанного в правиле постоянным значением
  (`{"value": "delete-failed"}`), слова есть в каждом поставляемом файле
  слов — это проверка 12. Код, прочитанный у хоста, — `{"from": "reason"}`
  факта `failed` или `{"outcome": "reason"}` в ветке «иначе», — принадлежит
  хосту: слова перечисляют для причин, которых ждёт сборка.

На стенде экрана админки правила передавали три кода с формами
множественного числа окну подтверждения, пять кодов — уведомлению на
странице и один — всплывающему сообщению.

## Слова постоянных списков

Роль может дать детали постоянный список: варианты выбора, вкладки
постоянного набора, пункты группы кнопок, столбцы таблицы. В манифесте —
то, что сравнивают правила и хранит хост, в файле слов — то, что читают
люди.

```json
"roles": {
  "status": {"part": "sf-dropdown", "settings": {"options": [{"value": "open"}, {"value": "won"}, {"value": "lost"}]}, "bind": {"values.value": "status"}},
  "table":  {"part": "sf-table", "settings": {"columns": [{"key": "title"}, {"key": "amount"}]}, "bind": {"settings.items": "deals"}}
}
```

```json
"roles": {
  "status": {"title": "Статус", "items": {"open": "Открытые", "won": "Выигранные", "lost": "Проигранные"}},
  "table":  {"title": "Сделки", "columns": {"title": "Сделка", "amount": "Сумма"}}
}
```

- В манифесте запись списка несёт только своё значение и технические
  поля: вариант `items` и `options` — `value` (или `id`, если у записей
  детали нет `value`, как у `sf-tabs`), столбец — `key`. Поле со словом
  (`label`, `text`, `title`, `hint`, `placeholder`, `description`) в
  постоянной записи и строка-запись со словами не проходят проверку 12.
- В файле слов слова лежат под `roles.<роль>.items.<значение>` и
  `roles.<роль>.columns.<ключ>`. Каждое называет запись постоянного списка
  роли, и у каждой записи есть слово в каждом поставляемом файле слов.
- Деталь получает список со словами на языке элемента — в том поле, которое
  называет её форма записи: `label` или `text`.
- Список, связанный с ключом, — это данные: его слова приходят с ним от
  хоста, и в файле слов их нет.

## Какой язык побеждает

Решение владельца (2026-10-26): **язык части страницы главнее языка,
выбранного для всей страницы.** Порядок:

1. слово, данное самому элементу: атрибут или настройка;
2. ближайший `[lang]` ниже `<html>`;
3. выбор страницы `SF.language.use(<язык>)`, который заодно ставит
   `<html lang>`;
4. `<html lang>`;
5. `en`.

Региональный вариант сводится к базовому языку: `ru-RU` → `ru`.

```html
<html lang="ru">
  <body>
    <sf-quantity name="count"></sf-quantity>       <!-- говорит по-русски -->
    <section lang="en">
      <sf-quantity name="count-en"></sf-quantity>  <!-- говорит по-английски,
                                                      даже после SF.language.use('ru') -->
    </section>
  </body>
</html>
```

## Смена языка на лету

SIMAI Framework одним наблюдателем следит за атрибутами `lang` в документе и
перерисовывает элементы под изменившимся атрибутом. Чтобы последовать за
`[lang]`, компоненту не нужны перезагрузка и вызов `SF.language.use`.

## Нехватка перевода

Во время работы недостающее слово берётся по-английски, затем на исходном
языке компонента, затем показывается ключ. Последние два случая пишут
предупреждение в журнал. Ключ никогда не считается текстом для людей.

## Множественное число

Слово из `runtime`, которое принимает число, — объект форм множественного
числа. Форма выбирается через `Intl.PluralRules` языка элемента:

| Число | Форма | Текст |
|:---|:---|:---|
| 1 | `one` | 1 запись |
| 3 | `few` | 3 записи |
| 25 | `many` | 25 записей |
| 1,5 | `other` | 1,5 записи |

## Слова поставляются с компонентом

- Построение поставляет `lang/<язык>.json` каждого компонента и
  регистрирует слова набора из этих файлов; ни одно слово не живёт только
  внутри набора.
- Статическая разметка создаётся для каждого поставляемого языка:
  `static/<шаблон>/<пример>.<язык>.html`.
- Каждый поставляемый файл слов подписывает весь интерфейс и все ключи с
  хозяином `logic`, содержит все слова `runtime` исходного языка, слова
  каждого кода, который правило пишет постоянным значением, и слово каждой
  записи постоянного списка — это проверяется при построении.
