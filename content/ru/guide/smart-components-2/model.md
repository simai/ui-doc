# Модель компонента

Страница вводит термины стандарта и описывает интерфейс — единственное, что
видят у компонента страница, сборка-родитель и Студия. Интерфейс одинаков у
детали и у сборки.

## Термины

| Термин | Слово в Студии | Что значит |
|:---|:---|:---|
| Компонент | компонент | Один тег `sf-…` с интерфейсом, разметкой, поведением, видом, примерами и словами |
| Деталь | деталь | Компонент без собственных частей |
| Сборка | сборка | Компонент из частей; у каждого её экземпляра своя шина |
| Часть | деталь | Компонент, поставленный в сборку на роль |
| Роль | — | Имя места в сборке: что должна уметь часть на этом месте |
| Интерфейс | интерфейс | Настройки, значения, события и действия компонента |
| Настройка | настройка | Значение, которое задают снаружи: атрибут или свойство |
| Значение | значение | То, что компонент держит и показывает наружу: `checked`, `selected` |
| Событие | событие | Момент, о котором компонент сообщает: `open`, `saved` |
| Действие | действие | То, что компонент делает по просьбе: `refresh`, `open {id}` |
| Шина | шина | Собственные данные и правила экземпляра сборки |
| Данные (ключ) | данные | Именованное значение на шине: тип и один хозяин |
| Связь | связь | Линия от настройки или значения части к ключу |
| Шип | шип | Связь, которую часть предлагает сама |
| Правило | правило | «Когда это событие — сделай шаги, только если…» |
| Ход | ход | Одно событие и все правила, которые оно запустило |
| Шаблон | шаблон | Файл разметки; шаблонов у компонента может быть несколько |
| Раскладка | раскладка | Шаблон сборки: где стоят её части |
| Манифест | описание | Машиночитаемый договор компонента, файл `component.json` |
| Пример | пример | Именованный набор настроек с ожидаемым результатом |

## Четыре части интерфейса

| Часть | Направление | Что это | Как выглядит на элементе |
|:---|:---|:---|:---|
| `settings` — настройки | внутрь | значения, данные снаружи | атрибуты и свойства |
| `values` — значения | наружу | что компонент держит и показывает | свойства только для чтения и событие `change` |
| `events` — события | наружу | моменты, о которых он сообщает | DOM-события |
| `actions` — действия | внутрь | что он делает по просьбе | сгенерированные методы; в сборке их вызывают правила |

Пример у переключателя `sf-switch`:

| Часть | Что у него есть |
|:---|:---|
| Настройки | `size`, `label`, `help`, `name`, `value` |
| Значения | `checked`; `effective-checked` — что видит человек с учётом наследуемого |
| События | `change` |
| Действия | своих нет; `checked` пишется снаружи как настройка |

- Настройки типов `list` и `object` передаются только свойствами. Остальные
  настройки — атрибуты, и у каждого есть свойство с тем же именем в camelCase.
- Значение, которое меняет человек (`checked`, `value`), можно и записать
  снаружи как настройку с тем же именем. В интерфейсе оно указано один раз — в
  `values`.
- Сборка (`"kind": "assembly"`) добавляет к интерфейсу `keys`, `roles`,
  `layouts` и `rules` — см. [Сборки](/ru/guide/smart-components-2/assemblies/).

## Базовый интерфейс

У каждого элемента есть общий базовый интерфейс. Он объявлен в стандарте один
раз и в манифестах не повторяется:

| Часть | Имена |
|:---|:---|
| Настройки | `template` — каким шаблоном рисовать, `root-class`, `root-style` |
| Действия | `focus`, `blur`, `connect-port {port}` (псевдоним `setHostPort`) |
| События | `sf-props-change`, `sf-updated`, `sf-after-render`, `sf-component-error` |

События этапов отрисовки есть только у базы. Компонент не заводит свои копии
вроде `modal:ready` или `modal:update`. Имена компонента не совпадают с
именами базы, поэтому сгенерированное действие никогда с ней не сталкивается.

## Типы

| Тип | Что хранит |
|:---|:---|
| `string` | строку |
| `enum` | одно из `values` |
| `boolean` | да или нет |
| `number` | число; может объявить `"integer": true`, `min`, `max`, `step` |
| `list` | список; может назвать поля записей: `"of": {"<поле>": "<тип>"}` |
| `object` | объект |
| `state` | одно из семи состояний данных — см. [Данные с сервера](/ru/guide/smart-components-2/data/) |
| `id` | строку или целое число; сравнивается как строка, возвращается в исходном типе |
| `icon` | имя значка; проверяется по шрифту значков |
| `date` | строку даты ISO 8601 |

Два флага подходят к любому типу:

- `"optional": true` — отсутствие значения — отдельное состояние **не
  задано**. Оно не равно пустой строке и не равно `false`. У логического
  атрибута три формы: атрибута нет, атрибут есть, атрибут `"false"`.
- `"nullable": true` — `null` допустим: «нет числа», «нет границы».

Переносимое поле события и параметр действия тоже могут быть `enum` со
списком `values`.

## Значение по умолчанию, текущее и видимое

У значения, которое меняет человек, два состояния:

- **по умолчанию** — атрибут; к нему возвращает сброс формы;
- **текущее** — свойство.

Манифест пишет `"default-from": "<атрибут>"`. Атрибут не повторяет текущее
значение, пока не указано `"reflect": true`.

Если необязательное значение не задано, человек может видеть не то, что
хранится. Тогда компонент объявляет второе значение `effective-<имя>` —
то, что показано. Так `effective-checked` у переключателя показывает
унаследованное положение, пока своё не задано.

## Управляемые значения

Значение может быть `"controlled": true`. Тогда изменение человеком — только
просьба: компонент отправляет `change` с желаемым значением и показывает его,
лишь когда настройку записали обратно. Так устроена сортировка таблицы:
человек щёлкает заголовок, а порядок меняет хост.

## Действия и их исход

- Параметры `with` приходят **одним объектом** в объявленном порядке. Их
  можно передать и по позициям.
- Действие отвечает **исходом**: `applied` или `refused {reason}`. Действие,
  которое ждёт хост, отвечает как хост: `applied`, `conflict`, `refused` или
  `unavailable`. Сгенерированный метод возвращает исход; цепочки вызовов в
  интерфейс не входят.
- Действие может быть `"emits": "<событие>"`. Тогда это программная форма
  просьбы человека, и оно отправляет это событие ровно один раз.
- Методов-читателей нет. Всё, что читает страница, — значение. Методы вроде
  `getModalRoot`, `getSlotHtml` и `getInputElement` уходят.
- Для значения, которое пишется как настройка, действие `set-<имя>` не
  заводят. Если оно нужно правилу, его генерирует построение компонента
  (build).

```js
const outcome = await document.querySelector('#orders').refresh();
if (outcome.answer !== 'applied') {
  console.warn(outcome.reason);
}
```

## Побочные эффекты

Компонент объявляет всё, что он делает со страницей за своими пределами:

| Эффект | Значит |
|:---|:---|
| `locks-page` | блокирует прокрутку страницы |
| `portal` | переносит свою отрисовку в конец `body` |
| `network` | сам обращается к сети |

Необъявленный эффект не пропускает проверка. Без `network` компонент не
ходит в сеть сам: содержимое приходит через деталь-источник или порт хоста.

## Версия интерфейса

Поле `version` обязательно: это semver интерфейса компонента, а не поставки
SIMAI Framework. Ломающее изменение настроек, значений, событий или действий
меняет старшую цифру. Версия не входит в имя тега.
