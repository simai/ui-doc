# Для ИИ

У стандарта есть сжатая машиночитаемая сводка —
`simai.smart-component.ai.json` (схема `simai.smart-component.ai.v2`). Она
нужна ИИ, который ставит смарт-компоненты на страницу, собирает из них
сборки и пишет правила. Нормативен полный стандарт; сводка обязана с ним
совпадать.

## Как сводку строят

Сводку не пишут руками. Каждый выпуск строит её скрипт
`build-ai-summary.mjs` из четырёх источников:

- версии стандарта и его модели правил;
- глаголов словаря, его изменений и фактов потока;
- верных образцов манифестов: деталь, просмотр записей, удаление с
  подтверждением, ленивые разделы, сборка в сборке, зависимая форма, список,
  чья ветка «иначе» читает исход; рядом с ними — одна раскладка (вкладки над
  `<x-role>`) и два файла слов: слова ролей, слова по коду с формами
  множественного числа, слова постоянных вариантов и столбцов;
- каталога деталей `parts-catalogue.json`, который строит
  `build-parts-catalogue.mjs`, — и ничего больше о деталях.

**Каталог деталей** собран из настоящих компонентов. В нём интерфейсы 66
поставляемых компонентов SIMAI Framework и ui-pro, приведённые к именам
стандарта (`real: true`, с исходником), и заменители со стендов там, где
поставляемого компонента для этой работы нет (`real: false`). Строковые
настройки со словами для людей — `label`, `text`, `title`, `placeholder`,
`hint` и имена, которые на них кончаются, — в интерфейс не входят: каталог
перечисляет их по имени в `words`. Так ИИ видит, что постоянное слово такой
настройки лежит в файле слов, а не в манифесте. Проверяющий находит детали
в том же файле, поэтому что показали ИИ и что проверяют — одно и то же.

Почему так, показали пять замеров на стенде. В каждом три ИИ-генератора
писали по пять сборок нарастающей сложности, читая только один файл, с
первой попытки и без подсказок:

| Замер | Что дали ИИ | Верных из 15 | Ошибок |
|:---|:---|---:|---:|
| 1 | только правила стандарта | 0 | 222 |
| 2 | правила, пять образцов и каталог из 19 заменителей | 11 | 11 |
| 3 | сводка 1.3.6 | 15 | 0 |
| 4 | сводка 1.3.7 с каталогом из поставляемых компонентов; ИИ писали ещё раскладки и файлы слов | 11 | 7 |
| 5 | сводка 1.3.8 | 14 | 2 |

Каждый верный манифест заработал. В четвёртом замере ИИ читали отказ хоста
в ветке «иначе» не тем чтением и одинаково угадывали слова постоянных
списков, форму страницы и шумный каталог — это закрывает стандарт 1.3.8.
В пятом обе ошибки — одна описка в одном файле, ни один ИИ не выдумал
деталь, и ни один не упёрся в пробел стандарта; то, что они ещё угадывали,
относится к тексту самой сводки. Проверка 37 держит это: каждый вложенный
образец вместе с раскладкой и файлом слов проходит проверки манифеста,
сборки и слов, а каталог сводки равен `parts-catalogue.json`.

## Что в сводке

| Раздел | Что содержит |
|:---|:---|
| `model` | четыре части интерфейса, виды `leaf` и `assembly`, типы, закрытый список полей верхнего уровня |
| `assembly` | ключи и их хозяева, производные ключи, форма роли, правила: поводы, шаги, чтения, условия, одновременные запуски, порядок выполнения, рамка, коды экземпляров, область |
| `host_answers`, `data_states` | ответы хоста с исходом `cancelled` и семь состояний данных |
| `events`, `verbs` | события по глаголу, шаблон DOM-имён, факты потока, запреты и все глаголы словаря с содержимым и русским словом |
| `page` | кнопка `data-sf-action` и три вида слотов |
| `look`, `language`, `naming` | вид, порядок выбора языка, правила имён, приставки пакетов и зарезервированные имена |
| `first_paint`, `saving` | скелетон и первый кадр сборки; сохранённый вид манифеста, правка заплаткой, версии |
| `quality_profile` | числа профиля качества: окно с 300 записей, 30 узлов на запись, время отрисовки, глубина цепочки 32 |
| `recipes` | готовые рецепты частых задач |
| `do_not` | чего делать нельзя |
| `manifest_examples` | целые верные манифесты с раскладкой и файлами слов: копировать форму, а не имена |
| `parts_catalogue` | детали, которые можно ставить: интерфейсы, пометка `real` и слова-настройки `words` |
| `source_files` | где лежат стандарт, словарь, образцы, реестр и сам скрипт |

## Отрывок

```json
{
  "schema": "simai.smart-component.ai.v2",
  "standard": "simai.smart-component 1.3.8",
  "vocabulary": "simai.smart-vocabulary 1.1.5",
  "events": {
    "declared_as": "the verb (open, saved, change)",
    "request": "<tag>-<verb> (sf-table-open)",
    "fact": "<tag>-<verb>ed (sf-property-view-saved)",
    "no": ["colons", "-intent suffix", "role names in DOM event names", "sf- in a manifest event name"]
  },
  "recipes": [
    {"task": "open a modal from a page button",
     "do": "<button data-sf-action=\"<modal-id>.open\">"}
  ],
  "parts_catalogue": {
    "parts": {
      "sf-search-field": {"real": false, "family": "field",
        "words": ["label", "placeholder"],
        "values": {"query": {"type": "string", "default": ""}},
        "events": {"change": {"carries": {"query": "string"}}},
        "actions": {"reset": {}}}
    }
  },
  "quality_profile": {"window_from_entries": 300, "nodes_per_entry": 30, "cause_chain_depth": 32}
}
```

## Как ИИ пользуется сводкой

1. **Читает модель.** Любой компонент — четыре списка: настройки, значения,
   события, действия. ИИ не ищет у компонента ничего сверх них.
2. **Ставит только детали из каталога.** Связывает только объявленные
   настройки и значения, слушает только объявленные события — по глаголу —
   и просит только объявленные действия. Деталь из пакета партнёра входит
   только через интерфейс `accepts`.
3. **Копирует форму образца.** Для новой сборки берёт ближайший образец из
   `manifest_examples` и меняет имена, а не устройство.
4. **Собирает по рецептам.** В `recipes` есть готовые схемы: показать записи
   с сервера, показать или скрыть деталь, вычислить итог из ключей, добавить
   и убрать строки, не дать отправить дважды, показать растущий ответ и
   остановить его, поставить компонент партнёра, листать страницы,
   назвать столбцы таблицы, сказать сбой хоста словами, передать порт
   детали внутри сборки.
5. **Проверяет себя по `do_not`.** Например: не писать в манифест выражения,
   циклы и склейку строк, не брать `latest` для изменения, не называть
   событие DOM-именем, не класть в манифест слова для людей — ни в
   настройки, ни в варианты и столбцы постоянных списков, не связывать
   детали напрямую, не делать компонент в продукте.
6. **Сверяется со словарём.** Глагол события берётся из `verbs`; свой
   глагол — только если ни один из словаря не подходит.

## Правка манифеста заплаткой

ИИ не пишет файл манифеста заново. Он правит его заплаткой JSON Patch
(RFC 6902), а инструмент применяет её печатью с сохранением байтов, поэтому
человек видит ровно то, что изменилось. Заплатка, которая меняет правило,
сначала проверяет его код:

```json
[
  {"op": "test", "path": "/rules/2/id", "value": "r-open"},
  {"op": "replace", "path": "/rules/2/steps/0/to", "value": {"from": "id"}}
]
```

Если на этом месте уже другое правило, заплатка не применяется. Манифест
после заплатки проходит те же проверки, что любой другой.

## Где лежит сводка

Сводка, стандарт, словарь и краткая русская версия переезжают в
`simai/ui-source` в папку `src/core/contracts/standards/simai.smart-component/1.3.8/`.
