# Разметка и шаблоны

Разметка смарт-компонента — это HTML-шаблоны на классах SIMAI Framework,
которые компилируются при построении. JavaScript разметку не собирает.
Страница описывает синтаксис шаблонов, правило «состояние видно из разметки»
и статическую разметку, которую печатает сервер.

## Шаблон по умолчанию и есть разметка

Шаблон `default` — это разметка компонента, написанная на CSS-классах
SIMAI Framework. Классы остаются общим визуальным языком, поэтому новому
смарт-компоненту не нужен сначала классовый компонент.

## Синтаксис шаблонов

| Запись | Что делает |
|:---|:---|
| `{{name}}` | текст или часть значения атрибута |
| `:attr="name"` | атрибут из значения; `false`, `null` и пустая строка убирают атрибут; у `checked`, `value` и `disabled` ставится и свойство |
| `@event="action"` | запускает действие из `behaviour.js` |
| `if="name"` | элемент есть, только пока значение истинно |
| `each="item in name" key="item.id"` | элемент повторяется для каждой записи; `key` обязателен |
| `<x-include name="…">` | вставляет часть шаблона, которую приносит общая черта |

- Имя в шаблоне — это настройка, значение или вычисляемое значение из
  `behaviour.js`. Допустимы `!name` и `a || b`; всё сложнее — вычисляемое
  значение.
- Вложенный `each` по другому списку допустим: `each="column in columns"`.
- Внутри повтора `{{row.x}}`, `:attr="row.x"` и `@event="action(row)"` видят
  запись, а состояние записи читается как `{{row.@current}}`.
- Текстовое поле, в котором печатает человек, получает `:value`, только пока
  у него нет фокуса, — курсор не прыгает.
- Шаблоны Lit внутри JavaScript — переходная форма для существующих
  компонентов.

**Шаблоны компилируются в Lit.** Стандарт задаёт синтаксис шаблонов, а не
движок отрисовки. Построение превращает каждый шаблон в шаблон Lit, и
обновления, повторы по ключу, события и запись атрибутов и свойств делает
Lit. Следующее построение может компилировать в другой движок, и ни один
манифест или шаблон при этом не меняется. Своего движка отрисовки у
стандарта нет.

```html
<label class="sf-switch flex items-cross-center gap-1/2">
  <input type="checkbox" class="sf-switch-input" role="switch"
         :name="name" :value="value" :checked="checked" :disabled="disabled">
  <span class="sf-switch-track"></span>
  <span class="sf-switch-label" if="label">{{label}}</span>
</label>

<ul class="sf-list">
  <li each="row in items" key="row.id" :aria-current="row.@current">
    <button type="button" @click="open(row)">{{row.title}}</button>
  </li>
</ul>
```

## Состояние видно из разметки

Вид состояния следует из самой разметки: `:checked`, `[disabled]`,
`[aria-*]`, атрибуты или классы, которые пишет шаблон. Вид не зависит от
класса, который позже добавит скрипт.

- **Видимые состояния**, которые не являются значениями, — на границе
  диапазона, наследуется, над элементом что-то тащат — объявляются как
  атрибуты хоста:

  ```json
  "host-states": {"data-at-min": "boolean", "data-at-max": "boolean", "data-inherited": "boolean"}
  ```

  Они не значения и не отправляют `change`.
- Компонент, чей вид меняется от такого состояния, обязан отражать его на
  хосте и объявлять в `host-states`. Проверка не пропускает класс состояния,
  который пишет скрипт.
- Кольцо фокуса рисует `:focus-visible`, а не класс из скрипта.

## Статическая разметка

**Что делает построение.** Каждый пример каждого компонента построение
открывает в браузере и сохраняет нарисованное как статический HTML — снимок,
который коммитится с исходниками и поставляется с компонентом (подробно — в
[Снимок при построении](/ru/guide/smart-components-2/first-paint/#снимок-при-построении)):

| Файл | Что в нём |
|:---|:---|
| `static/<шаблон>/<пример>.html` | готовая разметка примера |
| `static/<шаблон>/<пример>.skeleton.html` | скелетон примера — у компонента, чьи данные приходят позже |
| `static/sheets.json` | какие таблицы стилей нужны разметке (ядро, компонент, значки, семейства утилит) и нужен ли класс темы на `<html>` |

Одного `core.css` мало: переключателю нужны ещё восемь таблиц и класс
`theme-light` или `theme-dark` на `<html>`.

**Кто печатает.** Статическая разметка — первая отрисовка компонента. Её
печатают серверы (Larena, Bitrix), статические страницы Docara и
документация классовых компонентов — или отрисовывают шаблон сами из
настроек, помеченных как безопасные для сервера.

**Что можно отрисовать статически.** Шаблон, в котором каждое имя — одно из:

- настройка;
- значение со значением по умолчанию;
- вычисляемое значение, объявленное чистым от настроек
  (`"computed": {"state-classes": {"from": ["checked", "disabled"]}}`),
  записанное один раз на синтаксисе шаблона или дважды — в JavaScript и на
  сервере.

Списки и объекты приходят JSON-островом
`<script type="application/json" data-sf-settings>` на хосте; элемент читает
его до первой отрисовки. Для данных, которые знает только
браузер (размеры, фокус, данные порта), есть статическая замена — шаблон
`skeleton.html`, чья рамка равна рамке загруженного компонента; см.
[Первый кадр и ленивая загрузка](/ru/guide/smart-components-2/first-paint/).

## Подхват в браузере

Живой элемент над статической разметкой:

1. **принимает или заменяет** статических детей с пометкой `data-sf-static` в
   первой же отрисовке, за один кадр, и никогда не рисуется рядом с ними;
2. **даёт тот же DOM** при тех же настройках;
3. **берёт первые значения из атрибутов хоста**, а не из статических детей,
   поэтому расхождение не может перевернуть состояние;
4. **отправляет в форму то же значение**, что и статическая разметка.

Подхват написан один раз, в общей основе смарт-элементов: деталь,
напечатанная внутри напечатанного родителя, забирает свой кусок разметки и
не рисует себя второй раз. Ядро не прячет страницу, на которой есть
статическая разметка или скелетоны. Прятать можно только неопределённые
элементы без того и другого.

```html
<sf-switch id="notify" name="notify" label="Уведомления" checked>
  <label class="sf-switch flex items-cross-center gap-1/2" data-sf-static>
    <input type="checkbox" class="sf-switch-input" role="switch" name="notify" value="on" checked>
    <span class="sf-switch-track"></span>
    <span class="sf-switch-label">Уведомления</span>
  </label>
</sf-switch>
```

Сначала правило «состояние видно из разметки», потом статика: шаблон,
который оставляет вид состояния скрипту, статически не отрисовать —
включённый переключатель нарисовался бы выключенным.

## Почта — не цель

Таблицы стилей SIMAI Framework используют `@layer`, `var()`, `:has()` и
`light-dark()`, а почтовые клиенты выбрасывают их вместе с формами. Почтовый
вид компонента-отображения — отдельный шаблон со встроенными стилями, который
делает отдельный шаг построения.
