# Поля форм

Смарт-поле ведёт себя в форме как обычное поле HTML: форма его видит,
отправляет, сбрасывает и проверяет. Страница описывает раздел `form`
манифеста, обязательства поля, проверку значения, сборку как форму и общие
черты — первая из них даёт полям наследуемое значение.

## Раздел `form`

```json
"form": {"value": "value", "name": "name", "default": "value", "required": "required",
         "disabled": "disabled", "readonly": "readonly", "submits": "value", "reset": "default"}
```

Раздел говорит, какое значение компонента — значение поля, откуда берутся
имя, значение по умолчанию, обязательность, отключение и «только чтение», что
уходит в форму и к чему возвращает сброс.

## Что поле гарантирует

1. **Связь с формой.** Поле — элемент, связанный с формой
   (`static formAssociated`, `ElementInternals`). `form.elements`,
   `FormData`, `fieldset[disabled]`, `form.reset()` и `:invalid` видят сам
   элемент, а не скрытый `input`.
2. **Формат формы.** Значение уходит в форму в формате, который не зависит от
   языка страницы. Число отправляется с точкой и без разделителей групп
   (`2567.50`), хотя поле показывает `2 567,50`. Включённый переключатель без
   `value` отправляет `on`, как обычный флажок.
3. **Когда не отправляется.** Отключённое поле и поле без имени ничего не
   отправляют; поле «только чтение» отправляет.
4. **Сброс.** По `form.reset()` поле возвращается к значению по умолчанию без
   событий, а по `formStateRestoreCallback` восстанавливает состояние.
5. **Проверка.** Поле даёт `validity`, `validationMessage`, `willValidate`,
   `checkValidity()`, `reportValidity()`, `setCustomValidity()`, `form` и
   `labels`.
6. **Внутренние поля не входят в форму страницы.** Компоненты рисуют в
   светлом DOM, поэтому внутренний `<input>`, `<select>` или переключатель
   с атрибутом `name` попал бы в форму страницы. Внутренние поля `name` не
   несут: в форму уходит только сам элемент.

Поле, которое отправляет значение через скрытый `input`, может делать так до
версии стандарта 1.4.0, затем переходит на `ElementInternals`.

## Проверка значения

- Поле объявляет, о каких нарушениях умеет сообщать. Виды те же, что у
  `ValidityState` браузера:

  ```json
  "validity": ["value-missing", "type-mismatch", "pattern-mismatch",
               "too-short", "too-long", "range-underflow", "range-overflow",
               "step-mismatch", "bad-input", "custom-error"]
  ```

- `invalid` — **показанное** состояние. Оно включается, когда проверка не
  прошла после того, как человек тронул поле.
- Действие `set-error {message}` ставит `custom-error`, и форма не
  отправляется. Ошибка, которая только красит поле и не мешает отправке, —
  нарушение стандарта.
- `error-message` — своё сообщение об ошибке; `error` — псевдоним `invalid` с
  датой.

```js
const amount = document.querySelector('#amount');
await amount.setError({ message: 'Больше остатка на складе' });
amount.form.reportValidity(); // false: форма не отправится
```

## Сборка как форма

Сборка, чьи детали — поля формы, может объявить
`"form": {"aggregates": true}`. Построение даёт ей:

| Что | Имя | Как работает |
|:---|:---|:---|
| Значение | `valid` | да, когда каждая присутствующая деталь прошла проверку |
| Значение | `value` | объект значений деталей по ролям: `{"inn": "7701234567", "contact[c1]": {"name": "…", "phone": "…"}}` |
| Действие | `check-validity` | отвечает `applied`, если всё верно, иначе `refused {reason: invalid}`, и показывает ошибку каждой детали |
| Действие | `reset` | каждая деталь возвращается к значению по умолчанию |

- Детали под `if` и детали в скрытом контейнере (`hidden`) в `valid` и
  `value` не входят — см.
  [Сборки](/ru/guide/smart-components-2/assemblies/#показ-и-скрытие-детали).
- Внутри сборки `valid` и `value` — производные ключи, которые добавляет
  построение: правила и другие производные ключи их читают, никто не пишет.
  Родитель связывает их как любое значение.
- Обычная `<form>` вокруг сборки продолжает работать, потому что каждая
  деталь связана с формой сама.

Кнопка отправки отключается, пока форма неверна, производным ключом:

```json
"keys":  {"cannot-submit": {"type": "boolean", "writer": "derived",
                            "from": {"left": {"key": "valid"}, "op": "no"}}},
"roles": {"submit": {"part": "sf-button", "bind": {"settings.disabled": "cannot-submit"}}}
```

## События `input` и `change`

Они подчиняются общему правилу: только изменения человека, `change` — один
раз на фиксацию значения: Enter, уход из поля, нажатие на кнопку шага. Если
человек держит кнопку шага, `change` приходит один на всю серию. Сброс к
наследуемому значению — изменение человека с `source: reset`.

## Общие черты

Общая черта (trait) — часть интерфейса, одинаковая у нескольких
компонентов. Она описана один раз и подключается к манифесту:

```json
"traits": ["field-inherit@1"]
```

- Черта — папка с `trait.json` (её настройки, значения, события и
  действия), частью шаблона, которую вставляет `<x-include>`, и папкой
  `lang/`.
- Построение вливает черту в интерфейс компонента. Совпадение имён черты и
  компонента — ошибка проверки.
- Документация и Студия показывают часть черты один раз, со ссылкой.
- Событие, которое приносит черта, названо по черте: `sf-<черта>-<глагол>`, и
  несёт `tag` в `detail`, поэтому форма слушает его один раз для всех полей.
  Компонент может добавить своё `sf-<тег>-<глагол>` как псевдоним.

## Черта `field-inherit`: наследуемое значение

Поле может показывать значение, унаследованное от уровня выше: от раздела,
от шаблона, от общих настроек. Черта используется в `sf-input`,
`sf-textarea`, `sf-dropdown`, `sf-color`, `sf-switch` и `sf-quantity` и
приносит:

| Часть | Имена |
|:---|:---|
| Настройки | `inherited-value` (необязательная), `inherited-text` (слова), `reset-label` |
| Значение | `is-inherited` |
| Действие | `reset-to-inherited`, отвечает `applied` или `refused` |
| Событие | `sf-field-reset {tag, value, inherited-value, name}`, отклоняемое |

Пока у поля нет своего значения:

- наследуемое значение показано как подсказка, а не как значение;
- в форму уходит пустое значение, а на хосте стоит `data-inherited`;
- наследуемое значение **не выполняет `required`**: это подсказка, а не
  ответ.

```html
<sf-input name="title" label="Заголовок" inherited-value="Новости компании"
          inherited-text="Из настроек раздела" required></sf-input>
```
