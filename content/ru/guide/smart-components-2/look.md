# Внешний вид

Вид компонента меняют тремя способами, и выбор зависит от того, что
меняется. Страница описывает этот выбор, открытые CSS-переменные компонента,
состояния на хосте и то, как переменные проходят через сборки.

## Настройка, шаблон или новый компонент

| Что меняется | Чем |
|:---|:---|
| цвет, размер, плотность, скругление, значок | **настройка** на том же шаблоне |
| расположение тех же частей или то, какие компоненты их рисуют; интерфейс тот же | **шаблон** |
| интерфейс или порт хоста | **новый компонент** с именем по назначению |

Шаблоны называют по расположению — `rows`, `cards`, `rail` — и никогда по
продукту.

```html
<sf-record-list collection="orders" template="cards" size="1/2"></sf-record-list>
```

## Что может менять страница

Компонент объявляет, какой вид разрешено менять снаружи:

- `css-variables` — **обязательно**: 5–10 открытых переменных, у каждой тип
  и состояние, которое она красит;
- `parts` — по желанию: классы, к которым может обращаться страница.
  Компоненты рисуют в обычном DOM, поэтому это классы, а не `::part`.

Объявление может выглядеть так (имена переменных — пример):

```json
"css-variables": {
  "--sf-switch-checked-background-color": {"type": "color", "state": "checked"},
  "--sf-switch-track-background-color": {"type": "color", "state": "default"},
  "--sf-switch-thumb-color": {"type": "color", "state": "default"},
  "--sf-switch-disabled-opacity": {"type": "number", "state": "disabled"},
  "--sf-switch-focus-ring-color": {"type": "color", "state": "focus-visible"}
},
"host-states": {"data-inherited": "boolean"}
```

Всё остальное — внутреннее. Обращаться к закрытым классам компонента
страница не должна: это ломается при любом изменении шаблона.

## Переменная на каждое состояние

- Каждое видимое состояние, которое странице можно перекрасить, имеет свою
  открытую переменную, например `--sf-switch-checked-background-color`.
- Правило стиля для состояния читает открытую переменную, а токен роли
  служит ей запасным значением — никогда только токен:

  ```css
  .sf-switch:has(input:checked) .sf-switch-track {
    background-color: var(--sf-switch-checked-background-color, var(--sf-primary));
  }
  ```

- Состояние, от которого ветвится вид, отражено на хосте и объявлено в
  `host-states` — см. [Разметка и шаблоны](/ru/guide/smart-components-2/markup/).
- Переменная, которую читает код в форме `--sf-<тег>-<имя>` с запасным
  значением, объявлена в `css-variables`; иначе её не пропускает проверка.

## Уровни

Переменную можно задать на четырёх уровнях: тема → внешняя сборка →
вложенная сборка → деталь. Побеждает ближайший, а значение, заданное одной
детали, не перетекает на соседнюю деталь того же тега.

```css
/* вся тема */
:root { --sf-switch-checked-background-color: var(--sf-success); }
/* одна сборка */
#checkout { --sf-switch-checked-background-color: var(--sf-primary); }
/* одна деталь сборки по её роли */
#checkout [data-sf-role=gift] { --sf-switch-checked-background-color: var(--sf-warning); }
```

## Сборка пропускает переменные

Сборка объявляет, какие переменные своих деталей она пропускает наружу.
Страница задаёт их на хосте сборки или на детали по роли
(`[data-sf-role=gift]`). Слой, который рисуется через портал, уносит с собой
вычисленные значения объявленных переменных хоста.
