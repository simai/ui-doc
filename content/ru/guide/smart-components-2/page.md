# На странице

Страница описывает работу с компонентом без сборок: в разметке и в коде
страницы. Настройки — это атрибуты и свойства, значения читаются у элемента,
события — обычные DOM-события, действия — методы элемента или кнопка с
`data-sf-action`.

## Пример

```html
<sf-switch id="notify" label="Уведомления" name="notify"></sf-switch>

<sf-modal id="confirm" label="Удалить запись?">…</sf-modal>
<button type="button" data-sf-action="confirm.open">Удалить</button>

<script>
  document.querySelector('#notify')
    .addEventListener('change', (event) => console.log(event.currentTarget.checked));
</script>
```

| Что | Где на странице |
|:---|:---|
| Настройка | атрибут тега (`label`, `size`); списки и объекты — свойство (`element.items = [...]`) |
| Значение | свойство элемента только для чтения: `element.checked`, `element.selected` |
| Событие | `addEventListener` на элементе |
| Действие | метод `element.open()` или кнопка `data-sf-action="<id>.<действие>"` |

## Имена событий

Имена и содержимое событий берутся из общего словаря — см.
[Имена и общие слова](/ru/guide/smart-components-2/names/).

| Вид | Шаблон | Пример |
|:---|:---|:---|
| Просьба | `sf-<тег>-<глагол>` | `sf-property-view-close` |
| Свершившийся факт | `sf-<тег>-<глагол>ed` | `sf-property-view-saved` |
| Событие общей черты | `sf-<черта>-<глагол>` с `tag` в `detail` | `sf-field-reset` |

- `detail` — всегда объект: `select {ids}`, `delete {ids, revisions}`.
- `detail` не несёт элементов страницы — только коды и данные.
- Двоеточий и суффикса `-intent` в именах нет. События с двоеточием
  (`sf-accordion:toggle`, `sf-menu:navigate`, `sf-field:reset`,
  `sf-code-input:complete` и другие) переходят на шаблон и сохраняют старое
  имя как псевдоним с датой.
- Одно действие — одно событие, и отправляет его компонент, которому
  действие принадлежит. Сборка не пересылает событие своей части как своё:
  шаг `emit` создаёт её собственное новое событие.

## Событие `change`

`change` сообщает о том, что **сделал человек**: изменил значение сам или
нажал кнопку, которая запустила действие, например сброс.

- Значение, заданное снаружи — настройкой, действием, сбросом формы, — обратно
  не сообщается. Так же ведут себя обычные поля HTML.
- Правило сборки, которому нужно и такое изменение, слушает `data.<ключ>`
  того ключа, к которому привязано значение.
- У поля формы `input` и `change` могут быть обычными событиями браузера
  (`"carries": "native"`). Они обязаны дойти до элемента-хоста, а слушатель
  читает значение у хоста, а не у `event.target`.

```js
const quantity = document.querySelector('#amount');
quantity.addEventListener('change', () => {
  // Читаем у хоста: внутри event.target может быть внутренний input.
  console.log(quantity.value);
});
```

## Просьбы, которые можно отклонить

Событие, которое компонент отправляет **до** того, как действовать, и ждёт
решения, объявлено `"cancelable": true`.

| Кто отклоняет | Как |
|:---|:---|
| Страница | `event.preventDefault()` |
| Правило сборки | шаг `refuse` — см. [Правила](/ru/guide/smart-components-2/rules/) |

После отказа действие компонента отвечает `refused`. Так устроены сброс поля
к наследуемому значению и закрытие окна.

```js
const editor = document.querySelector('#editor');
editor.addEventListener('sf-modal-close', (event) => {
  if (event.detail.unsaved && event.detail.reason !== 'api') {
    event.preventDefault(); // окно остаётся открытым
  }
});
```

## Кнопка `data-sf-action`

Атрибут `data-sf-action="<id элемента>.<действие>"` на кнопке страницы
запускает это действие без своего кода. Атрибут генерируется из списка
`actions` компонента и заменяет `data-sf-modal-*` и `data-sf-drawer-*`, которые
остаются псевдонимами.

```html
<sf-drawer id="filters" label="Фильтры">…</sf-drawer>
<button type="button" data-sf-action="filters.open">Фильтры</button>
<button type="button" data-sf-action="orders.refresh">Обновить список</button>
```

Тот же атрибут — единственный способ, которым обычное содержимое слота
просит сборку о чём-либо: см. [Слоты](/ru/guide/smart-components-2/slots/).

## Чего на странице нет

- Методов-читателей: всё, что нужно прочитать, — значение.
- Обращения к внутренностям сборки: страница видит только события самой
  сборки, а не её частей.
- Классов состояния, которые добавляет скрипт: состояние видно из разметки —
  см. [Разметка и шаблоны](/ru/guide/smart-components-2/markup/).
