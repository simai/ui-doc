# Подключение набора

Набор подключают одной строкой: на скрипт ядра SIMAI Framework добавляют
атрибут `data-sf-sets` с именем набора. Больше ничего перечислять не нужно:
Loader сам найдёт подходящий выпуск набора и загрузит только те его
компоненты, которые есть на странице.

Атрибут `data-sf-sets` понимает Loader начиная с выпуска SIMAI Framework
`5.20261103.2154` (`core.runtime` 1.25.0).

## Одна строка

Пример подключает набор эффектов к выпуску SIMAI Framework `5.20261107.1157`
и ставит на страницу один эффект:

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@simai-studio/ui@5.20261107.1157/distr/core/css/core.min.css">
<script src="https://cdn.jsdelivr.net/npm/@simai-studio/ui@5.20261107.1157/distr/core/js/core.min.js" data-sf-sets="effects"></script>

<sf-effect effect="aurora-curtain" speed="200"></sf-effect>
```

В своём проекте на месте `5.20261107.1157` стоит версия пакета
`@simai-studio/ui`, которую закрепил проект (см.
[Версии](/ru/guide/connection/versions/)): `5.20261103.2154` или новее.
Набор берётся из общего каталога выпусков: Loader выбирает самый новый
выпуск набора, который подходит к этому SIMAI Framework. В примере Loader
найдёт в каталоге набор `effects` 1.0.0 и загрузит его с jsDelivr.

## Закрепить версию набора

Чтобы страница всегда получала одну и ту же версию набора, её пишут после
имени через `@`:

```html
<script src=".../distr/core/js/core.min.js" data-sf-sets="effects@1.0.0"></script>
```

С закреплённой версией Loader не читает каталог выпусков и берёт набор прямо
из пакета npm `@simai-studio/effects@1.0.0`. Так подключают набор в рабочем
проекте: версия меняется только тогда, когда её меняет проект.

## Несколько наборов

Имена наборов перечисляют через пробел; у каждого может быть своя версия:

```html
<script src=".../distr/core/js/core.min.js" data-sf-sets="view admin@1.2.0"></script>
```

Если один набор опирается на другой (админка показывает данные компонентами
набора `view`), страница называет оба. Loader сам второй набор не подключает.

## Свой адрес набора

Набор можно взять не с CDN, а со своего сервера или из локальной копии. Адрес
задают в `SF_BOOT_CONFIG` до скрипта ядра:

```html
<script>
  window.SF_BOOT_CONFIG = {packages: {effects: '/assets/sets/effects/dist/smart'}};
</script>
<script src=".../distr/core/js/core.min.js"></script>
```

В `SF_BOOT_CONFIG.packages` набор можно описать любым из способов:

| Запись | Что значит |
|:---|:---|
| `effects: true` | выпуск из каталога, как `data-sf-sets="effects"` |
| `effects: '1.0.0'` | эта версия пакета npm, каталог не читается |
| `effects: '/assets/sets/effects/dist/smart'` | набор лежит по этому адресу |

Если набор назван и в `SF_BOOT_CONFIG`, и в `data-sf-sets`, действует
`SF_BOOT_CONFIG`.

## Если что-то не так

Ошибка в подключении набора не ломает страницу: остальные компоненты
работают, а Loader пишет предупреждение в консоль браузера.

| Что случилось | Что будет |
|:---|:---|
| Набор не назван на странице | Его компоненты остаются неопределёнными тегами; `SF.package('effects')` отвечает ошибкой и называет строку, которую нужно добавить |
| Набора нет в каталоге или для этого SIMAI Framework нет подходящего выпуска | Предупреждение с причиной; компоненты набора не загружаются. Помогает закреплённая версия или свой адрес |
| В `data-sf-sets` написано не имя набора | Слово пропускается с предупреждением |
| Файлы набора не загрузились | Предупреждение с адресом; компоненты набора не загружаются |
| Набору нужен другой набор, которого нет на странице | В режиме отладки (`?sf-debug`) Loader называет недостающий набор |
