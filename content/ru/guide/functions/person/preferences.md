# Настройки вида

Человек меняет под себя порядок колонок, их ширину, сортировку, плотность
списка — и ждёт увидеть то же при следующем открытии. `SF.Preferences`
хранит такой выбор одинаково для всех компонентов: значение под ключом
читается сразу, до первой отрисовки, лежит в браузере и, если хост (например,
Larena) хранит настройки пользователя, уходит и к нему.

## Вызов

```js
const key = 'sf-table/orders';
const view = SF.Preferences.read(key);              // значение или null
SF.Preferences.write(key, {density: 'compact'});
const stop = SF.Preferences.subscribe(key, (value) => apply(value));
SF.Preferences.remove(key);                          // «Сбросить вид»
```

| Член | Что делает |
|:---|:---|
| `read(key)` | Значение ключа: данные хоста, если он их дал, иначе копия браузера; `null`, если ничего нет. Читается сразу, без ожидания. |
| `readMerged(...keys)` | Несколько ключей от общего к частному, слитые по полям: `readMerged('sf-table/*', 'sf-table/orders')`. |
| `write(key, value)` | Сохраняет значение — простой JSON — в браузере и, если есть хост, отправляет ему через 400 мс после последней записи. То же значение второй раз не пишется. Возвращает `false` для неверного ключа. |
| `remove(key)` | Убирает значение у браузера и у хоста и сообщает подписчикам `null`. |
| `subscribe(key, listener)` | Вызывает `listener(value, key)`, когда значение пришло от хоста, изменилось в другой вкладке или убрано. Возвращает функцию отписки. |
| `preload(values)` | Значения хоста для этого человека: `{ключ: значение}`. То, что отличается от копии браузера, заменяет её и сообщается подписчикам. |
| `useHost(adapter)` | Подключает хост: `{save(key, value), remove(key), load?(keys)}`. |
| `load(keys)` | Просит у хоста ключи, которых он ещё не дал. |
| `hosted` | Подключён ли хост. |
| `flush()` | Отправляет хосту ожидающие записи сразу; при уходе со страницы это делается само. |

Ключ — `<компонент>/<экземпляр>`, например `sf-table/orders`: буквы, цифры,
`_ . * : -`, до 200 знаков.

## Когда доступно

Ядро: сразу после выполнения `core.js`, ждать не нужно.

## Пример

Хост примера хранит настройки в памяти, отдаёт их через `preload` и пишет в
журнал всё, что получил. Кнопки плотности записывают выбор — через 400 мс хост получает значение;
«Сбросить» убирает его.

Значения хоста можно отдать прямо в разметке страницы, до первого чтения:

```html
<script type="application/json" data-sf-preferences>{"sf-table/orders": {"density": "compact"}}</script>
```

## Особые случаи

- Ключ не задан или неверный — ничего не хранится: `read` отвечает `null`,
  `write` — `false`.
- Своя запись подписчиков не вызывает.
- Где браузерное хранилище недоступно (изолированный фрейм, запрет
  настроек), `read` отвечает только тем, что дал хост: значение ключа,
  которого хост не давал, после `write` не читается.
