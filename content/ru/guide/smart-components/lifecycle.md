# Жизненный цикл

Глава перечисляет этапы жизни компонента, методы, которые можно
переопределить, и правила освобождения ресурсов. Это нужно, чтобы компонент
корректно переживал удаление и повторное добавление на страницу.

## Этапы

1. Тег появляется на странице; Loader подключает файлы компонента, а с первым
   Smart-элементом страницы — и общую среду Smart-компонентов
   (см. [Подключение к странице](/ru/guide/smart-components/connection/#подключение-к-странице)).
2. Тег регистрируется (тег библиотечного компонента — когда пришла общая
   среда); браузер создаёт экземпляр.
3. Подключение: базовый класс забирает содержимое слотов из детей тега, затем
   вызывает `onConnected()` и отправляет `sf-connected`.
4. Отрисовка: `beforeRender()` и `sf-before-render`, затем шаблон (внешний
   шаблон сначала загружается вместе со своим `index.css`), затем ожидание
   стилей, затем `afterRender()` и `sf-after-render`.
5. Обновление при смене атрибутов, содержимого слотов или языка страницы:
   отрисовка заново, затем `afterUpdate()`, `sf-updated`, `sf-props-change`.
6. Отключение: `onDisconnected()`, освобождение внешнего шаблона,
   `sf-disconnected`.

Общие события этапов — `sf-connected`, `sf-disconnected`, `sf-before-render`,
`sf-after-render`, `sf-updated` и `sf-props-change`. Собственные события
конкретного компонента — на его странице в справочнике. События всплывают, поэтому
в составном компоненте проверяйте `event.target`: события вложенных элементов
тоже доходят до родителя.

## Методы для переопределения

| Метод | Когда вызывается |
|:---|:---|
| `onConnected()` | После подключения к странице |
| `beforeRender(changed)` | Перед каждой отрисовкой |
| `afterRender(changed)` | После отрисовки и загрузки стилей |
| `afterUpdate(changed, mode)` | После обновления |
| `onDisconnected()` | При удалении со страницы |

Публичные методы для кода проекта:

| Метод | Что делает |
|:---|:---|
| `refresh(reason)` | Перерисовывает компонент, например после изменения данных, которые он читает не из атрибутов |
| `whenRendered(callback?, { next? })` | Обещание, которое выполнится после отрисовки; если отрисовка уже была, выполняется сразу. Необязательная функция `callback` вызывается в тот же момент и получает сведения об отрисовке (`component`, `tagName`, `template`, `changedAttributes`); обещание выполняется с теми же сведениями. `{ next: true }` ждёт следующую отрисовку, даже если первая уже была; без функции первым аргументом передают `null`: `whenRendered(null, { next: true })` (см. [Ожидание готовности](/ru/guide/smart-components/connection/#ожидание-готовности)) |

Правила:

- `connectedCallback()` и `disconnectedCallback()` целиком не переопределяют:
  в них базовый класс забирает слоты, подписывается на язык страницы и
  освобождает внешний шаблон.
- Вызов `super` в этих методах не обязателен. Базовые `onConnected()`,
  `beforeRender()` и `afterUpdate()` пусты, `afterRender(changed)` ничего не
  делает. Базовый `onDisconnected()` освобождает внешний шаблон, и базовый класс
  делает это и сам после вашего `onDisconnected()`, поэтому
  `super.onDisconnected()` — безопасная привычка, а не условие.
- Поля класса и собственный конструктор допустимы: конструктор первым делом
  вызывает `super()`, поле вроде `handleRelease = () => { … }` хранит
  функцию экземпляра для обработчиков. Поле не называют именем объявленного
  свойства: пока атрибута нет, `getProp()` возвращает значение поля, а не
  значение по умолчанию.

## Освобождение ресурсов

Компонент завершает свою работу при отключении: снимает обработчики на
`window` и `document`, останавливает таймеры, отменяет незавершённые запросы.
Пример показывает снятие обработчика через `AbortController`:

```js
onConnected() {
  this.abort = new AbortController();
  window.addEventListener('resize', this.handleResize, { signal: this.abort.signal });
}
onDisconnected() {
  this.abort?.abort();
  super.onDisconnected();
}
```

`handleResize` — сохранённая функция экземпляра, а не новая стрелочная функция
при каждом подключении. При повторном подключении создаётся новый
`AbortController`: отменённый контроллер повторно не используют. Ответ на запрос,
пришедший после удаления или после нового запроса, не применяется.

**Проверка:** добавить элемент, выполнить действие, удалить, добавить снова.
Одно действие — одно событие.
