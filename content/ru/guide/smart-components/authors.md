# Правила для авторов

Автор смарт-компонента отвечает за три вещи, которые проверка выпуска
проверяет сама и без которых пара SIMAI Framework не выходит.

| Что изменил | Что сделать | Что будет, если забыть |
|:---|:---|:---|
| `component.json`, `examples.json` или `lang/` | перегенерировать файлы компонента | проверка построения находит сгенерированный файл, который расходится с исходными, и не пропускает папку |
| вид компонента: шаблон, стили, слова, значки | снять снимок начального вида заново | проверка снимков находит устаревший снимок, и кандидат пары не проходит |
| любой файл компонента | поднять его версию в `component.json` | проверка выпуска находит изменившийся хеш при прежней версии и отказывает выпуску |

## Изменил договор — перегенерируй файлы

По стандарту 1.4 человек пишет пять файлов компонента, а `rule.js`,
`aliases.json`, `smart.manifest.json`, `meta.mjs`, файлы Студии и
`probe.json` генерирует построение (см.
[Папка компонента и манифест](/ru/guide/smart-components/folder/#одна-папка)).
После правки исходных файлов их перегенерируют в `simai/ui-source`:

```sh
node scripts/generate-component-files.mjs --write --component tree
```

- `--check` только сравнивает и падает на расхождении; так файлы проверяет
  тест договора.
- `--package <папка пакета>` делает то же для компонентов пакета.
- Сгенерированные файлы руками не правят: правка пропадёт при следующей
  генерации, а до неё проверка не пропустит папку.

## Изменил вид — сними снимок заново

Начальный вид компонента — снимок, который построение делает в браузере и
коммитит вместе с исходниками (см.
[Первый кадр и ленивая загрузка](/ru/guide/smart-components/first-paint/#снимок-при-построении)).
После любой правки, которая меняет то, что компонент рисует, снимок снимают
заново одной командой в `simai/ui-source` по собранному выводу:

```sh
node scripts/snapshot-first-paint.mjs <папка сборки> tree
```

- Имя папки компонента в конце (`tree` для `sf-tree`) ограничивает съёмку
  одним компонентом; без него снимаются все.
- `--check` ничего не записывает и падает на устаревшем или отсутствующем
  снимке; кандидат пары запускает именно его.
- Новые и изменённые файлы `static/` коммитятся вместе с правкой.
- Если выведенный скелетон получился неверным (строки повторяются по
  настройке), напишите `skeleton.html` и объявите его в
  `presentation.skeleton.file`; других способов поправить снимок нет.

## Изменил файлы — подними версию

У каждой единицы SIMAI Framework есть паспорт по стандарту
`simai.linkage` 1.0.0: код, версия, хеш содержимого всех её файлов и её
зависимости. У смарт-компонента паспорт выводится из `component.json`,
отдельного файла рядом нет.

- **Версия следует за файлами.** Изменился хотя бы один файл компонента —
  меняется его версия: исправление без изменений интерфейса — третья цифра,
  добавление, которое ничего не ломает, — вторая, изменение, после которого
  потребитель должен что-то сделать, — первая.
- **Хеши и зависимости пересчитывает команда, версию — никогда.** После
  правки и подъёма версии выполните в `simai/ui-source`:

  ```sh
  npm run linkage:write
  ```

  `npm run linkage:check` проверяет паспорта, не меняя их.
- Версия не уменьшается, а код единицы не меняется и не используется
  повторно. Переименование — новый код и старое имя с датой в журнале
  изменений.
- Выпуск, в котором хеш единицы изменился, а версия осталась прежней,
  проверка выпуска не пропускает. Проверка действует с первой пары, которая
  поставляет опись единиц; первая такая пара — `ui-6d7ee4232223`.

## Зачем это нужно

С выпуска `ui-6d7ee4232223` пара поставляет опись единиц: код, версию и
хеш каждой. Сайт
документации, библиотека в Figma и проекты записывают, с какой версией и
каким хешем каждой единицы они сделаны, а команда сверки из ui-builder
сравнивает эту запись с описью нового выпуска и говорит про каждое место: актуально, есть
обновление, нужно действие, старое имя работает до даты или единицы больше
нет. Сверка верна, только если версия честно следует за файлами, а снимок —
за видом.
