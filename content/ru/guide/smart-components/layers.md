# Окна и панели

Окно, боковая панель, всплывающая поверхность, меню, выпадающий список и
уведомление рисуются поверх страницы. Все они — слои одного общего стека
ядра SIMAI Framework. Страница описывает стек, работу фокуса, закрытие с
причиной и вопрос человеку из правила сборки.

## Один стек

Каждый компонент, который рисуется поверх страницы, регистрируется в
**одном стеке слоёв документа** и объявляет:

```json
"layer": {"kind": "modal", "locks-page": true, "traps-focus": true}
```

| Поле | Что значит |
|:---|:---|
| `kind` | `modal` — окно, `panel` — панель, `surface` — всплывающая поверхность, `toast` — уведомление |
| `locks-page` | блокирует прокрутку страницы |
| `traps-focus` | держит фокус внутри |

- Стек даёт каждому слою z-index из одной шкалы токенов в порядке открытия;
  открытый последним — верхний.
- Escape, нажатие снаружи и Tab обрабатывает только верхний слой. Нижний
  слой на них не реагирует.

## Слой помнит, откуда он

Слой, который рисуется вне своего хоста (через портал в конец `body`),
несёт с собой:

- вычисленные `lang` и `dir` хоста;
- тему ближайшего предка с темой;
- вычисленные значения открытых CSS-переменных, которые объявил хост.

Он выглядит и говорит так, будто стоит на месте хоста, и по-прежнему
блокирует страницу, если объявил `locks-page`.

## Фокус

Слой с `traps-focus`:

- при открытии переводит фокус внутрь;
- пока он верхний, держит Tab и Shift+Tab внутри;
- при закрытии возвращает фокус элементу, который был активен при открытии.
  Если того элемента больше нет — новому верхнему слою, иначе ближайшему
  ориентиру страницы (landmark), иначе `body`.

Слой, который закрывается в глубине стека, фокус не двигает.

## Закрытие с причиной

Перед закрытием слой отправляет **отклоняемую просьбу**
`sf-<тег>-close {reason, unsaved}`, а после — факт `sf-<тег>-closed {reason}`.

| `reason` | Что закрыло |
|:---|:---|
| `close` | собственная кнопка закрытия слоя |
| `escape` | клавиша Escape |
| `outside` | нажатие на подложку или вне слоя |
| `cancelled` | явное действие отмены |
| `api` | действие из правила или скрипта |

- `unsaved` — настройка слоя `unsaved`: её задаёт страница или связывают с
  ключом «форма изменена».
- `dismissible: false` (псевдоним `unclose`) убирает `escape` и `outside`, но
  никогда не явное действие.
- Глагол `cancel` в панели превращается в `close {reason: cancelled}`.

```js
const panel = document.querySelector('#record');
panel.addEventListener('sf-drawer-close', (event) => {
  if (event.detail.unsaved && !confirm('Закрыть? Введённое не будет сохранено.')) {
    event.preventDefault();
  }
});
```

## Вопрос человеку

Шаг правила `ask` открывает слой и ждёт, пока он закроется. Ответ —
`{accepted, reason, value}`.

- `accepted` истинно только для действия подтверждения слоя: роли `confirm`
  в его подвале или кнопки `data-sf-action="<id>.confirm"`.
- Ответ пишется в ключ шага и сохраняет цепочку причин. Дальше правило
  проверяет его, например
  `{"check": {"left": {"key": "answer.accepted"}, "op": "yes"}}`.

```html
<sf-modal id="ask-delete" label="Удалить запись?">
  <p slot="content">Запись удалится без возможности восстановления.</p>
  <div slot="footer" class="flex gap-1/2">
    <button type="button" data-sf-action="ask-delete.close">Отмена</button>
    <button type="button" data-sf-action="ask-delete.confirm">Удалить</button>
  </div>
</sf-modal>
```
