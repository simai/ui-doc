# Доступность

Доступность компонента описана в манифесте так, что её можно проверить
автоматически: роль, откуда берётся имя, какая клавиша что делает и о чём
сообщается экранному диктору. Страница описывает раздел `accessibility`
детали и сборки и проверку в браузере.

## Раздел `accessibility`

```json
"accessibility": {
  "role": "spinbutton",
  "name": {"from": ["label", "slot:label", "aria-label"]},
  "keys": {"Tab": "reach", "ArrowUp": "step:+1", "ArrowDown": "step:-1",
           "PageUp": "step:+page", "PageDown": "step:-page",
           "Home": "to:min", "End": "to:max", "Enter": "commit"}
}
```

## Имя — точно из источника

- `name.from` перечисляет источники имени по порядку: настройка, слот,
  `aria-label`. В каждом примере у имени должен быть источник.
- **Имя точное.** Вычисленное доступное имя равно первому непустому
  источнику из `from` — ни словом больше.
- Помощь, описание и подсказка уходят в описание (`aria-describedby`) и
  никогда в имя. Переключатель, который кладёт описание внутрь своего
  `<label>`, нарушает это правило: диктор прочтёт описание как часть имени.

## Клавиши и их действие

`accessibility.keys` связывает каждую клавишу с её действием из закрытого
списка:

| Действие | Что делает клавиша |
|:---|:---|
| `reach` | до элемента можно дойти клавишей |
| `toggle:<состояние>` | переключает состояние: `toggle:checked` |
| `step:<±n или ±page>` | меняет значение на шаг или на страницу |
| `to:<min, max, first или last>` | переводит к краю |
| `focus:<next, prev, first или last>` | переводит фокус |
| `open`, `close` | открывает, закрывает |
| `commit`, `revert` | фиксирует, отменяет ввод |
| `select` | выбирает |

Клавиша, которая работает только при некоторых настройках, говорит об этом
через `when`:

```json
"Escape": {"effect": "close", "when": {"orientation": "horizontal"}}
```

Простой список клавиш без действий — старая форма. Кроме клавиш
доступности, манифест объявляет клавиатуру по элементам — хост, `row`,
`cell`, `header`, `panel` — в поле верхнего уровня `keyboard`:

```json
"keyboard": {"row": {"ArrowDown": "focus:next", "Enter": "open"}}
```

Поле называется `keyboard`, потому что `keys` у сборки — её данные, и оба
поля должны помещаться в один манифест. Старое написание `keys` для
клавиатуры читается до версии стандарта 1.4.0 с предупреждением проверки.

Каждая объявленная клавиша нажимается в каком-нибудь примере. Клавиша,
которую обещает документация и которой у компонента нет, — ошибка.

## Что говорит сборка

- Сборка объявляет роль и имя, как любой компонент.
- `accessibility.announces` — `{"total": "polite"}` — перечисляет значения,
  о которых сборка сообщает. Она рисует одну живую область (live region) и
  пишет туда слова значения при его изменении. Поле `announces` на верхнем
  уровне манифеста — старая форма; она читается до версии стандарта 1.4.0.

```json
"accessibility": {"role": "region", "name": {"from": ["runtime.title"]},
                  "announces": {"total": "polite"}}
```
- Состояние данных (`loading`, `ready`) никогда не объявляется как есть:
  слова берутся из файла слов — «Загружается список», «Найдено 25 записей».
- Сборка, которая рисует заголовок, берёт его уровень из настройки
  `heading-level`. Без настройки она рисует подпись группы, а не заголовок.

```html
<sf-record-list collection="orders" heading-level="2"></sf-record-list>
```

## Что проверяется в браузере

Для каждого примера:

- роль и имя из дерева доступности; имя равно своему источнику;
- каждая клавиша из `accessibility.keys` нажата, и её действие видно;
- у элемента в фокусе или его части видно кольцо фокуса;
- каждое изменение значения видно в дереве (`checked`, `expanded`,
  `valuenow`, `selected`) или в живой области;
- axe-core без нарушений уровня `serious` и выше. Правила уровня страницы
  (`heading-order`, `region`, `landmark-*`) запускаются на странице примера,
  а не на компоненте.

Ещё проверяется, что объявлены побочные эффекты и указана версия.
