# События

Глава описывает, какие события отправляет компонент и по каким правилам. Единые
правила позволяют проекту подписываться на любой компонент одинаково.

Событие сообщает, что произошло, и передаёт данные в `event.detail`.
Компоненту не нужно знать, какая страница его использует: проект подписывается
на событие и решает, что делать дальше. Поэтому дочерний компонент не
связывают с конкретным глобальным объектом проекта.

## Три вида событий

| Вид | Имя | Пример |
|:---|:---|:---|
| Изменение значения | `change` | Выбрана дата, введён текст, переключён флажок |
| События компонента | Своё у каждого компонента | `sf-popover-open`, `sf-page-change`, `sf-file-upload:select`, `modal:after-close`, `drawer:after-open`, `close` |
| Этапы жизненного цикла | `sf-<этап>` | `sf-connected`, `sf-after-render` |

У событий компонентов нет единого шаблона имени. Точное имя каждого события
записано в разделе `events` манифеста компонента и на его странице в
справочнике; имя не выводят по аналогии с другим компонентом.

В классе событие компонента обычно отправляется методом
`emitComponentEvent('table-query-intent', detail)` — базовый класс сам
добавляет префикс `sf-`: вызов `emitComponentEvent('confirm')` создаёт
событие `sf-confirm`. Подписка использует полное имя.

`detail` частых событий:

| Событие | `detail` |
|:---|:---|
| `change` у `sf-datepicker` | `value` (дата `ГГГГ-ММ-ДД` или пара `[начало, конец]` при `range`), `date`, `isoValue`, `formattedValue` (дата в формате `format`), `range`, `format`; при `range` ещё `startValue`, `endValue`, `formattedStartValue`, `formattedEndValue`, `startIsoValue`, `endIsoValue` |
| `change` у `sf-dropdown` | `value` (значение выбранного варианта), `label`, `values` (все выбранные значения), `item`, `root`, `multiple` |
| `sf-page-change` у `sf-pagination` | `component`, `tagName`, `template`, `previous`, `current`, `total`, `pageCount`, `pageSize` |
| `sf-page-size-change` у `sf-pagination` | `component`, `tagName`, `template`, `previous`, `pageSize`, `current`, `total`, `pageCount` |
| `modal:before-open`, `modal:after-open`, `modal:after-close` и другие `modal:*` | `component` и `modal` (сам элемент `<sf-modal>`), `modalId`, `root`, `phase` |
| `sf-theme-change` на `window` | `theme`, `preference` (см. [Как выбирается тема на странице](/ru/guide/colour/themes/#как-выбирается-тема-на-странице)) |

Остальные — на страницах компонентов в справочнике. У `sf-datepicker`
прежнее имя `sf-change` несёт другой `detail`: все данные компонента, а не
состав `change`; подписывайтесь на `change`.

## Соглашение `change`

- Любой элемент формы сообщает подтверждённое изменение значения событием
  `change` на своём теге.
- Ровно один раз на одно действие человека.
- Непрерывное действие — удержание кнопки, перетаскивание — одно действие:
  `change` отправляется один раз, когда оно завершилось (кнопку отпустили).
  Промежуточные значения, если подписчику они нужны, сообщаются событием
  `input`, как у нативного `<input type="range">`.
- Значение, установленное из кода, — не изменение.
- Если нативный элемент внутри уже отправил `change`, компонент не повторяет
  его — иначе подписчик получит два события.

Для совместимости компоненты продолжают отправлять и дополнительные имена
события изменения; в манифесте они отмечены как `alias_of: "change"` (см. [Жизненный цикл изменений](/ru/guide/connection/change-lifecycle/)).

## Правила для события

- События всплывают (`bubbles`, `composed`): родитель получает события вложенных
  элементов. Проверяйте `event.target`, если внутри несколько одинаковых
  контролов.
- Не отправляйте то же событие повторно из каждого родителя — исходное и так
  всплывает.
- В `detail` — минимальные сведения о действии. Не передавайте секреты и
  целый ответ сервера. Событие, отправленное через `emitComponentEvent`,
  получает от базового класса ещё `component`, `tagName` и `template`.
  Событие `change` и другие события, которые компонент отправляет сам через
  `dispatchEvent`, этих полей не содержат.
- **Копия содержимого сохраняет то, что не переносит JSON.**
  `JSON.parse(JSON.stringify(...))` молча превращает `File`, `Blob`, `Date` и
  `Map` в `{}` или строку. Например, намерение загрузки придёт с пустым
  объектом вместо файла, и проверка размера на стороне приложения пропустит
  всё. Копируйте простые части, а такие значения передавайте по ссылке или
  через `structuredClone`.
- Слушатель на `document` или `window` компонент хранит как функцию и снимает
  при отключении (см. [Освобождение ресурсов](/ru/guide/smart-components/lifecycle/#освобождение-ресурсов)).
- Каждое событие объявлено в разделе `events` манифеста; схема `detail`
  записана в его поле `payload`.
