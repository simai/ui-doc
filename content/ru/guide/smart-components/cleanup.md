# Обновление и освобождение ресурсов

Когда элемент удаляется со страницы, его обработчики на внешних объектах, таймеры и незавершённые запросы могут продолжать работать. Компонент должен завершать принадлежащую ему работу при отключении.

## Когда применять

Это обязательно для компонентов, которые слушают `window`, периодически опрашивают данные или открываются и закрываются много раз.

## Пример

```js
onConnected() {
  this.abort = new AbortController();
  window.addEventListener('resize', this.handleResize, {
    signal: this.abort.signal
  });
}
onDisconnected() {
  this.abort?.abort();
  super.onDisconnected();
}
```

`handleResize` должен быть сохранённой функцией экземпляра. При повторном подключении создаётся новый `AbortController`, поскольку отменённый контроллер повторно использовать нельзя.

## Проверка

Добавьте элемент, выполните действие, удалите его и добавьте снова. Одно действие должно приводить к одному событию. Для асинхронного запроса дополнительно исключите применение устаревшего результата после удаления или нового запроса.

Базовый класс вызывает `onConnected()` после подключения и `onDisconnected()`
перед окончательным освобождением внешнего шаблона. Для обычной настройки не
переопределяйте `connectedCallback()` и `disconnectedCallback()` целиком.
Также доступны `beforeRender`, `afterRender` и `afterUpdate`. Если вы
переопределяете очистку, сохраняйте вызов `super.onDisconnected()`.
