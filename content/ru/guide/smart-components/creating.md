# Создание Smart-компонента

Smart-компонент начинается с JavaScript-класса. Класс описывает входные значения, действия и шаблон; браузер связывает его с собственным HTML-тегом. Для проекта выберите свой префикс — например `project-counter`, чтобы не пересечься с библиотечными `sf-*`.

## Когда применять

Создавайте новый компонент, если готового элемента с нужным поведением нет, а сценарий повторяется. Для одного статичного фрагмента достаточно HTML и утилит.

## Подготовка

Подключите Core. Его Loader запускается асинхронно: если `SF.loadSmartBase` ещё не появилась, дождитесь события `sf-loader-init`, как в коде ниже. Затем выполните `await SF.loadSmartBase()`. После этого доступны `SF.smart.SfBaseElement` и `SF.smart.html`. В исходном модуле Framework те же сущности импортируются из `smart-base` и `lit`; проектный пример ниже использует уже загруженную браузерную поставку и не требует сборщика.

## Что происходит внутри

`SfBaseElement` наследуется от стандартного `HTMLElement`. Базовый класс читает объявленные атрибуты и запускает обновление при их изменении. Lit — небольшая библиотека шаблонов — обновляет DOM по результату `html`. В этой поставке разметка создаётся внутри самого элемента, в обычном DOM; не следует считать, что каждый Smart-компонент использует Shadow DOM.

Не вызывайте `customElements.define()` повторно для другой реализации уже существующего тега. Для нового поведения создайте новый тег или обновите общий исходный класс перед загрузкой страницы.
