# Записи: строки и узлы

Таблица, список, дерево и лента показывают **записи** — строки, пункты,
узлы, сообщения. Страница описывает, что есть у записи, как компонент держит
выбор и состояние записей, как меняются отдельные записи и как компонент
справляется с тысячами записей.

## Ключи записи

У записи есть `id` (тип `id`) и ключи записи из словаря:

| Ключ | Слово | Что значит |
|:---|:---|:---|
| `revision` | версия | версия для сравнения и замены; каждое изменение несёт её; разделы записи делят версию записи; растущая запись повышает её с каждой частью |
| `client-key` | ключ записи | постоянный ключ одного изменения; повтор с тем же ключом — то же изменение; его делает источник |
| `growing` | пишется | другая сторона ещё пишет эту запись (поток между `begun` и концом); список остаётся `ready`, запись рисуется с `aria-busy` |
| `write` | отправка | `pending`, `failed` или `done` — собственное изменение записи; список при этом остаётся `ready` |
| `allowed` | разрешённые действия | какие действия предлагает эта запись |
| `writable` | можно менять | какие поля этот человек может менять в этой записи |
| `level` | уровень | уровень в дереве, с 0 |
| `siblings`, `place` | всего на уровне, место на уровне | для дерева |
| `address` | адрес | собственный адрес записи: скопировать ссылку, открыть целиком |
| `trail` | путь | коды от корня |
| `cursor` | продолжение | следующая страница уровня или списка |

Для деревьев есть ещё `parent`, `position`, `has-children`, `expanded`,
`icon` и `icon-expanded`, для лент — `deleted` и `files`.

Поля записи пишутся в kebab-case. Источник переводит поля хоста
(`__tree.*`, `href`, `path`) в эти имена и не передаёт дальше имена вида
`__x`; `address` заменяет `href` и `url`.

## Собственное состояние записи

Компонент, который повторяет записи, может объявить `entry-state` —
поля, которые он держит сам для каждой записи по её коду:

```json
"entry-state": {"current": "boolean", "pending": "list", "loading": "boolean"}
```

- У состояния записи нет шины и правил.
- Оно переживает новый `items` для того же кода и удаляется для кода, который
  ушёл.
- Шаблон читает его как `row.@current`.

## Выбор

Компонент объявляет `"selection": "none" | "one" | "many"`.

| Режим | Значения |
|:---|:---|
| `one` | `selected` — один код, текущая запись |
| `many` | `selected` и `selection` — список кодов в порядке записей |

- Оба значения можно записать и снаружи.
- Выбор хранится по кодам, отдельно от записей. Новый `items` сохраняет коды,
  которые остались, убирает остальные и сообщает `change` один раз.
- Значение может объявить `"max"`; сверх него компонент отказывает и
  сообщает об этом.
- Выбор диапазоном и рамкой — поведение, а не интерфейс.

## Действия над записями

| Что | Как |
|:---|:---|
| Действие одной строки | `apply {action, scope: entry, ids: [id]}`; `revisions` заполняет компонент, который держит записи |
| Перестановка | `move {ids, parent, before, revisions}`; `before` — код или `null` для конца |
| Действие над выбранными | `apply {action, scope: selection, ids, revisions}` |
| Действие над всеми под фильтром | `apply {action, scope: filter}`; нужно подтверждённое, а не приблизительное число |

Действие предлагается у записи, только если его называет её `allowed`.

## Запись в ячейке

Изменение одного поля одной записи прямо в ячейке — событие с
`"waits": true`:

1. `write` записи становится пополевым: `{"published": "pending"}`;
2. изменение несёт `revision` и `client-key`;
3. исход приходит через действие `settle {id, answer, record}`;
4. при любом ответе, кроме `applied`, ячейка показывает значение хоста, а
   поле помечается `failed`.

```js
table.addEventListener('sf-table-save', async (event) => {
  const { id, values, revision } = event.detail;
  const answer = await app.save({ id, values, revision });
  table.settle({ id, answer: answer.answer, record: answer.record });
});
```

## Много записей

- Список может объявить `"entries": {"key": "id", "changes": "revision"}`
  или `"changes": "content"`. Тогда связь несёт заплатки
  `{upsert, remove, order}` по коду вместо всего списка.
  - «Равное значение не передаётся повторно» сравнивает `id` вместе с
    `revision` (по умолчанию, `changes: revision`) или поля записи
    (`changes: content`).
  - Хост, у которого запись растёт (поток ответа), повышает её версию с
    каждым изменением, иначе список объявляет `content`. На стенде хост,
    который не менял версию, довёз 2 части из 30.
- Компонент, у которого бывает **больше 300 записей**, обязан объявить
  `"window": true`. Остальные могут.
  - Он рисует только видимые записи с запасом и сообщает
    `window {first, last}`.
  - Статическая разметка рисует только первую страницу.
- Изменение одной записи перерисовывает только её и **на месте**: элемент
  обновляется, а не заменяется, поэтому фокус и выделение внутри записи
  остаются. Лента, которая заменяет узел сообщения на каждую часть ответа,
  роняет фокус на `body` — так делать нельзя.
- Ячейка, которая только показывает значение, — разметка на классах.
  Смарт-элемент ставится в ячейку, только пока её редактируют.

Дорого рисование, а не шина: ход с 200 связанными деталями занимает меньше
1 мс, а замена списка из 10 000 записей целиком против заплаток по коду —
38 мс против 32 мс.

Пределы ниже — числа профиля качества текущей версии стандарта, см.
[Проверки](/ru/guide/smart-components/quality/#профиль-качества).

| Случай при четырёхкратно замедленном процессоре | Предел |
|:---|:---|
| Первая отрисовка, 100 записей | ≤ 1 с |
| Первая отрисовка, 1 000 записей | ≤ 1,5 с |
| Изменилась одна запись | ≤ 50 мс при любом числе |
| DOM-узлов на запись | ≤ 30 |
| Пример на 10 000 записей | ≤ 2× примера на 1 000 |
| Ход шины с 200 связанными деталями | ≤ 5 мс |
