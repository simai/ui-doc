# Загрузка и общая среда

Страница про то, что происходит, когда смарт-компоненты приходят на
страницу: какой код у них общий, в каком порядке загрузчик их определяет и
на какие браузеры рассчитан SIMAI Framework. Как выглядит компонент до
прихода кода, описано на странице
[Первый кадр и ленивая загрузка](/ru/guide/smart-components/first-paint/).

## Одна общая среда на странице

Страница, на которой есть смарт-элементы, выполняет **одну копию** кода, на
котором они построены. Сборка каждого смарт-компонента
(`distr/smart/<папка>/js/<папка>.min.js`) и каждого пакета продукта несёт
только свой элемент. Lit, основа смарт-элементов и слой элементов приходят
из **общей среды** страницы — скрипта `distr/core/js/smart-base.min.js` рядом
с `core.min.js`.

:::diagram {engine=mermaid title="Общая среда: сборки компонентов и пакетов просят общие модули у страницы и не несут их копий"}
flowchart TB
    core["core.min.js — ядро и загрузчик"]
    runtime["smart-base.min.js — общая среда: lit, основа, слой элементов"]
    button["Сборка sf-button — только свой элемент"]
    tree["Сборка sf-tree — только свой элемент"]
    larena["Пакет larena из ui-pro — только свои элементы"]
    core -->|загружает| runtime
    button -->|просит модули| runtime
    tree -->|просит модули| runtime
    larena -->|просит модули| runtime
:::

До выпуска `ui-1fe369009512` (core.runtime 1.1.0) каждая сборка несла свой
слой элементов: около 26 КБ минифицированного кода, 61 % средней сборки, один и тот
же код 59 раз. С общей средой 66 сборок смарт-компонентов весят 580 КБ в
gzip вместо 1075 КБ, а страница списка в админке загружает 641 КБ скриптов
вместо 831 КБ.

**Что раздаёт среда.** Список — договор `core/contracts/shared-runtime.v1.json`
выпуска:

| Модули | Что это |
|:---|:---|
| `lit` и его директивы (`ref`, `keyed`, `repeat`, `unsafe-html` и другие) | шаблоны |
| `smart-base` | основа смарт-элемента |
| `element-manifest`, `aliases`, `alias-table`, `deprecations`, `instance-path` | элемент из манифеста, псевдонимы старых имён, путь экземпляра |
| `host-port`, `page-actions`, `layer-stack`, `open-surface-mark` | порт хоста, кнопки `data-sf-action`, общий стек слоёв |
| `page-language`, `position`, `control-spacing` | язык страницы, позиционирование, отступы элементов управления |

Сборка не кладёт эти модули в себя: она просит их у страницы —
`SF.runtimeModule(id, abi)` — и ждёт. Часть модулей ядро выполняет само
(псевдонимы, устаревшие имена, язык страницы, стек слоёв, позиционирование)
и отдаёт сборкам **свой экземпляр**, поэтому ядро и все смарт-элементы
делят одно состояние. Страница без ядра — тест, проба, страница с одной
`smart-base.js` — тоже работает: у среды есть свои копии этих модулей, а их
состояние в обоих случаях лежит на `SF`.

**Что сборка берёт из `component.json`.** Элемент импортирует свой
`component.json` и строит себя по нему. С виду файлов 1.4 в нём лежит и то,
что читают только построение, реестр и документация. В сборку попадают
только ключи верхнего уровня, которые читает среда (`id`, `tag`, `version`,
`kind`, `settings`, `values`, `events`, `actions`, `form`, `presentation`,
`host-states`, `port`, `layer`, `implements`, `traits`, `words`,
`css-variables`), и без слов для людей (`description`, `summary`,
`examples` и подобных) на глубине двух уровней и ниже. По 59 манифестам
вложенные данные уменьшились со 180 до 98 КБ. Код, который читает другой
ключ манифеста, обязан добавить его в этот список — проверка договора
находит такое чтение и не пропускает его.

## ABI среды

У среды есть номер ABI — договора о её модулях; сегодня он равен 1.
Сборка построена с ABI своего исходного кода и просит модули с ним. Среда
другого ABI отказывает: ошибка в консоли и отклонённое определение элемента,
а не `undefined` в руках пакета, построенного под другой выпуск.

| Изменение | ABI |
|:---|:---|
| добавлен модуль или экспорт | не меняется |
| убран или переименован модуль или экспорт, изменился смысл экспорта | поднимается; договор переписывается, каждый пакет пересобирается под новый выпуск |

Модуль среды экспортирует только `const`, `function` и `class`: сборка
получает замороженную копию его пространства имён, и `export let`,
переназначенный позже, остался бы у неё первым значением. Проверка договора
не пропускает `export let`, `export var` и `export *` в этих модулях.

Пакеты продукта работают на той же среде и своей копии не несут — см.
[Пакеты партнёров и проектов](/ru/guide/smart-components/packages/#пакет-работает-на-общей-среде).

## Порядок загрузки

- **Среда приходит заранее.** Ядро начинает загружать `smart-base.min.js`,
  как только видит на странице неопределённый элемент `sf-`, а выполняет его,
  когда загрузчик ставит в очередь первый смарт-элемент. Страница, которая
  сама пишет `<link rel="modulepreload">` для среды, получает её ещё раньше.
  Скрипт среды, подключённый вручную, загрузчик ждёт и второй раз не
  загружает.
- **Элемент с объявленным портом — первым.** Загрузчик просит части
  элемента, внутри которого объявлен порт (его правило, детали внутри и их
  связи), раньше остальных, а основа определяет их отдельной пачкой, до
  других определений этого кадра. Сам первый запрос к порту ядро отправляет
  ещё раньше, до кода любого компонента — см.
  [Порт, объявленный в элементе](/ru/guide/smart-components/data/#порт-объявленный-в-элементе).
- **Компонент рисуется после своих стилей.** Он отрисовывается, только когда
  применены его таблица стилей, таблицы связанных компонентов и таблицы
  утилит, которые используют его шаблоны (`Loader.ensureStylesReady`).
  Таблица, уже подключённая в `<head>`, считается сразу; ленивая связь не
  ждётся. До этого остаётся напечатанный начальный вид, поэтому кадра с
  текстом без стилей нет. Работа после отрисовки идёт, когда стили на месте
  (`data-sf-style-ready`).
- **После загрузки страницы — никаких долгих задач.** Загрузчик не держит
  основной поток дольше 50 мс: правила утилит ищет по классу, добавленные
  куски страницы обходит порциями не больше 16 мс (`scheduler.yield`), а
  готовые компоненты определяет одной пачкой на кадр, вставив их таблицы
  стилей вместе. На стенде админки задачи загрузчика были 378 и 241 мс.

## Браузеры

SIMAI Framework рассчитан на **современные браузеры** и не обещает таблицы
минимальных версий.

- Используются возможности веб-платформы, которые есть во всех популярных
  движках: Chromium, Gecko и WebKit.
- Возможность только одного движка используется лишь как улучшение:
  компоненты работают и без неё. Пример — отдельные реестры элементов для
  двух старших версий одного пакета.
