# Сравнение с прежним устройством

До стандарта смарт-компоненты SIMAI Framework были классами на
`SfBaseElement` с манифестом `smart.manifest.json`, который писал автор.
Таблицы ниже показывают, куда в стандарте переходит каждое знакомое понятие
прежнего устройства. Компоненты переходили по одной семье на выпуск пары
SIMAI Framework; все 59 смарт-компонентов переведены в выпусках
`ui-8e0b5505db8f` … `ui-363de49bdfa8`, а с выпуска `ui-e84590925e63` все
смарт-компоненты SIMAI Framework лежат в папке вида 1.4. Старые имена событий и методов
продолжают работать как псевдонимы до 2026-12-01.

Новые компоненты следуют стандарту с первого выпуска. Компоненту, у которого
ещё нет манифеста, интерфейс на время перехода даёт адаптер; других задач у
адаптеров нет.

## Устройство и интерфейс

| Прежнее понятие | Место в стандарте | Где описано |
|:---|:---|:---|
| Атрибуты и свойства (`static props`, `inputs`) | **настройки** (`settings`) и **значения** (`values`); значение, которое меняет человек, указано один раз в `values` | [Модель компонента](/ru/guide/smart-components/model/) |
| Состояние компонента | значения наружу; видимые состояния — атрибуты хоста `host-states` | [Разметка и шаблоны](/ru/guide/smart-components/markup/#состояние-видно-из-разметки) |
| Публичные методы (`methods`) | **действия** (`actions`) с исходом `applied` или `refused`; методы генерируются; методов-читателей нет | [Модель компонента](/ru/guide/smart-components/model/#действия-и-их-исход) |
| Класс на `SfBaseElement`, `index.js`, `rule.js`, `meta.mjs` | одна папка: `component.json`, `template.html`, `behaviour.js`; код элемента, правило загрузчика и реестр генерируются | [Папка компонента и манифест](/ru/guide/smart-components/folder/) |
| Методы для переопределения (`onConnected`, `beforeRender`…) | `behaviour.js` с вычисляемыми значениями и кодом действий; события отрисовки — только базовые | [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс) |
| Шаблон Lit и `templateContext()` | **HTML-шаблоны** с `{{…}}`, `:attr`, `@event`, `if`, `each … key`, которые построение компилирует в Lit; Lit внутри JavaScript — переходная форма | [Разметка и шаблоны](/ru/guide/smart-components/markup/) |
| Внешний шаблон (`template="compact"`) | `template.<имя>.html` в папке компонента; шаблоны называются по расположению | [Внешний вид](/ru/guide/smart-components/look/) |
| Публичные `refresh(reason)`, `set()` и `state` базового элемента | переименованы в `rerender`, `assign` и закрытое `#state` с псевдонимами, чтобы имя `refresh` осталось действию из словаря | [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс) |
| Слоты, забранные из детей тега | содержимое ставится и не копируется; слоты с `accepts` и `each` | [Слоты](/ru/guide/smart-components/slots/) |
| Заготовка до прихода кода, скелетоны | статическая разметка каждого примера и её подхват за один кадр | [Разметка и шаблоны](/ru/guide/smart-components/markup/#статическая-разметка) |
| Версия компонента и совместимость с экраном | **отпечаток договора** в реестре и файле блокировки; роль может закрепить `part@<старшая версия>`; изменение используемого члена отклоняет деталь при загрузке | [Папка компонента и манифест](/ru/guide/smart-components/folder/#отпечаток-договора) |
| Обработчики и таймеры, которые компонент снимает сам | **область экземпляра**: всё запущенное привязано к сигналу отмены и заканчивается с экземпляром | [Сборки](/ru/guide/smart-components/assemblies/#область-экземпляра) |
| Сохранение манифеста инструментом | сохранённый вид: новый файл — канонически, существующий — с сохранением байтов; ИИ правит заплаткой JSON Patch | [Папка компонента и манифест](/ru/guide/smart-components/folder/#сохранённый-вид-манифеста), [Для ИИ](/ru/guide/smart-components/ai/#правка-манифеста-заплаткой) |

## Манифест `smart.manifest.json` → `component.json`

| Прежде | В стандарте |
|:---|:---|
| `inputs` (схема JSON) | `settings` и `values` |
| `events` | `events` с именами по словарю |
| `methods` | `actions`; читатели уходят |
| `state.machines` | у компонента данных — состояние данных `state`; у поля — видимые состояния (`at-min`, `inherited`) как атрибуты хоста |
| `persistence` | `persist` у ключа |
| `composition` | `roles` и `bind`; `uses` выводит построение; `declarative.slots` → `slots`; `declarative.host_port` → `port` |
| `capabilities`, `tags`, `reuse_mode`, `lifecycle` | каталог `catalogue.json` |
| `provenance`, `runtime_pair` | файл блокировки построения |
| данные для Студии | `examples.json` |
| `readiness` | проверки стандарта |
| `contracts.*` (свободный текст) | `docs.md` или пример |
| `accessibility.keyboard`, `accessible_name` | `accessibility.keys` с действиями и `accessibility.name.from` |
| `aria-label`, `role` как входные настройки | атрибуты хоста, а не настройки |
| строковая настройка с числами (`min`, `max`, `step`, `heading-level`) | `number` с `integer`, `min`, `max` и `step` |
| `keys` для клавиатуры у детали | `keyboard`; `keys` — только данные сборки |
| побочные эффекты в свободной форме | `side-effects` |
| `announces` на верхнем уровне | `accessibility.announces` |
| `security`, `ownership`, `presentation`, `ai_guidance` | остаются как есть до следующей версии стандарта |

С папкой вида 1.4 `smart.manifest.json` никто не пишет: его вместе с
`rule.js`, `aliases.json`, `meta.mjs`, файлами Студии и `probe.json`
генерирует построение из `component.json`, `examples.json` и `lang/`.

Манифест прежнего вида переводит скрипт; всё, что он не смог разместить,
перечисляется по компоненту и проходит проверку переведённых манифестов.
Подробно о манифесте — [Папка компонента и манифест](/ru/guide/smart-components/folder/).

## Известные расхождения текущей поставки

Стандарт перечисляет места, где компоненты текущей поставки ему ещё не
соответствуют. Каждое исправляется вместе с переходом своей семьи.

Уже закрыто и убрано из таблицы:

- ядро больше не прячет всю страницу, а элемент не рисуется рядом со
  статическими детьми — подхват в общей основе (simai/ui-source#39, #40,
  выпуск `ui-133dc02b833d`);
- `sf-tree` рисует записи плоско, строками на классах по ключу, и при
  более чем 300 видимых записях — только те, что в окне (simai/ui-source#43,
  `sf-tree` 2.0, выпуск `ui-363de49bdfa8`);
- `sf-property-view` держит одну версию на запись и читает разделы через
  `group.load` (пункты 25 и 35 переноса, порт 1.15.0 в выпуске
  `ui-dde3ef154c34`, ui-pro `c6f3cfc`);
- деталь под ложным `if`, в закрытом контейнере или с `start` `opened`
  или `visible` не загружает код, а редакторы полей `sf-property-view`
  загружаются лениво (simai/ui-source#47, выпуск `ui-6d7ee4232223`; ui-pro
  `41956dc`);
- базовое действие `connect-port` есть у каждого смарт-элемента, а
  `SF.Assembly` доводит порт до деталей (выпуск `ui-8ae9162049f4`);
- проверка 36 — проба в браузере на кандидате: убранный компонент не
  оставляет ни обработчиков, ни таймеров, ни запросов (пункт 36 переноса,
  выпуск `ui-5b5b8543358e`);
- до кода элемент держит только рамку, которую дала страница, рисуется
  после своих стилей, а загрузчик не держит основной поток дольше 50 мс
  (стенд 25, выпуск `ui-f528fb4a3c0a`);
- одна общая среда смарт-элементов на странице вместо копии слоя элементов
  в каждой сборке (выпуск `ui-1fe369009512`);
- порт, объявленный в элементе: ядро спрашивает первые строки раньше кода
  компонентов (`SF.EarlyPort`, выпуск `ui-9d72994c3163`);
- запись реестра `smart.manifest.json` больше не расходится с
  `component.json`: её генерирует построение (стандарт 1.4, все
  смарт-компоненты SIMAI Framework с выпуска `ui-e84590925e63`).

## Открытые вопросы стандарта

Эти вопросы стандарт 1.3.12 не решает; ответы на них в него не входят:

- старшая версия ui-pro относительно пар SIMAI Framework;
- таблица соответствия типов значений документа композиции типам ключей:
  направление задано, а таблица пишется с первым документом, который
  скомпилирует Docara или Larena;
- компоненты поведения после `sf-source`: `sf-form-state` (ключ «форма
  изменена», который читает `unsaved` у слоя) и горячие клавиши;
- оптимистичные изменения отдельных ключей в строках и их откат в полосе
  проверки Студии;
- статическая разметка двух старших версий одного тега на одной странице;
- операторы связи кроме `debounce` и чтения сверх закрытого списка: каждый
  появится, только когда его докажет стенд;
- шаг `do` ничего не возвращает правилу: сводка и отпечаток подтверждения
  хоста доходят до правила через значения источника, а необязательный
  `answer` у `do`, как у `ask`, убрал бы их из интерфейса источника;
- провод для `persist: "host"`: что должен предложить хост, чтобы настройку
  хранил он, а не браузер;
- сборка, которая сама слой: объявляет ли она `layer` и входит ли в общий
  стек слоёв;
- проверка, что файлы, которые называет манифест — `docs.md`, раскладки,
  файлы слов, — существуют;
- слова черты: `field-inherit@1` приносит шести полям настройки-слова
  `inherited-text` и `reset-label`, и открыто, перечисляет ли интерфейс
  черты свои слова отдельно.
