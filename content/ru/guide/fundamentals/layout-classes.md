# Классы раскладки

Компонент Framework сам себя не раскладывает. CSS оформляет части — цвет,
размер, границу, — а флекс-контейнер, в котором они лежат, пишется в разметке
утилитарными классами. Это не упущение, а устройство: одна и та же часть
встречается в разных композициях, и раскладку выбирает тот, кто собирает
страницу.

Цена такого устройства — забытый класс. Никто не возразит: элемент просто не
становится контейнером, и его части сваливаются в угол.

```html
<!-- точка окажется в левом верхнем углу кольца -->
<span class="sf-radio-button-box flex">…</span>

<!-- точка по центру -->
<span class="sf-radio-button-box flex flex-row flex-nowrap justify-center items-center">…</span>
```

Smart-компоненты собирают разметку сами и так не ломаются. Ошибка возможна там,
где разметку пишет человек: в примере руководства, в шаблоне проекта, в странице.

## Что требуется, а что нет

Над каждым правилом, которому нужна раскладка, в исходном CSS стоит подсказка:

```css
/* utility-hint: display/flex (.flex) flex-direction/row (.flex-row)
   flex-wrap/nowrap (.flex-nowrap) justify-content/center (.justify-center)
   align-items/center (.items-center) */
.sf-radio-button .sf-radio-button-box { … }
```

Она перечисляет раскладку целиком, как её записал макет. Требование — не вся
подсказка. Флекс-контейнер и так идёт строкой, без переноса и от начала, поэтому
`flex-row`, `flex-nowrap` и `justify-start` ничего не меняют и без них ничего не
ломается. Значение имеет остальное: сам `flex`, колонка, перенос, выравнивание
не от начала.

## Проверка

Статически это не проверить. Значение может прийти из утилиты, из стилей
проекта, из инлайна; опубликованный CSS содержит вложенные `@supports`, `@layer`
и `:where()`. Итог знает только браузер, поэтому проверка работает в странице.

```html
<script src="/ru/assets/tools/layout-check.js"></script>
```

Можно и вставить содержимое файла в консоль. Проверка ничего не меняет на
странице и ничего не отправляет; результат — список в консоли и массив из
`sfLayoutCheck()`, которому можно передать корень, чтобы проверить часть
страницы.

Это инструмент разработки. В рабочую сборку его включать не нужно.

Сообщается только доказуемое:

* элемент — контейнер, но выравнивание в нём осталось по умолчанию: решение из
  макета до страницы не дошло;
* элемент контейнером не стал, но ему объявлен `gap`: расстояние между частями
  не применяется.

Остальное не считается ошибкой. Страница вправе прийти к тому же виду другим
способом — `text-align`, отступами, сеткой родителя, — и подсказка описывает
макет, а не единственный допустимый путь. Скрытые элементы и подписи без
вложенных элементов пропускаются.
