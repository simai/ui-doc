# Каскадные слои

Весь CSS фреймворка объявлен в именованных каскадных слоях, а их порядок задан
один раз, в начале `core.css`:

```css
@layer sf.reset, sf.tokens, sf.base, sf.utilities, sf.components, sf.overrides, sf.states;
```

Слой, объявленный позже, сильнее объявленного раньше — независимо от
специфичности селектора. Это главное, что нужно знать: специфичность решает спор
**внутри** слоя, но не между слоями.

## Что в каждом слое

| Слой | Что в нём |
|:---|:---|
| `sf.reset` | нормализация браузерных значений |
| `sf.tokens` | объявления переменных |
| `sf.base` | базовые стили элементов и примитивы: шкала, палитра, иконки |
| `sf.utilities` | все классы утилит |
| `sf.components` | стили компонентов |
| `sf.overrides` | компонент, перенастраивающий другой компонент внутри себя |
| `sf.states` | значения, зависящие от состояния, — они должны побеждать перенастройку |

## Три следствия

**Компонент сильнее утилиты.** `sf.components` объявлен после `sf.utilities`,
поэтому утилита не перебьёт собственное правило компонента. Если нужно поменять
геометрию или цвет компонента, меняйте его токен (`--sf-button--…`), а не
навешивайте класс утилиты и не повышайте специфичность — это не поможет.

Исключение — `!important`: у важного объявления порядок слоёв переворачивается,
и утилита побеждает компонент. Во фреймворке так написаны только утилиты цвета
тени для `hover` и `active` (52 правила из 81 028), потому что перекрасить тень
иначе нечем. В своём коде `!important` в утилите не нужен.

**CSS без слоя сильнее любого слоя.** Правило, написанное в проекте без
`@layer`, побеждает весь фреймворк, включая `sf.states`. Это удобно и опасно
одновременно: случайно оказавшееся вне слоя правило фреймворка становится
неотключаемым. Именно так однажды цвет иконки перестал поддаваться токену.

**Порядок задаётся один раз.** Первая строка с перечислением слоёв фиксирует
очередь. Повторное `@layer sf.components { … }` ниже по файлу ничего не двигает —
оно просто дописывает в уже занявший своё место слой.

## Как переопределять правильно

Переопределение проекта пишите в `sf.overrides` — тогда оно будет сильнее
компонентов, но останется под состояниями и под вашим же кодом вне слоёв:

```css
@layer sf.overrides {
  .my-panel .sf-button {
    --sf-button--border-top-left-radius: var(--sf-radius-square);
  }
}
```

Если правило должно пережить и состояния — пишите его без слоя, осознанно, и
понимая, что отключить его изнутри фреймворка будет уже нечем.

## Проверка

Какой слой победил в конкретном месте, статически не вычислить: в опубликованном
CSS есть вложенные `@supports`, `@layer` и `:where()`. Итог знает только браузер —
для этого есть проверка на странице, описанная в разделе
[Классы раскладки](/ru/guide/fundamentals/layout-classes/).
