# Границы

Граница в интерфейсе делает одну из двух работ: либо по ней **опознают элемент
управления**, либо она **очерчивает область** и делит её внутри. Работы разные,
и роли для них разные.

## Правило

| Что рисуем | Роль | Утилита |
| :--- | :--- | :--- |
| Граница контрола в покое: поле, кнопка с контуром, флажок, радио, переключатель | `--sf-outline-control` | — |
| Граница контрола при фокусе; сплошная линия, где нужен полный контраст | `--sf-outline` | `border-outline` |
| Край области: панель, карточка, таблица | `--sf-outline-variant` | `border-outline-variant` |
| Линия внутри области: строка таблицы, пункт списка | `--sf-outline-variant` | `divide-outline-variant` |
| Состояние: ошибка, успех, предупреждение | `--sf-outline-error` и остальные | `border-error` и остальные |

Граница контрола — не украшение. Линию, по которой человек находит элемент
управления, WCAG 1.4.11 требует держать на 3:1 к поверхности позади. Роль
`--sf-outline-control` — это `--sf-outline` ровно на этом пороге: 80%
непрозрачности в светлой теме и 64% в тёмной. Форма выглядит спокойнее, а поле
остаётся заметным. При наведении линия становится основного цвета, при фокусе —
цвета фокуса, то есть взаимодействие делает её только сильнее. Измерено на
собранных байтах:

| Роль | Светлая тема | Тёмная тема | Годится для контрола |
| :--- | :--- | :--- | :--- |
| `--sf-outline-variant` | 1.34:1 | 1.91:1 | нет |
| `--sf-outline-control` | 3.10:1 | 3.12:1 | да, в покое |
| `--sf-outline` | 4.47:1 | 5.56:1 | да |

Чтобы вернуть прежнюю, более контрастную линию во всём продукте, достаточно
одной строки в теме:

```css
.theme-light, .theme-dark {
    --sf-outline-control: var(--sf-outline);
}
```

К краю панели и к линии между строками такого требования нет: по ним ничего не
опознают, они делят пространство. Поэтому там полупрозрачная роль — она тише и
работает на любой подложке, не усиливая шум.

## Толщина

Волосяная линия — `--sf-px`, то есть ровно один пиксель. Не `--sf-a1`: тот
задан в `rem` и растёт вместе с кеглем, поэтому на крупной типографике рамка
толстеет, а соседняя, заданная в пикселях, нет.

Утилиты `border-0`, `border-1` и дальше задают толщину явно, когда нужна
не волосяная линия.

## Радиусы

Два радиуса по умолчанию, названные по тому, к чему их прикладывают:

- `--sf-radius--ui` — мелкий контрол: поле, кнопка, флажок. Стоит на
  `--sf-radius-1\/2`, это 4px;
- `--sf-radius--surface` — крупный блок: карточка, панель, модальное окно.
  Стоит на `--sf-radius-1`, это 8px.

Контрол ровно вдвое мельче блока. Вложенный угол должен быть меньше внешнего,
иначе вложенность не читается.

Числовая шкала `--sf-radius-0` … `--sf-radius-4` остаётся источником значений и
меняется по режиму — мобильному или десктопному. Смысловые имена берут из неё.

`--sf-radius-default` — прежнее имя для радиуса блока, сохранено как алиас. Его
значение не менялось и осталось четырьмя пикселями, то есть радиусу блока оно
больше не равно: берите `--sf-radius--surface`.
`--sf-radius-rounded` совпадает с `--sf-radius-circle`, новых мест ему не
отдают.

## Вложенность

Блок берёт отступ и угол **с одной ступени**: `p-3` — значит `radius-3`.
Вложенный блок спускается на ступень ниже.

| Уровень | Классы | Отступ (моб. / десктоп) | Угол (моб. / десктоп) |
| :--- | :--- | ---: | ---: |
| внешний | `p-4 radius-4` | 24px / 32px | 24px / 32px |
| | `p-3 radius-3` | 16px / 24px | 16px / 24px |
| | `p-2 radius-2` | 16px / 20px | 12px / 16px |
| внутренний | `p-1 radius-1` | 12px / 16px | 8px / 8px |

Угол ступени не превышает её отступ — поэтому `p-N radius-N` читается как одно
решение, а не как две подогнанные друг к другу величины.

Лестница заканчивается на `radius-1`: это `--sf-radius--surface`, радиус блока
по умолчанию, и ниже него блок не опускается. Всё, что мельче, — уже не блок, а
контрол.

Со скольких ступеней начинать — решает глубина макета, а не номер. Плоской
карточке хватит `p-2 radius-2`; если внутри неё живёт ещё одна, начинайте
выше, чтобы внутренней осталось куда спуститься.

Контрол внутрь лестницы не входит. Поле, кнопка и флажок берут угол из роли
`--sf-radius--ui` — это 4px, и значение не зависит от того, на каком уровне
вложенности контрол оказался: его размер задаёт лестница высот, а не глубина
макета. На примере выше кнопка лежит внутри самого глубокого блока и своего
угла не меняет.

## Утилиты

Классы повторяют роли, а не изобретают свои:

```html
<div class="border border-outline-variant radius-surface">…</div>
<input class="border border-outline radius-ui">
<ul class="divide-y-1 divide-outline-variant">…</ul>
```

`border` без цвета даёт полупрозрачную роль — она чаще нужна, потому что
областей на экране больше, чем контролов с собственной рамкой.

Толщину разделителя задают `divide-y-1` для горизонтальных линий и `divide-x-1`
для вертикальных; цвет — отдельным классом, как выше.

## Высота

Поднятый элемент показывает высоту двумя вещами сразу: тенью под собой и
поверхностью, на которой стоит.

| Уровень | Куда |
| :--- | :--- |
| 1 | приподнятый элемент в потоке: ручка ползунка, пункт списка |
| 2 | всплывающее меню, контекстное меню, подсказка |
| 3 | модальное окно, календарь, выпадающий список стран |
| 4 | выдвижная панель |

Уровень просят одним классом — он ставит обе части сразу:

```html
<div class="elevation-2">Контекстное меню</div>
```

В своём CSS то же самое парой переменных одной ступени:

```css
.project-panel {
    background: var(--sf-elevation-2--surface);
    --sf-on-surface-variant: var(--sf-on-elevation-2--variant);
    box-shadow: var(--sf-elevation-2--shadow);
}
```

Класс `shadow-2` ставит **только тень**. Он остаётся для редкого случая, когда
нужна именно тень, но для высоты берите `elevation-2`: в светлой теме одна тень
выглядит правильно, а в тёмной панель ложится плашмя, и заметить это на светлом
экране невозможно.

В светлой теме поднятая поверхность остаётся обычной — там всю работу делает
тень. В тёмной тень не работает вовсе: она чёрная, а фон почти чёрный. Замер на
собранных байтах: в светлой теме пиксель под карточкой отличается от поверхности
на 18 единиц на первом уровне и на 72 на пятом; в тёмной весь набор укладывался
в 3–7 единиц из 255, то есть ниже порога различимости. Поэтому в тёмной теме
высоту несёт ступень поверхности, которая там светлеет.

Первая ступень эту работу делала только на бумаге. Она стояла на `surface-1`, а
это 1.10:1 к странице — на большой залитой площади такой подъём не читается.
Ступени сдвинуты на одну вверх: первая стоит на `surface-2` и даёт 1.25:1,
четвёртая — на новой `surface-5`, и каждая следующая выше предыдущей примерно на
1.15–1.20:1. Пятый уровень по-прежнему делит верх лестницы с четвёртым.

### Текст на поднятой поверхности

Приглушённый текст задаётся относительно поверхности, на которой лежит, а в
тёмной теме поверхность светлеет со ступенью. Одно значение поэтому не годится
для всех: `--sf-on-surface-variant` даёт 4.14:1 на второй ступени и 2.93:1 на
четвёртой при требуемых WCAG 1.4.3 четырёх с половиной.

Поднятая поверхность несёт свою пару:

| Ступень | Поверхность (тёмная) | Приглушённый текст | Контраст |
| :--- | :--- | :--- | ---: |
| 1 | `surface-2` | `--sf-on-elevation-1--variant` | 4.77 |
| 2 | `surface-3` | `--sf-on-elevation-2--variant` | 5.76 |
| 3 | `surface-4` | `--sf-on-elevation-3--variant` | 4.89 |
| 4–5 | `surface-5` | `--sf-on-elevation-4--variant` | 5.47 |

**Писать эти имена не нужно.** Класс `elevation-N` переопределяет
`--sf-on-surface-variant` у себя, и компонент внутри панели продолжает брать
привычную роль, получая значение под свою поверхность. То же делают компоненты,
которые красятся ступенью напрямую, — меню, контекстное меню, календарь,
выдвижная панель.

В светлой теме поднятая поверхность остаётся обычной, поэтому там значение не
меняется.

## Чего не делать

- Не рисовать границу контрола полупрозрачной ролью: она не проходит 1.4.11.
- Не брать сплошную роль для линий внутри таблицы: экран превращается в сетку
  коробок, где всё одинаково важно.
- Не задавать толщину в `rem`: рамка начнёт жить своей жизнью при смене кегля.
- Не брать сырой цвет палитры. Роль знает про обе темы, цвет — нет.
- Не поднимать элемент одной тенью: в тёмной теме подъёма не будет видно.
- Не писать цвет тени руками: он ничего не знает о теме, в которую попадёт.
- Не задавать приглушённый текст на поднятой панели вручную: класс высоты уже
  поставил значение под её поверхность.
