# Стандарт: порт хоста

`simai.composite-host-port`, версия 1.0.2. Требования те же, что в 1.0.0: новые версии выходили, когда менялись только закреплённые байты опор.

[Динамический композитный компонент](/ru/standards/dynamic-composite-component/)
описывает поведение на стыке с приложением: намерения, ревизии, слои настроек,
состояния данных. Но сам стык при этом нигде не объявлен. Пока обе стороны
пишет один автор, они совпадают случайно; как только компонент меняет другой
продукт, приложение узнаёт об этом по поломке.

Этот стандарт делает стык предметом договора: компонент объявляет порт, порт
версионируется отдельно от компонента, приложение объявляет, какие версии порта
поддерживает, и доказывает это набором проверок.

Стандарт наследует динамический композитный компонент 1.0.2: все его требования
действуют и здесь, повторно они не перечисляются.

## Требования

| Идентификатор | Уровень | Требование |
|:---|:---|:---|
| `port-declared` | обязательно | Динамический композит объявляет свой порт в манифесте: какие данные принимает, какие намерения поднимает и какие настройки хранит, каждое со схемой. Ничего необъявленного через стык не ходит. |
| `port-versioned-separately` | обязательно | У порта своя версия, независимая от версии компонента: вид и поведение внутри компонента могут меняться без изменения порта. |
| `port-schemas-closed` | обязательно | Данные, содержимое намерений и настройки описаны закрытыми схемами. Ключ, которого в порте нет, в договор не входит и отклоняется обеими сторонами. |
| `intent-answers-declared` | обязательно | У намерения есть устойчивое имя, схема содержимого, признак «несёт ревизию» и перечень ответов хоста: применено, конфликт с текущей ревизией, отказано с причиной, недоступно. |
| `capabilities-negotiated` | обязательно | Необязательные части порта — именованные возможности. Хост объявляет, какие из них даёт этому экземпляру, компонент предлагает только их. Отсутствующая возможность объясняется, а не показывается сломанной кнопкой. |
| `permissions-come-with-data` | обязательно | Права приходят вместе с данными: хост сообщает по каждой записи и каждой возможности, что разрешено, и компонент предлагает только это. Компонент не выводит право из значения поля, имени роли или отсутствия ошибки. |
| `answer-echoes-request` | обязательно | Ответ повторяет запрос, на который отвечает: применённые фильтры, поиск, сортировку и окно, а также признак, что часть запроса отклонена. Компонент показывает то, что ответил хост, а не то, что последним набрал человек. |
| `minor-is-additive` | обязательно | Младшая версия порта только добавляет: необязательные поля, необязательные намерения, возможности. Хост, реализовавший более раннюю младшую версию той же старшей, продолжает работать без изменений. |
| `major-for-breaking` | обязательно | Удаление, переименование, превращение необязательного в обязательное и смена смысла поля или намерения — это новая старшая версия порта. |
| `previous-major-kept` | обязательно | При смене старшей версии предыдущая остаётся в изданных релизах объявленный срок, а её отказ от поддержки называет замену и дату окончания. |
| `host-declares-supported` | обязательно | Хост объявляет для каждого компонента, какие версии порта реализует. Компонент связывается с хостом по этому объявлению, а не по догадке из ответов. |
| `mismatch-is-honest` | обязательно | Если хост не реализует нужную версию порта, компонент сообщает, что возможность не подключена. Он не работает наполовину и не выбрасывает молча то, что не может отправить. |
| `conformance-kit-published` | обязательно | С каждой версией порта владелец компонента издаёт набор проверок: образцы данных, намерения, которые поднимает компонент, и ожидаемые ответы хоста, включая конфликт, отказ и запрет. |
| `kit-is-transport-neutral` | обязательно | Набор проверок описывает данные, намерения и ответы, а не адреса и форматы передачи, поэтому его может пройти хост на любом языке и на любом транспорте. |
| `host-claim-backed-by-kit` | обязательно | Хост заявляет поддержку версии порта только после прохождения её набора проверок и записывает версию набора, ревизию хоста и результат. |
| `reference-host-tested` | следует | Владелец компонента проверяет каждый релиз на эталонном хосте, который проходит набор, чтобы поломка стыка находилась у владельца, а не у продукта. |
| `port-owned-by-component-owner` | обязательно | Порт принадлежит владельцу компонента. Продукт просит об изменении, но не ответвляет и не расширяет порт у себя. |
| `product-rules-in-profiles` | обязательно | Правила конкретного продукта — хранилище, модель прав, типы полей — живут в профиле продукта поверх порта, а не в самом порте. |
| `change-recorded-with-recheck` | обязательно | Каждая версия порта записывает, что изменилось и что хосту перепроверить, в форме жизненного цикла Standard Contract, чтобы продукт по одной записи понял, касается ли его обновление. |
| `pinned-by-exact-release` | следует | Продукт закрепляет компонент и порт точным изданным релизом и обновляется осознанно. Изданный релиз не меняется на месте. |

## На чём стандарт стоит

- динамический композитный компонент 1.0.2 — наследуется целиком, закреплён по
  точным байтам;
- манифест Smart-компонента 2.1.0 — место, где объявляется сам порт.

## Машиночитаемая часть

[Конверт `simai.composite-host-port` 1.0.2](/ai/standards/simai.composite-host-port/1.0.2/standard.json)
в формате `standard-contract` 1.0. Источник:
`ui-source:contracts/standards/simai.composite-host-port/1.0.2/standard.json`.

## Как проверяется

Проверка ручная: владелец компонента показывает объявленный порт, изданный
набор проверок и результат эталонного хоста. Черновик подготовила команда
Larena на стыке представления данных; требования про права вместе с данными и
про эхо запроса добавлены при издании.
