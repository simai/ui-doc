# Свои блоки: как сделать свой блок

Блок — то, что автор вставляет на страницу в редакторе страниц: «Заголовок»,
«Карточка», «Колонки», «Таблица». Набор блоков SIMAI Framework можно дополнить своими;
свой блок появляется в каталоге редактора рядом со встроенными, со своими
вариантами, параметрами и данными. Эта страница — для разработчика, который
такой блок делает.

Здесь **блок** — собственный тип узла Composition, сделанный по набору автора
блока. Он стоит в странице (профиль `structured-content`) или в макете
(профиль `ui-layout`) рядом с типами SIMAI Framework, его рисует тот же
`SF.Composition.render`, и правят те же редакторы. Не путайте его с блоком —
шаблоном Recipe ([Блок](/ru/guide/layouts/building/block/)): тот собирается из
готовых узлов и своего манифеста не имеет.

Своего формата у блока нет. Он состоит из того, что в SIMAI Framework уже
есть:

- **манифест типа** (`simai.composition.type-manifest`, версия схемы 1): имя,
  данные, параметры, слоты, рендерер и ресурсы ([Манифест типа](/ru/guide/layouts/reference/type-manifest/));
- **манифест редактора** (`simai.composition.editor-manifest`, версия схемы
  1): поля формы параметров;
- **рендерер**, который регистрирует хост: функция, превращающая узел в HTML;
- **контрольные примеры** (`simai.composition.structured-content-conformance-case`,
  версия схемы 1): документы с блоком и то, что они рисуют.

Набор лежит в репозитории SIMAI Framework, в папке
[`kits/block/`](https://github.com/simai/ui-source/tree/4863a40e221cba7684cd0c7d860b286613d3e8c4/kits/block):
шаблон, с которого начинают, генератор и проверка, которую разработчик
запускает на своём блоке. Набор вышел в паре `ui-8e1a016a28a0`; эти
инструменты лежат вне исходников SIMAI Framework (`src/`), в поставку не
собираются и версий модулей не меняют.

Примеры блоков, сделанных только средствами набора, — `sample.quote`
(цитата с автором) и `sample.cards` (блок с данными: место в каталоге,
варианты, параметры раскладки, именованное место и привязка к хосту). Они
лежат в `src/core/kits/block/` и с выпуска `ui-c3015f76bcc2` входят в
поставку целиком: `distr/core/kits/block/sample-quote/` и
`distr/core/kits/block/sample-cards/` в пакете `@simai-studio/ui`. Хост может
загрузить их с CDN, например
`https://cdn.jsdelivr.net/npm/@simai-studio/ui@5.20261108.2127/distr/core/kits/block/sample-quote/type.json`.

## Быстрый старт

```bash
node kits/block/new.mjs acme.price-card ../acme-blocks/price-card
node kits/block/check.mjs ../acme-blocks/price-card --update
node kits/block/check.mjs ../acme-blocks/price-card
```

Первая команда создаёт блок из шаблона. Затем меняют `type.json`,
`editor.json`, `words.json`, `renderer.mjs`, `style.css` и `cases/`. Вторая
записывает в контрольные примеры то, что блок рисует сейчас: после неё читают
разницу. Третья проверяет блок.

По умолчанию проверка работает с `src/` той же копии репозитория. Флаг
`--framework <папка>` запускает её на другой сборке SIMAI Framework, например
на выпущенной поставке (`--framework ../ui/distr`). Флаг `--json` печатает
отчёт в JSON.

## Файлы блока

| Файл | Формат | Что в нём |
|:---|:---|:---|
| `type.json` | `simai.composition.type-manifest` v1 | имя, версия, категория, режим, профили, `data_schema`, `props_schema`, слоты, рендерер, ресурсы |
| `editor.json` | `simai.composition.editor-manifest` v1 | по полю на каждый параметр |
| `words.json` | `simai.composition.editor-words` v1 | подписи полей по языкам |
| `renderer.mjs` | модуль ES | `export default ({node, slots, locale}) => html` |
| `style.css` | CSS | собственная таблица стилей блока, один из его ресурсов |
| `cases/*.json` | `simai.composition.structured-content-conformance-case` v1 | документ и то, что он рисует |

## Пространства имён

Имя типа — два или больше сегментов в нижнем регистре: `<владелец>.<имя>`.
Первый сегмент говорит, чей это тип:

- `content.*` — типы содержимого SIMAI Framework ([Типы содержимого](/ru/guide/layouts/content-and-data/content-types/));
- `layout.*` — типы макета SIMAI Framework;
- `smart.*` — смарт-компоненты SIMAI Framework в Composition;
- `<продукт>.*` — всё остальное, по имени продукта-владельца:
  `acme.price-card`, `sample.quote`.

Блок никогда не берёт пространство имён SIMAI Framework и имя типа, который
в SIMAI Framework уже есть: проверка отклоняет и то и другое
(`type_namespace_reserved`, `type_taken`). Пространство имён говорит, кто
владеет именем, а не где блок стоит. Где он стоит, говорят `category`
(`content`, `layout`) и `profiles`. Блок содержимого — это
`category: "content"`, его принимает любой слот содержимого, а в `profiles`
он перечисляет `structured-content` (и `ui-layout`, если может стоять и в
макете).

## Данные, параметры и форма

Узел — это вызов: `data` — его содержимое, `props` — параметры.

```json
{"id": "q", "type": "sample.quote", "data": {"author": "Ada Lovelace"}, "props": {"align": "center"},
 "slots": {"default": [{"id": "q1", "type": "content.paragraph", "data": {"content": [{"type": "text", "value": "..."}]}}]}}
```

`data_schema` и `props_schema` — закрытые объекты (`type: "object"`,
`additionalProperties: false`). Валидатор Composition читает только эти
ключевые слова: `type`, `const`, `enum`, `oneOf`, `minLength`, `maxLength`,
`pattern`, `minimum`, `maximum`, `minItems`, `maxItems`, `uniqueItems`,
`items`, `required`, `properties`, `additionalProperties: false` (и `title`,
`description`, `default` как пояснения). Любое другое (`format`, `$ref`,
`anyOf`) он молча пропустил бы, и документ, который автор хотел отклонить,
прошёл бы проверку. Поэтому проверка набора такие слова отклоняет
(`schema_keyword_unsupported`). Ключ, который формат документа запрещает
везде (`html`, `script`, `class`, `token`, `password` и другие), не может быть
и ключом блока (`schema_key_forbidden`).

Параметр, равный значению по умолчанию, не записывается. Значение по
умолчанию живёт в поле манифеста редактора, и рендерер рисует то же значение,
когда ключа нет.

### Манифест редактора

У каждого параметра и у каждого скалярного ключа данных, без которого узел не
обходится, есть поле. Тогда форма, построенная по одному манифесту
редактора, может создать полный блок (иначе — `form_required_field_missing`).

```json
{"key": "align", "plane": "props", "target": "align", "property": {"type": "string", "version": 2},
 "constraints": {"min_length": 1, "max_length": 16}, "group": "basic", "visibility": "visible",
 "choices": ["start", "center"], "default": "start",
 "label_key": "sample.quote.align", "help_key": "sample.quote.align_help",
 "capability_hints": ["composition.props.align"], "permission_hints": ["composition.node.update"], "owner": "sample/quote"}
```

`type_version` привязывает список полей к одной точной версии типа.
Идентичность свойства (`property`) и наличие `choices` выбирают один из
опубликованных видов поля:

| Вид | `property` | `choices` | Что рисует |
|:---|:---|:---|:---|
| выбор | `string` 1 или 2 | обязательны | список выбора |
| целое число | `integer` 1 | нет; нужны `min` и `max` | поле числа |
| текст | `string` 2 | нет; нужен `max_length` (до 2000) | текстовое поле |
| переключатель | `boolean` 1 | нет | переключатель; `false` не записывается |

`owner` — собственный владелец блока (`<продукт>/<имя>`); встроенными полями
владеет `simai/framework` (иначе — `editor_owner_foreign`). Подписи — это
слова, а не текст в манифесте: `words.json` даёт для каждого языка
`label_key`, `help_key` и `<label_key>.<choice>` для каждого варианта выбора,
а хост регистрирует их так же, как слова любого компонента:

```js
SF.language.register('sample.quote', 'ru', words.words.ru);
```

Проверка строит форму для каждого узла блока из контрольных примеров
(`projectEditorFields`, затем `renderFieldFallback` для каждого поля) и
подставляет в документ каждое значение, которое форма предлагает: каждый
вариант выбора, оба положения переключателя, наименьшее и наибольшее целое.
После каждой подстановки документ должен остаться действительным
(`form_value_breaks_document`). Так ловится вариант выбора, который схема
типа не разрешает.

## Регистрация рендерера

`renderer: {"kind": "registered", "name": "sample.quote"}` означает, что
рисование даёт хост. Хост добавляет тип к встроенным и регистрирует функцию
под этим именем:

```js
import type from './sample-quote/type.json' with {type: 'json'};
import drawQuote from './sample-quote/renderer.mjs';

const registry = SF.Composition.extendRegistry([type], {[type.renderer.name]: drawQuote});
const {html, assets, diagnostics} = await SF.Composition.render(document, {registry});
```

`extendRegistry` сохраняет типы SIMAI Framework, а `createRegistry(list)`
берёт список как весь реестр ([Собственный тип](/ru/guide/layouts/reference/custom-type/)).
Тот же вызов работает и на сервере: рендерер — обычный модуль, а среда
Composition работает в Node (`core/js/composition/index.mjs` выпущенной
поставки).

Рендерер получает `{node, slots, locale, context, manifest, resolvedBindings}`
и возвращает строку (или промис строки):

- `node` — узел, как его хранит документ, уже проверенный. Его только
  читают и никогда не меняют: проверка следит за каждым вызовом
  (`renderer_mutates_node`).
- `slots.<имя>` — HTML дочерних узлов слота, нарисованных их собственными
  рендерерами; `slots.<имя>List` — то же по строке на каждый дочерний узел.
  Каждый слот, объявленный в типе, должен попасть в HTML
  (`renderer_slot_dropped`).
- `locale` — язык документа (`en`, если язык не указан).
- Внешний элемент несёт `data-sf-composition-id="<id узла>"`, ровно один раз
  (`renderer_node_id_missing`): по нему редакторы макета, редактор текста и
  перетаскивание находят узел на нарисованной странице.

Тип, который нигде не зарегистрирован, на своём месте ничего не рисует, а
`render` сообщает `renderer_unavailable` в `node:<id>`. Проверка начинает с
этого, поэтому имя, на которое уже отвечает рендерер SIMAI Framework,
ловится сразу (`renderer_name_taken`). Блок-веб-компонент объявляют как
`"kind": "custom-element"`, а в `name` пишут тег элемента: он рисуется этим
элементом с параметрами в атрибутах и попадает в список `hydration`
результата `render`; скрипт элемента хост подключает как ресурс.

## Слоты и встроенная разметка текста

Слот объявляют с границами и с тем, что он принимает
([Слоты и порядок](/ru/guide/layouts/building/slots/)):

```json
"slots": {"default": {"min": 1, "max": 20, "types": ["content.paragraph"]}}
```

`types` перечисляет типы, которые слот берёт; `categories` (`content`,
`layout`, `smart`) берёт категорию целиком. Дочерний узел вне них
отклоняется (`slot_child_type_forbidden`, `slot_child_category_forbidden`),
как и число узлов вне `min` и `max` (`slot_cardinality`). Блок-лист слотов
не объявляет.

Тексту с выделениями и ссылками место в слоте из `content.paragraph` (или
других типов содержимого), а не в собственных данных блока. Там его держит
встроенная модель текста SIMAI Framework: фрагменты текста с `strong`, `em` и
`code`, ссылки на фрагментах, встроенные компоненты
([Структурированный текст](/ru/guide/layouts/content-and-data/structured-text/)).
К каждой ссылке применяется правило адресов документа, рендерер абзаца её
экранирует, а редакторы правят текст на месте, каждый абзац по его
`data-sf-composition-id`. Так пример `sample.quote` хранит слова цитаты, а
автора — в простых данных.

Блок, которому нужно держать встроенный текст в собственных данных, может
взять схему встроенного текста `content.paragraph`
(`BUILTIN_TYPE_MANIFESTS.find(({type}) => type === 'content.paragraph').data_schema.properties.content`).
Но валидатор применяет правило адресов к типам SIMAI Framework по их именам:
данные типа продукта — и ссылки, и адреса — проверяет его собственный
рендерер. Проверка набора подставляет ссылку на `javascript:` в каждое поле
встроенного текста и в каждое текстовое поле, которое пропускают схемы, и
отклоняет вывод, который её рисует.

## Ресурсы и безопасный предпросмотр

`assets` называет то, что нужно нарисованному блоку кроме HTML. Часть SIMAI
Framework называют так же, как её называют встроенные типы
(`component/alerts`, `utility/table-frame`); собственную таблицу стилей
блока — в его пространстве имён (`sample/quote`). `render` возвращает набор
ресурсов для всего документа, и хост подключает каждый из списка: страница
без цитаты не загружает стили цитаты. Таблица стилей блока читает публичные
переменные SIMAI Framework (`--sf-primary`, `--sf-on-surface`,
`--sf-space-*`), поэтому следует теме и тёмному режиму.

HTML рендерера — это и предпросмотр блока в редакторе, и содержимое страницы
читателя, поэтому он безопасен сам по себе:

- каждое значение экранировано (`& < > " '`);
- каждый адрес проверен правилом адресов документа (относительный,
  фрагмент, `http:`, `https:`, `mailto:`, `tel:`);
- нет элементов `script`, `style`, `iframe`, `object`, `embed`, `form`,
  `base`, `meta`, `link` и `template`, нет атрибутов `on*`, нет `style`,
  который что-то загружает или выполняет.

Поведение (карусель, счётчик) — это пользовательский элемент, который хост
подключает как ресурс, а не скрипт в HTML. Проверка читает вывод каждого
контрольного примера и вывод при враждебных значениях, подставленных в
каждое текстовое, адресное и встроенное поле (`output_element_forbidden`,
`output_event_handler`, `output_unsafe_url`, `output_unsafe_style`).

## Версии

`version` в `type.json` — версия блока, и `type_version` в `editor.json`
называет ту же версию точно (иначе — `editor_type_registration_mismatch`).
Документ называет тип, а не его версию: каждый документ, сохранённый с
блоком, должен оставаться действительным и рисоваться так же при каждой
следующей версии под этим именем. Поэтому версия меняется так же, как у
комплекта проверки соответствия ([Версии и отпечатки](/ru/guide/layouts/reference/versions/)):

- **patch** — исправление рендерера, которое сохраняет HTML всех контрольных
  примеров, новый контрольный пример, исправленные слова;
- **minor** — добавлен необязательный ключ данных или параметр, добавлен
  вариант выбора, поднят `max` слота; все прежние контрольные примеры
  проходят без изменений;
- **major** — всё, что отклоняет или перерисовывает сохранённый документ:
  ключ удалён или переименован, новый обязательный ключ, удалён вариант
  выбора, изменился HTML существующего примера. Под тем же именем это
  требует, чтобы хост сначала перенёс свои документы; иначе это новое имя
  типа, а старое остаётся зарегистрированным, пока документы его содержат.

Расхождение проверка показывает как `case_html_mismatch`: либо ошибся
рендерер, либо изменение задумано — тогда примеры переписывают с
`--update` и поднимают версию.

## Неизвестный тип остаётся непрозрачным

Хост, который не знает тип, никогда его не угадывает:

- `validate` сообщает `type_unknown` в этом узле, документ недействителен, и
  `render` не рисует ничего: страница никогда не рисуется наполовину;
- редактор содержимого `sf-editor-content` ([Редактор содержимого](/ru/pro/editor/content-editor/))
  показывает неизвестный узел заглушкой с именем типа, сохраняет его данные и
  слоты байт в байт и только перемещает или удаляет его целиком; редактор
  текста так же поступает с незнакомым встроенным элементом;
- ничего не пропадает молча: хост узнаёт о неизвестном типе при проверке, а
  не потеряв его.

Поэтому документ с блоком переживает хост без этого блока и при сохранении
там возвращается без изменений. Проверка требует этого от среды выполнения:
хост без блока отклоняет документ примера целиком (`unknown_not_refused`,
`unknown_drawn`), неизвестный блоку тип внутри его слота отклоняется так же и
сохраняется как пришёл (`unknown_child_accepted`, `unknown_child_drawn`,
`unknown_child_changed`), а рендерер оставляет каждый узел байт в байт
(`renderer_mutates_node`).

## Шаблон и генератор

`node kits/block/new.mjs <продукт>.<имя> <папка>` копирует шаблон
`kits/block/template/` (блок `product.block-name`) в новую папку и заменяет
имя шаблона именем блока во всех формах, в которых его пишут файлы: имя типа
и рендерера, ключи подписей, владелец полей и имя ресурса
(`<продукт>/<имя>`), имена классов. Имя пространства SIMAI Framework
генератор не принимает (`block_namespace_reserved`), непустую папку не
перезаписывает (`block_folder_not_empty`). Дальше остаётся изменить схемы, поля, слова и HTML, написать
контрольные примеры и запускать проверку, пока она не пройдёт.

## Проверка

`node kits/block/check.mjs <папка блока>` запускает пять групп на
собственной среде Composition SIMAI Framework:

| Группа | Что проверяет |
|:---|:---|
| `manifest` | `type.json` по опубликованной схеме, пространство имён, закрытые схемы с ключевыми словами валидатора, `editor.json` через `validateEditorManifest` и виды полей |
| `renderer` | `renderer.mjs` экспортирует функцию; без регистрации тип ничего не рисует, после регистрации рисует блок с его `id` и слотами |
| `form` | у каждого обязательного скаляра есть поле, форма строится для каждого узла из примеров, каждое предложенное значение оставляет документ действительным, слова |
| `output` | каждый контрольный пример по правилу комплекта соответствия: `valid`, HTML, диагностика, ресурсы; каждый вывод и каждое враждебное значение нарисованы безопасно |
| `unknown` | правило непрозрачности выше |

Группа, которая не может выполниться, так и говорит (`SKIP` с причиной), и
блок не проходит. Предупреждение (`WARN`) называет то, что стоит добавить:
параметр без поля, вариант выбора, который не рисует ни один пример,
недостающее слово, отсутствие примера, который блок отклоняет.

```text
SIMAI Framework block check: sample.quote 1.1.0 (src/core/kits/block/sample-quote)
  PASS  manifest  the type and editor manifests are valid
  PASS  renderer  the renderer is registered and draws the block
  PASS  form      the parameter form builds from the editor manifest
  PASS  output    JSON to HTML gives the expected output, and the output is safe
  PASS  unknown   an unknown type stays safe, the block is kept byte for byte
BLOCK_CHECK_PASS sample.quote@1.1.0 groups=5 cases=7 warnings=0
```

Код выхода — 0, если блок прошёл, 1 — если не прошёл, 2 — если проверка не
смогла выполниться. Тесты набора (`tests/block-author-kit.test.mjs`)
запускают проверку на примере, на шаблоне и на испорченных копиях примера.
