# Подтверждение изменения

:badge[sf-confirm-change]{variant=tonal scheme=primary size=1/2} :badge[1.4.0]{variant=outline scheme=on-surface size=1/2}

`<sf-confirm-change>` — карточка подготовленного изменения, которое ждёт
«да» или «нет» человека: каждое значение как было и как станет, два
равноценных ответа, срок, до которого можно ответить, а после ответа —
только итог. Так спрашивают о предложении ассистента, правке коллеги,
импорте перед записью. Карточка ничего не применяет: нажатие — это событие.

**Теперь в SIMAI Framework.** С выпуска `ui-c3015f76bcc2` карточка входит в
выпуск SIMAI Framework под тегом `<sf-confirm-change>`, а пакет `pro` её
больше не поставляет. Прежний тег `<sf-confirm-change>` работает до
2027-01-01. Рядом с ней в Framework — `<sf-confirm>`: тот же вопрос без
«было и станет», например удаление, о котором спрашивают в строке; оба
описаны в справочнике ниже.

## Разметка

- `heading` называет изменение (без него — «Что изменится»),
  `heading-level` — уровень заголовка там, где стоит карточка.
- `changes` — список `{label, before, after}`: в атрибуте — JSON, в
  свойстве — массив; свойство важнее. Значение — текст; пустое читается как
  «пусто».
- `change-id` — имя изменения у приложения; оно возвращается в каждом
  событии.
- Слот `description` — строка под заголовком: код, кто предложил.

## Варианты

### Без значений

Изменение, у которого нечего показать «было — стало», например удаление, —
это заголовок и ответы. `accept-text` и `decline-text` меняют слова
ответов.

:::example {id="smart-components/change-confirm/no-values" label="Удаление: заголовок и два ответа"}
:::

## Состояния

### Ответ отправляется и недоступно

Нажатие переводит карточку в `pending`: ответы пропадают, чтобы ничего не
нажали дважды, а строка состояния говорит, что происходит. `disabled`
показывает ответы, но не даёт их нажать — например, пока идёт другая
отправка.

:::example {id="smart-components/change-confirm/state-pending" label="Ответ отправляется; ответы недоступны"}
:::

### Итог

После ответа приложение ставит `state`: `accepted` — подтверждено,
`declined` — отклонено. Если ответ доставить не удалось, верните `open`.
После `expires-at` открытая карточка читается как `expired` и один раз
отправляет `sf-confirm-change-expired`.

:::example {id="smart-components/change-confirm/state-outcome" label="Подтверждено, отклонено и истёк срок"}
:::

## Применение

### Ответ и события

Ответ человека приходит событием `sf-confirm-change-answer` с
`{id, accepted}`: `id` — значение `change-id`, `accepted` — `true` для «да» и
`false` для «нет». Приложение применяет или отклоняет изменение и ставит
итог. Если отменить событие (`preventDefault()`), вопрос остаётся открытым.
`answer({accepted: true})` и `answer({accepted: false})` отвечают из кода, как
человек. Прежние имена `sf-change-confirm-accept`, `-decline` и `-expire` и
вызов `answer('accept')` работают до 2026-12-01, имена
`sf-change-confirm-answer` и `sf-change-confirm-expired` — до 2027-01-01, как
и прежний тег.

```js
const card = document.querySelector('sf-confirm-change');
card.addEventListener('sf-confirm-change-answer', async (event) => {
  const {id, accepted} = event.detail;
  try {
    await (accepted ? api.apply(id) : api.reject(id));
    card.state = accepted ? 'accepted' : 'declined';
  } catch {
    card.state = 'open';
  }
});
```

## Доступность

- Карточка — раздел, названный заголовком; значения — список описаний,
  который читается как «Название: было Новости, станет События».
- Два ответа — настоящие кнопки (`Tab`, `Enter`, `Space`).
- Строка состояния — вежливая живая область. Когда нажатие убирает ответы,
  фокус переходит на неё, а если приложение отменило событие — обратно на
  первый ответ.

### Атрибуты

- `template` — `string`, по умолчанию `default`, значения: `default`. Имя шаблона отрисовки; `default` — встроенный.
- `root-class` — `string`, по умолчанию пусто. Свои CSS-классы для нарисованного элемента.
- `root-style` — `string`, по умолчанию пусто. Свои стили для нарисованного элемента, например `max-width: 20rem`.
- `heading` — `string`, по умолчанию пусто. Что это за изменение; без него карточка называется «Что изменится».
- `heading-level` — `string`, по умолчанию `3`, значения: `2`, `3`, `4`, `5`, `6`. Уровень заголовка там, где стоит карточка.
- `state` — `string`, по умолчанию `open`, значения: `open`, `pending`, `accepted`, `declined`, `expired`. Состояние вопроса: `open` — ответы можно нажать; `pending` — ответ отправляется (ставится нажатием); `accepted`, `declined`, `expired` — виден только итог.
- `expires-at` — `string`, по умолчанию пусто. ISO 8601. После этого момента открытая карточка считается просроченной и один раз сообщает об этом через sf-change-confirm-expired.
- `change-id` — `string`, по умолчанию пусто. Имя изменения у приложения; возвращается в каждом событии.
- `disabled` — `boolean`, по умолчанию `false`. Ответы видны, но нажать их нельзя, например пока отправляется другой ответ.
- `accept-text` — `string`. Подпись кнопки согласия; пусто — «Подтвердить» на языке страницы.
- `decline-text` — `string`. Слова ответа «нет»; пусто — «Отклонить» на языке страницы.
- `changes` — `array` из `object`, по умолчанию `[]`. Значения в JSON для разметки; свойство, заданное из скрипта, важнее.

### Методы

- `open()` — возвращает `object`. Задаёт вопрос снова: ответы опять можно нажать. Когда вопрос задаёт сборка, она получает ответ `{accepted, reason, value}`, как только человек ответит или выйдет срок.
- `answer(accepted: boolean)` — возвращает `object`. Ответить, как ответил бы человек: `accepted` true подтверждает, false отклоняет. Отказ, если карточка закрыта, выключена или ответ отменён.
- `confirm()` — возвращает `object`. Отвечает «да», как нажатие кнопки согласия; с разметки — `data-sf-action="<id>.confirm"`.
- `cancel()` — возвращает `object`. Кнопка отказа.

### События

Все события приходят на сам элемент и всплывают. Что означает глагол в имени события, говорит общий словарь: [Имена и общие слова](/ru/guide/smart-components/names/). Общие события базового элемента перечислены в главе [Модель компонента → Базовый интерфейс](/ru/guide/smart-components/model/#базовый-интерфейс).

- `sf-confirm-change-answer` — `detail`: `{ id: any, accepted: boolean }`. Человек ответил. Отмените событие, чтобы вопрос остался открытым.
- `sf-confirm-change-expired` — `detail`: `{ id: any }`. Открытая карточка прошла `expires-at`; сообщается один раз на каждое время.

### Доступность

- Роль: область (`region`).
- Доступное имя: внутренний.
- Клавиши: `Tab`, `Enter`, `Space`.
- Фокус: Раздел, названный заголовком (role=heading уровня heading-level). Значения — список описаний. Строка состояния — вежливая живая область, которая есть на странице до того, как заговорит; когда нажатие убирает ответы, фокус переходит на неё, а не падает на страницу, и возвращается на первый ответ, если приложение отменило событие.

### Минимальная разметка

```html
<sf-confirm-change heading="Переименовать раздел" change-id="c1" changes='[{"label":"Название","before":"Новости","after":"События"}]'></sf-confirm-change>
```
