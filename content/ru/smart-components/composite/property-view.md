# Представление свойств

:badge[smart.property-view]{type=main scheme=on-surface size=1} :badge[experimental]{type=tonal scheme=warning size=1}

`<sf-property-view>` — карточка одного объекта. Поля сгруппированы в области,
области собраны в разделы, каждое поле рисуется набором отрисовщиков по своему
типу. Область правится и сохраняется целиком одной ревизией.

Это пара к [представлению данных](/ru/smart-components/content/table/): то
показывает множество записей, это — один объект.

Компонент не владеет данными. Он поднимает намерение, а запись, права и
проверку значений держит приложение через host port.

Пример сам отвечает на намерения: `record.load` отдаёт запись, `group.save`
принимает изменённые поля и возвращает следующую ревизию. Нажмите карандаш у
области, измените значение и сохраните — панель выйдет из правки только после
ответа хоста.

## Минимальное подключение

```html
<sf-property-view
  record-id="record-00829e9f"
  aria-label="Карточка решения">
</sf-property-view>
```

Запись не передаётся разметкой: компонент спрашивает её у host port сразу после
подключения.

## Host port

```js
panel.setHostPort({
  version: '1.7.0',
  capabilities: ['field-options', 'field-upload', 'view-settings'],
  async raise(intent, payload) { /* … */ },
});
```

`capabilities` — это то, что приложение умеет, а не то, что компонент показывает
на всякий случай. Управление, под которое хост не заявил возможность, панель не
рисует.

### Намерения

| Намерение | Когда поднимается | Что должен вернуть хост |
|:---|:---|:---|
| `record.load` | при подключении и по запросу обновления | `{answer: 'applied', record}` |
| `group.save` | по нажатию сохранения в области | запись следующей ревизии |
| `field.options` | когда поле-ссылка открывает список кандидатов | страницу вариантов |
| `record.open` | по переходу на связанную запись | `{answer: 'applied'}` |
| `record.delete` | по удалению записи | решение принимает хост, подтверждение — его |
| `view.save`, `view.reset` | при настройке вида | ревизию вида |

Ответ `conflict` возвращает панель в правку с сообщением; `refused` с картой
`errors` ставит ошибки у конкретных полей; `unavailable` показывает состояние
недоступности вместо карточки.

### Что несёт `group.save`

```js
{
  record_id: 'record-00829e9f',
  collection: 'docs.demo_solutions',
  section: 'main',
  group: 'main',
  values: { title: 'Новое название' },
  revision: 4
}
```

Отправляются только изменённые поля и ревизия, прочитанная при загрузке.
Сравнивает ревизии хост — он один знает, что произошло с записью между чтением
и записью.

## Структура записи

```js
{
  record_id: 'record-00829e9f',
  collection: 'docs.demo_solutions',
  revision: 4,
  sections: [
    { key: 'main', label: 'Общее', groups: [
      { key: 'main', label: 'Основное', columns: 2, fields: [
        { key: 'title', label: 'Название', propertyType: 'string', value: '…', width: 'half', required: true },
      ] },
    ] },
  ],
}
```

Поле занимает половину или всю ширину области (`width`), область раскладывается
в одну или две колонки (`columns`). Редкие поля (`rare`) скрыты до запроса,
скрытые (`hidden`) не рисуются вовсе.

## Раскладка

Выше брейкпоинта ящика разделы стоят колонкой слева от полей. Ниже — раздел
открывается отдельным экраном, и появляется возврат к списку разделов.

Шапка и подвал панели закреплены: прокручиваются только колонки с разделами и
полями, каждая со своим внутренним отступом.

## События

| Событие | Когда |
|:---|:---|
| `sf-property-view-state` | смена состояния: загрузка, готово, правка, ошибка |
| `sf-property-view-close` | закрытие панели |
| `sf-property-view-open-record` | переход на связанную запись |
| `sf-property-view-open-full` | открытие записи на отдельной странице |
| `sf-property-view-address-copy` | копирование ссылки на запись |
| `sf-property-view-delete-record` | запрос удаления |
| `sf-property-view-favourite` | отметка записи |
