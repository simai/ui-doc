# Подтверждение изменения

`<sf-change-confirm>` — карточка подготовленного изменения, которое ждёт
«да» или «нет» человека: каждое значение как было и как станет, два
равноценных ответа, срок, до которого можно ответить, а после ответа —
только итог. Так спрашивают о предложении ассистента, правке коллеги,
импорте перед записью. Карточка ничего не применяет: нажатие — это событие.

Компонент поставляется пакетом `larena` из репозитория `simai/ui-pro`
(SIMAI Pro, папка `components/`), а не выпуском Framework. Лицензия пакета —
PolyForm Small Business 1.0.0 или PolyForm Noncommercial 1.0.0, по запросу —
коммерческая лицензия SIMAI; в составе Larena — лицензия Larena. Как
подключить пакет — в разделе
[Подключение Smart-компонентов](/ru/guide/smart-components/page/#подключение-к-странице).

## Разметка

- `heading` называет изменение (без него — «Что изменится»),
  `heading-level` — уровень заголовка там, где стоит карточка.
- `changes` — список `{label, before, after}`: в атрибуте — JSON, в
  свойстве — массив; свойство важнее. Значение — текст; пустое читается как
  «пусто».
- `change-id` — имя изменения у приложения; оно возвращается в каждом
  событии.
- Слот `description` — строка под заголовком: код, кто предложил.

## Варианты

### Без значений

Изменение, у которого нечего показать «было — стало», например удаление, —
это заголовок и ответы. `accept-text` и `decline-text` меняют слова
ответов.

:::example {id="smart-components/change-confirm/no-values" label="Удаление: заголовок и два ответа"}
:::

## Состояния

### Ответ отправляется и недоступно

Нажатие переводит карточку в `pending`: ответы пропадают, чтобы ничего не
нажали дважды, а строка состояния говорит, что происходит. `disabled`
показывает ответы, но не даёт их нажать — например, пока идёт другая
отправка.

:::example {id="smart-components/change-confirm/state-pending" label="Ответ отправляется; ответы недоступны"}
:::

### Итог

После ответа приложение ставит `state`: `accepted` — подтверждено,
`declined` — отклонено. Если ответ доставить не удалось, верните `open`.
После `expires-at` открытая карточка читается как `expired` и один раз
отправляет `sf-change-confirm-expire`.

:::example {id="smart-components/change-confirm/state-outcome" label="Подтверждено, отклонено и истёк срок"}
:::

## Применение

### Ответ и события

`sf-change-confirm-accept` и `sf-change-confirm-decline` приходят с `id` —
значением `change-id`. Приложение применяет или отклоняет изменение и ставит
итог. Если отменить событие (`preventDefault()`), вопрос остаётся открытым.
`answer('accept')` и `answer('decline')` отвечают из кода, как человек.

```js
const card = document.querySelector('sf-change-confirm');
card.addEventListener('sf-change-confirm-accept', async (event) => {
  try {
    await api.apply(event.detail.id);
    card.state = 'accepted';
  } catch {
    card.state = 'open';
  }
});
```

## Доступность

- Карточка — раздел, названный заголовком; значения — список описаний,
  который читается как «Название: было Новости, станет События».
- Два ответа — настоящие кнопки (`Tab`, `Enter`, `Space`).
- Строка состояния — вежливая живая область. Когда нажатие убирает ответы,
  фокус переходит на неё, а если приложение отменило событие — обратно на
  первый ответ.

### Атрибуты

- `template` — `string`, по умолчанию `default`, значения: `default`.
- `heading` — `string`, по умолчанию пусто. Что это за изменение; без него карточка называется «Что изменится».
- `heading-level` — —, по умолчанию `3`, значения: `2`, `3`, `4`, `5`, `6`. Уровень заголовка там, где стоит карточка.
- `state` — —, по умолчанию `open`, значения: `open`, `pending`, `accepted`, `declined`, `expired`. open: ответы предложены. pending: ответ отправляется (ставится нажатием). accepted, declined, expired: виден только итог.
- `expires-at` — `string`, по умолчанию пусто. ISO 8601. После этого времени открытая карточка читается как истёкшая и один раз сообщает об этом событием sf-change-confirm-expire.
- `change-id` — `string`, по умолчанию пусто. Имя изменения у хоста; возвращается в каждом событии.
- `disabled` — `boolean`, по умолчанию `false`. Ответы видны, но их нельзя нажать (где-то уже идёт отправка).
- `accept-text` — `string`, по умолчанию пусто. Слова ответа «да»; пусто — «Подтвердить» на языке страницы.
- `decline-text` — `string`, по умолчанию пусто. Слова ответа «нет»; пусто — «Отклонить» на языке страницы.
- `changes` — `array` из `object`, по умолчанию `[]`. Значения в JSON для разметки; свойство, заданное из скрипта, важнее.

### Методы

- `answer(accepted: boolean)` — возвращает `object`. Ответить, как ответил бы человек: `accepted` true подтверждает, false отклоняет. Отказ, если карточка закрыта, выключена или ответ отменён. `answer('accept')` и `answer('decline')` читаются до 2026-12-01.
- `confirm()` — возвращает `object`. Согласие; `data-sf-action="<id>.confirm"`.
- `cancel()` — возвращает `object`. Отказ; `data-sf-action="<id>.cancel"`.
- `open()` — возвращает `object`. Задаёт вопрос снова; если его попросила сборка, отвечает `{accepted, reason, value}`, когда человек ответил или время вышло.

### События

Все события приходят на сам элемент и всплывают. Что означает глагол в имени события, говорит общий словарь: [Имена и общие слова](/ru/guide/smart-components/names/). Общие события базового элемента перечислены в главе [Модель компонента → Базовый интерфейс](/ru/guide/smart-components/model/#базовый-интерфейс).

- `sf-change-confirm-answer` — `detail`: `{ id: string, accepted: boolean }`. Человек ответил (словарь answer). Отмените событие, чтобы вопрос остался открытым. Имена версии 1.0 `sf-change-confirm-accept` и `-decline` отправляются после него до 2026-12-01.
- `sf-change-confirm-expired` — `detail`: `{ id: string }`. Открытая карточка прошла `expires-at`; сообщается один раз на каждое время. Имя версии 1.0 `sf-change-confirm-expire` отправляется после него до 2026-12-01.

### Доступность

- Роль: область (`region`).
- Доступное имя: внутренний.
- Клавиши: `Tab`, `Enter`, `Space`.
- Фокус: Раздел, названный заголовком (role=heading уровня heading-level). Значения — список описаний. Строка состояния — вежливая живая область, которая есть на странице до того, как заговорит; когда нажатие убирает ответы, фокус переходит на неё, а не падает на страницу, и возвращается на первый ответ, если хост отменил событие.

### Минимальная разметка

```html
<sf-change-confirm heading="Переименовать раздел" change-id="c1" changes='[{"label":"Название","before":"Новости","after":"События"}]'></sf-change-confirm>
```
