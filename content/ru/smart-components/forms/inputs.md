# Поле ввода

:badge[smart.inputs]{type=main scheme=on-surface size=1} :badge[experimental]{type=tonal scheme=warning size=1}

`<sf-input>` собирает подпись, нативное поле, подсказку, ошибку и дополнительные элементы в один управляемый компонент. В прикладном коде задавайте данные через атрибуты и работайте с нативным элементом через `getInputElement()`.

## Основные параметры

| Атрибут | По умолчанию | Назначение |
|:---|:---|:---|
| `label` | пусто | Видимая подпись поля |
| `name` | пусто | Имя для формы и прикладной логики |
| `value` | пусто | Текущее значение |
| `default-value` | пусто | Начальное значение |
| `placeholder` | пусто | Краткий пример ожидаемого ввода |
| `hint` | пусто | Постоянная поясняющая подсказка |
| `icon-start` | пусто | Иконка у логического начала строки |
| `text-end` | пусто | Дополнительный текст у логического конца |
| `size` | `1` | Размер поля: `1/2`, `1`, `2` |
| `appearance` | `bordered` | Вид поля: `bordered`, `filled` или `hidden` |
| `required` | `false` | Обязательное поле |
| `disabled` | `false` | Недоступно для взаимодействия |
| `readonly` | `false` | Доступно для чтения без редактирования |
| `invalid` | `false` | Семантически невалидное значение |
| `error-message` | пусто | Сообщение, связанное с ошибкой |

Прежнее имя продолжает работать и считается устаревшим: `type` — как `appearance`. В новой разметке берите имена осей.

`left-icon` и `right-text` сохранены только как совместимые псевдонимы. В новом коде используйте `icon-start` и `text-end`.

## Имя, подпись и пояснение

Публичный вызов компонента не разделяется на отдельные Input и Form Field:
`<sf-input>` уже собирает нативный контроль и связанную с ним текстовую часть.

- `name` — машинное имя, которое используется при отправке формы и не
  показывается пользователю;
- `label` — основная видимая подпись и доступное имя поля;
- `placeholder` — пример формата внутри пустого поля, но не замена подписи;
- `hint` — постоянное пояснение под полем;
- `error-message` вместе с `invalid` — сообщение о причине ошибки и способе её
  исправления.

Внутренний нативный `<input>` находится в обычном DOM элемента и получает
`name`, поэтому `<sf-input>` внутри `<form>` участвует в обычной отправке формы
и в `FormData` без дополнительного кода. `required` переходит на нативное поле,
и браузер проверяет его перед отправкой.

```html
<sf-input
  name="search"
  label="Поиск"
  placeholder="Название или код"
  hint="Введите минимум два символа">
</sf-input>
```

В обычной форме сохраняйте `label` видимым. В компактной панели инструментов
композиция может визуально скрыть подпись, если она остаётся в дереве
доступности. Сам вызов при этом не меняется: отдельного сокращённого варианта
без подписи у компонента нет.

## Маска

Маска включается атрибутом `mask`. Её параметры задаются через `mask-pattern`, `mask-lazy`, `mask-placeholder-char` и `mask-options`. Маска помогает вводить значение, но не заменяет серверную проверку.

```html
<sf-input
  name="phone"
  label="Телефон"
  inputmode="tel"
  mask
  mask-pattern="+{7} (000) 000-00-00">
</sf-input>
```

## Публичный метод

`getInputElement()` возвращает внутренний нативный `<input>`. Используйте его, когда форме нужен стандартный DOM API — например, `focus()`, `checkValidity()` или `setCustomValidity()`.

## События

`input` приходит при каждом изменении значения во время ввода, `change` — когда значение зафиксировано. Оба — нативные события внутреннего поля, всплывают до `sf-input`. Для реакции на изменение значения подписывайтесь на `change`: это общее имя для всех полей значения.

## Доступность

Передавайте понятную подпись через `label`. Не заменяйте её одним `placeholder`: он исчезает после ввода. Состояния ошибки должны быть отражены через `invalid` и `error-message`, а видимый фокус сохраняется при клавиатурной навигации.

## Справочник API

- `appearance` — `string`, по умолчанию `bordered`, значения: `bordered`, `filled`, `hidden`. Вид поля: блок с рамкой, с заливкой или скрытый.
- `label` — `string`, по умолчанию пусто.
- `required` — `boolean`, по умолчанию `false`.

- `autocomplete` — `string`, по умолчанию пусто.
- `inputmode` — `string`, по умолчанию пусто, значения: пусто, `none`, `text`, `tel`, `url`, `email`, `numeric`, `decimal`, `search`.
- `minlength` — `string`, по умолчанию пусто.
- `maxlength` — `string`, по умолчанию пусто.
- `pattern` — `string`, по умолчанию пусто.
- `hint` — `string`, по умолчанию пусто.
- `value` — `string`, по умолчанию пусто.
- `default-value` — `string`, по умолчанию пусто.
- `name` — `string`, по умолчанию пусто.
- `icon-start` — `string`, по умолчанию `null`.
- `text-end` — `string`, по умолчанию `null`.

### Методы

- `getInputElement()`
- `onInput()`
- `onChange()`
- `onKeyUp()`
- `onKeyDown()`
- `onFocus()`
- `onBlur()`

### События

Все события приходят на сам элемент, всплывают и проходят границу Shadow DOM. Общие события базового элемента описаны в разделе [Загрузка и готовность](/ru/guide/smart-components/lifecycle/).

- `change` — `detail` не описан. Значение зафиксировано; нативное событие всплывает от внутреннего поля ввода, которое является его целью.
- `input` — `detail` не описан. Значение изменилось при вводе; нативное событие всплывает от внутреннего поля ввода, которое является его целью.

### Доступность

- Роль: текстовое поле (`textbox`).
- Доступное имя: обязательно.
- Клавиши: `Tab`, `native text editing`.
- Фокус: Сохраняет видимый фокус на активном элементе управления.

### Минимальная разметка

```html
<sf-input label="Email" input-type="email" name="email" autocomplete="email"></sf-input>
```
