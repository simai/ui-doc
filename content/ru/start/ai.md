# Работа с Framework при помощи ИИ

ИИ полезнее, когда опирается на реальную документацию и контракты установленной версии. Передавайте ему задачу и источники, а не только просьбу написать похожую разметку.

## Читать эту документацию

Передайте агенту адрес конкретной страницы утилиты или компонента. Для чтения нужен доступ агента к этому сайту. Локальный адрес `ui-doc.test` не становится доступным облачному клиенту автоматически.

```text
Используй указанную документацию SIMAI Framework и установленную в проекте версию.
Сначала найди подходящие готовые утилиты и компоненты.
Не выдумывай классы и параметры; проверяй их по источнику.
Не подключай полный пакет только для маскировки ошибки Loader.
Проверь пример, адаптивность и клавиатурное взаимодействие.
В ответе укажи источники, изменения и реально выполненные проверки.
```

## Использовать контракты UI Studio

UI Studio имеет отдельный MCP-сервер для каталога Smart-компонентов. Рабочий порядок: `smart.search` → `smart.describe` → `smart.validate` → `smart.test`. Доступные инструменты нужно подтвердить у подключённого сервера.

В этой локальной установке в документации Studio указан endpoint:

```text
https://ui-studio.test/mcp
```

Это адрес **UI Studio**, не MCP-сервер сайта `ui-doc.test`. Введите его в MCP-клиенте с поддержкой Streamable HTTP только если сервер запущен, адрес разрешается в окружении клиента и сертификат доверенный. Другие установки имеют собственные адреса.

Контракты, schemas, fixtures и scenarios дополняют статью: помогают проверить API и подобрать допустимую композицию. `apply` не следует вызывать автоматически ради чтения; операции записи требуют разрешения и корректного плана.

## Проверять совместимость

Сопоставляйте revision Framework в проекте, registry Studio и документацию. Наличие похожего компонента в более новом каталоге не означает, что он уже доступен в текущей поставке.

Утилиты и примеры проверяйте с настоящим Loader. При изменении дизайна сохраняйте токены и правила шаблона. Backend-права и предметные операции проверяются владельцем приложения, а не стилями и фронтенд-событиями.

## Что развивается дальше

Для Docara подготовлен проект автоматического экспорта знаний и отдельного read-only MCP-доступа к опубликованной документации. Это ещё не означает, что у этого сайта уже есть `llms.txt` или `/mcp`. Пока используйте доступные HTML-страницы и отдельно подключённые контракты Studio.
