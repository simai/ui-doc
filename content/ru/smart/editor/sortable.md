# Перетаскивание

:badge[sf-sortable]{variant=tonal scheme=primary size=1/2} :badge[1.2.1]{variant=outline scheme=on-surface size=1/2}

Перетаскивание даёт переставлять элементы списка, переносить их в другие
списки той же группы и копировать из библиотеки — мышью, пером, касанием и
клавиатурой. Компонент только сообщает, что человек хочет сделать; страницу и
данные меняет приложение.

## Разметка

Списку нужны группа, имя для объявлений и элементы с `id`:

```html
<sf-sortable id="todo" group="tasks" label="Нужно сделать">
  <div data-sf-sortable-item="brief"><span data-sf-sortable-handle aria-hidden="true">⠿</span>Собрать требования</div>
  <div data-sf-sortable-item="layout"><span data-sf-sortable-handle aria-hidden="true">⠿</span>Нарисовать макет</div>
</sf-sortable>
```

Элементы списка — потомки с `data-sf-sortable-item="<id>"`; `id` приходит в
событиях. Ручка `data-sf-sortable-handle` внутри элемента ограничивает
перетаскивание и служит целью касания; без ручки перетаскивается весь
элемент. Элементы, добавленные в список позже, становятся перетаскиваемыми
сами. Код компонента загрузчик SIMAI Framework подключает по требованию,
когда на странице появляется `sf-sortable`.

## Варианты

### Предпросмотр места

При перетаскивании указателем элемент по умолчанию поднимается из списка, а
на месте, куда он встанет, открывается контур его размера; соседние элементы
расступаются (`preview="silhouette"`). `preview="line"` вместо этого рисует
на месте вставки тонкую линию и оставляет список как есть. В списке, который
переносится в сетку (например, поля в две колонки), контур занимает одну
ячейку в порядке чтения. Перемещение с клавиатуры и внешние цели всегда
показывают линию.

:::example {id="smart-components/sortable/preview" label="Контур и линия на месте вставки"}
:::

### Ориентация

`orientation="horizontal"` говорит, что элементы стоят в строку: место
вставки при перетаскивании указателем считается по горизонтали. Раскладку
списка задают классы, а не этот атрибут.

:::example {id="smart-components/sortable/orientation" label="Метки в строку"}
:::

## Поведение

### Группы и библиотека

`group` — имя группы списка по шаблону `^[a-z][a-z0-9-]{0,31}$`. Элементы
переносятся между списками одной группы; `accepts` перечисляет через пробел
дополнительные группы, которые список принимает.

`mode="copy"` превращает список в библиотеку: элемент остаётся на месте, а в
событии приходит `mode: 'copy'`. В библиотеку ничего не бросают. На холст
редактора копия попадает через атрибут `accepts` у
[оверлея редактора](/ru/smart/editor/composition-overlay/).

### Событие `sf-sortable-move`

Когда пользователь отпускает элемент, список-получатель отправляет
`sf-sortable-move` с `event.detail` (прежнее имя `sf-sortable-intent`
приходит с тем же `detail`):

| Поле | Содержимое |
|:---|:---|
| `item` | `id` элемента из `data-sf-sortable-item` |
| `from` | `id` исходного списка, а без `id` — его `group` |
| `to` | `id` списка-получателя, а без `id` — его `group` |
| `index` | итоговая позиция в списке-получателе |
| `mode` | `move` или `copy` |

`index` — уже итоговая позиция, поэтому приложению не нужно пересчитывать её
после удаления элемента из исходного списка. Если приложение отклонило
изменение, ничего менять не нужно: компонент сам DOM не трогает.

`sf-sortable-state` сообщает о сеансе: `{state, item}`, где `state` —
`picked`, когда элемент взят, `dropped` или `cancelled`, когда сеанс
закончился.

```js
document.addEventListener('sf-sortable-move', (event) => {
  const {item, from, to, index, mode} = event.detail;
  // Применить к своей модели с ожидаемой ревизией; при отказе ничего не менять.
});
```

### Перерисовка списка хостом

Компонент сообщает намерение, а список перерисовывает хост. Чтобы
объявления и фокус продолжали работать:

1. **У каждого списка свой `id`.** `from` и `to` — это `id` списков, а имя
   группы приходит только у списка без `id`, и по нему не найти нужный
   список.
2. **Перерисовывайте элементы, а не весь список.** Среди детей списка
   компонент держит область объявлений `aria-live` и подсказку, на которую
   элементы ссылаются через `aria-describedby`. Заменяйте только элементы с
   `data-sf-sortable-item`. Если хост всё же очистил список целиком
   (`replaceChildren()`), компонент вернёт оба узла с тем же `id` подсказки.
3. **Фокус после клавиатуры возвращается сам.** После того как элемент
   положили с клавиатуры, компонент через два кадра ставит фокус на элемент с
   тем же `id` в списке-получателе — но только если фокус оказался на `body`.
   Если хост поставил фокус сам, компонент его не трогает.

```js
list.addEventListener('sf-sortable-move', (event) => {
  const {item, from, to, index, mode} = event.detail;
  if (!model.apply({item, from, to, index, mode})) return; // отказ: ничего не менять
  for (const element of list.querySelectorAll('[data-sf-sortable-item]')) element.remove();
  list.append(...model.items(to).map(renderItem));          // область объявлений на месте
});
```

### Точка вставки

`inserter-items` (или свойство `inserterItems`) включает точку вставки: «+»
в промежутке между элементами, перед первым и после последнего открывает
вставщик с поиском по перечисленным видам. Пункт —
`{value, label, icon, caption, keywords, disabled}`; `{type: "heading",
label}` и `{type: "separator"}` группируют пункты. Выбор приходит событием
`sf-sortable-insert` с `index`, `item` и `to`: приложение создаёт элемент и
перерисовывает список. `preventDefault()` отказывает и оставляет вставщик
открытым. Без `inserter-items` места вставки нет.

С клавиатуры точка вставки — последняя остановка `Tab` в списке: стрелки
переводят её между местами, `Enter` или `Space` открывает вставщик; `+` на
элементе в фокусе открывает вставщик для места после него.

### Внешние цели

Сеанс перетаскивания общий для всех смарт-компонентов страницы. Цель, которая
не является списком, подключается через
`SF.Sortable.registerSortableDropTarget({resolve, drop})`: `resolve(x, y,
session)` возвращает место под указателем или `null`, `drop(session,
descriptor)` отправляет намерение. Вызов возвращает функцию, которая
отключает цель. Так к сеансу подключён оверлей редактора.

### Колонки таблицы: `SF.Sortable.attach`

Ячейки шапки таблицы нельзя обернуть в `<sf-sortable>`, а колонка переезжает
вместе с ячейками всех строк. Для этого `SF.Sortable.attach(container, options)`
даёт то же перетаскивание указателем любому контейнеру и возвращает функцию,
которая его отключает. Объект `SF.Sortable` появляется вместе со скриптом
`sf-sortable`, поэтому дождитесь его: `await SF.whenDefined('sf-sortable')`.

```js
await SF.whenDefined('sf-sortable');
const detach = SF.Sortable.attach(table.tHead.rows[0], {
  items: 'th[data-key]',
  extent: table,
  cellsOf: (th) => [...table.rows].map((row) => row.cells[th.cellIndex]),
  groupOf: (th) => (th.dataset.pinned ? 'pinned' : 'loose'),
  canStart: (event) => !event.target.closest('.resizer'),
  label: 'Колонки',
  onIntent: ({item, index, group}) => saveColumnOrder(item, index, group),
});
```

| Параметр | Что задаёт |
|:---|:---|
| `items` | селектор перетаскиваемых элементов внутри контейнера; обязателен |
| `extent` | элемент, во всю высоту которого встаёт контур (таблица); по умолчанию контейнер |
| `cellsOf` | ячейки, которые приглушаются вместе с колонкой; по умолчанию сам элемент |
| `groupOf` | группа элемента: элемент переставляется только среди своей группы |
| `canStart` | можно ли начать перетаскивание с этого нажатия |
| `preview` | `column` (по умолчанию) — контур шириной в колонку; `line` — тонкая линия |
| `label` | имя списка для объявлений |
| `onIntent` | получает `{item, from, index, group}`: `index` — место среди элементов той же группы без перетаскиваемого |

Пока колонку тянут, она приглушена во всех строках, а на её будущем месте
стоит пунктирный контур. Клик, которым заканчивается перетаскивание, до
заголовка не доходит, поэтому сортировка по клику от отпускания не
срабатывает. Порядок применяет приложение в `onIntent`. Перестановку с
клавиатуры даёт обычный `<sf-sortable>`, например список колонок в настройках
таблицы.

## Доступность

- Задайте списку `label` — имя, которое звучит в объявлениях, например «Нужно
  сделать». Без него используется `aria-label` или имя группы.
- Элементы становятся фокусируемыми и получают описание с инструкцией. Имя
  элемента — его `aria-label` или видимый текст без частей с
  `aria-hidden="true"`, поэтому значок ручки помечайте `aria-hidden`.
- `Space` или `Enter` берут элемент, стрелки вверх и вниз меняют позицию,
  влево и вправо переводят в соседний список или на внешнюю цель, `Space` или
  `Enter` кладут, `Escape` или `Tab` отменяют.
- Каждый шаг объявляется на языке страницы через живую область.
- У краёв прокручиваемой области во время перетаскивания включается
  автопрокрутка.

## Справочник

### Атрибуты

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `group` | строка | пусто | шаблон `^[a-z][a-z0-9-]{0,31}$` | Группа списка: элемент переносится между списками одной группы; обязательна для списка с переносимыми элементами. |
| `accepts` | строка | пусто | — | Другие группы, элементы которых принимает этот список, через пробел. |
| `mode` | строка | `move` | `move`, `copy` | copy: список-библиотека; его элементы копируются наружу и остаются на месте. |
| `orientation` | строка | `vertical` | `vertical`, `horizontal` | — |
| `label` | строка | пусто | — | Имя списка в том, что объявляется вслух. |
| `preview` | строка | `silhouette` | `silhouette`, `line` | silhouette открывает промежуток размером с элемент; line рисует линию. |
| `inserter-items` | строка | пусто | — | Что предлагает точка вставки — JSON или свойство `inserterItems`: `[{value, label?, icon?, caption?, keywords?, disabled?}]`, со строками `{type: "heading", label}` и `{type: "separator"}`; `sf-sortable-insert` несёт выбранное значение как `detail.item`. Пусто — точки вставки нет. |
| `aria-label` | строка | пусто | — | — |

#### Общие для всех компонентов

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `template` | строка | `default` | — | Имя шаблона отрисовки; `default` — встроенный. |
| `root-class` | строка | пусто | — | Свои CSS-классы для нарисованного элемента. |
| `root-style` | строка | пусто | — | Свои стили для нарисованного элемента, например `max-width: 20rem`. |

Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `icon-start` — `iconStart`. Свойство атрибута `template` называется `templateName`.

### Методы

Публичных методов нет.

### События

События приходят на сам элемент и всплывают; глаголы в именах — из [общего словаря](/ru/guide/smart-components/names/). Общие события базового элемента — в главе [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс).

| Событие | `detail` | Когда приходит |
|:---|:---|:---|
| `sf-sortable-move` | `{ item: string, from: string, to: string, index: number, mode: "move" \| "copy" }` | Просьба перенести (или скопировать) элемент в место: один ручной перенос, `{id, parent, position}` под именами item, to и index; применяет его приложение. |
| `sf-sortable-state` | `{ state: "picked" \| "dropped" \| "cancelled", item: string }` | Шаг перетаскивания: взяли, отпустили или отменили. |
| `sf-sortable-insert` | `{ index: integer, item: string, to: string }` | Просьба вставщика поставить новый элемент палитры в место; отменяемая. |
