# Подтверждение изменения

:badge[sf-confirm-change]{variant=outline scheme=on-surface size=1/2} :badge[1.10.4]{variant=outline scheme=on-surface size=1/2}

Подтверждение изменения показывает человеку подготовленное изменение и
ждёт его «да» или «нет»: каждое значение как было и как станет, главный
залитый ответ «Подтвердить» и тихий «Отклонить», под ними — срок, до которого
можно ответить, а после ответа — только итог. Так спрашивают о предложении ассистента, правке коллеги,
импорте перед записью. Карточка ничего не применяет: нажатие — это событие.

Если показывать «было и станет» не нужно — например, удаление, о котором
спрашивают прямо в строке, — берите [Подтверждение](/ru/smart/actions/confirm/).

## Разметка

- `heading` называет изменение (без него — «Что изменится»),
  `heading-level` — уровень заголовка там, где стоит карточка.
- `changes` — список `{label, before, after}`: в атрибуте — JSON, в
  свойстве — массив; свойство важнее. Значение — текст; пустое читается как
  «пусто».
- `change-id` — имя изменения у приложения; оно возвращается в каждом
  событии.
- Слот `description` — строка под заголовком: код, кто предложил.

## Варианты

### Без значений

Изменение, у которого нечего показать «было — стало», например удаление, —
это заголовок и ответы. `accept-text` и `decline-text` меняют слова
ответов.

:::example {id="smart-components/change-confirm/no-values" label="Удаление: заголовок и два ответа"}
:::

### Опасное изменение

`status` • [справочник](#атрибуты)

Принимающий ответ всегда главный и залитый, отклоняющий — тихий.
`status="danger"` отмечает удаление или то, что нельзя отменить: тогда
принимающий ответ — залитая красная кнопка. Под ответами строкой стоит
срок, а после ответа — итог.

:::example {id="smart-components/change-confirm/danger" label="Обычное и опасное изменение"}
:::

## Состояния

### Ответ отправляется и недоступно

Нажатие переводит карточку в `pending`: ответы пропадают, чтобы ничего не
нажали дважды, а строка состояния говорит, что происходит. `disabled`
показывает ответы, но не даёт их нажать — например, пока идёт другая
отправка.

:::example {id="smart-components/change-confirm/state-pending" label="Ответ отправляется; ответы недоступны"}
:::

### Итог

После ответа приложение ставит `state`: `accepted` — подтверждено,
`declined` — отклонено. Если ответ доставить не удалось, верните `open`.
После `expires-at` открытая карточка читается как `expired` и один раз
отправляет `sf-confirm-change-expired`.

:::example {id="smart-components/change-confirm/state-outcome" label="Подтверждено, отклонено и истёк срок"}
:::

## Применение

### Ответ и события

Ответ человека приходит событием `sf-confirm-change-answer` с
`{id, accepted}`: `id` — значение `change-id`, `accepted` — `true` для «да» и
`false` для «нет». Приложение применяет или отклоняет изменение и ставит
итог. Если отменить событие (`preventDefault()`), вопрос остаётся открытым.
`answer({accepted: true})` и `answer({accepted: false})` отвечают из кода, как
человек.

```js
const card = document.querySelector('sf-confirm-change');
card.addEventListener('sf-confirm-change-answer', async (event) => {
  const {id, accepted} = event.detail;
  try {
    await (accepted ? api.apply(id) : api.reject(id));
    card.state = accepted ? 'accepted' : 'declined';
  } catch {
    card.state = 'open';
  }
});
```

## Доступность

- Карточка — раздел, названный заголовком; значения — список описаний,
  который читается как «Название: было Новости, станет События».
- Два ответа — настоящие кнопки (`Tab`, `Enter`, `Space`).
- Строка состояния — вежливая живая область. Когда нажатие убирает ответы,
  фокус переходит на неё, а если приложение отменило событие — обратно на
  первый ответ.

## Справочник

### Атрибуты

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `heading` | строка | пусто | — | Что это за изменение; без него карточка называется «Что изменится». |
| `heading-level` | строка | `3` | `2`, `3`, `4`, `5`, `6` | Уровень заголовка там, где стоит карточка. |
| `state` | строка | `open` | `open`, `pending`, `accepted`, `declined`, `expired` | `open` — ответы предложены. `pending` — ответ в пути (ставится нажатием). `accepted`, `declined`, `expired` — показывается только итог. Если человек отказался здесь, поверхность сворачивается (`hidden`), а фокус с кольцом возвращается к элементу, который задал вопрос, иначе — к ближайшему доступному для фокуса месту рядом или к следующему элементу страницы; состояние `declined`, заданное приложением без такого ответа, остаётся видимым. |
| `expires-at` | строка | пусто | — | ISO 8601. До этого времени строка под ответами говорит, до какого срока можно ответить, время — sf-time («Подтвердить можно до 23:30», «… до завтра, 10:00»; точный момент и его пояс — в подсказке). После срока открытая карточка читается как просроченная и один раз сообщает об этом событием `sf-confirm-change-expired`. |
| `change-id` | строка | пусто | — | Имя изменения у приложения; возвращается в каждом событии. |
| `disabled` | да/нет | нет | — | Ответы видны, но нажать их нельзя, например пока отправляется другой ответ. |
| `status` | строка | пусто | пусто, `danger` | Что делает принятие (C25, как настройка sf-confirm): `danger` — удаление или то, что нельзя отменить. Тогда принимающий ответ — залитая опасная кнопка; без настройки принимающий ответ — главный, залитый `primary` (C183 (6)). Отказ в обоих случаях тихий. |
| `accept-text` | строка | — | — | Подпись кнопки согласия; пусто — «Подтвердить» на языке страницы. |
| `decline-text` | строка | — | — | Слова ответа «нет»; пусто — «Отклонить» на языке страницы. |
| `changes` | список: объект | `[]` | — | Значения в JSON для разметки; свойство, заданное из скрипта, важнее. |

#### Общие для всех компонентов

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `template` | строка | `default` | `default` | Имя шаблона отрисовки; `default` — встроенный. |
| `root-class` | строка | пусто | — | Свои CSS-классы для нарисованного элемента. |
| `root-style` | строка | пусто | — | Свои стили для нарисованного элемента, например `max-width: 20rem`. |

Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `icon-start` — `iconStart`. Свойство атрибута `template` называется `templateName`.

### Методы

| Метод | Возвращает | Что делает |
|:---|:---|:---|
| `open()` | объект | Задаёт вопрос снова: ответы опять можно нажать. Когда вопрос задаёт сборка, она получает ответ `{accepted, reason, value}`, как только человек ответит или выйдет срок. |
| `answer(args: object)` | объект | Ответить, как ответил бы человек: `accepted` true подтверждает, false отклоняет. Отказ, если карточка закрыта, выключена или ответ отменён. |
| `confirm()` | объект | Отвечает «да», как нажатие кнопки согласия; с разметки — `data-sf-action="<id>.confirm"`. |
| `cancel()` | объект | Кнопка отказа. |

### События

События приходят на сам элемент и всплывают; глаголы в именах — из [общего словаря](/ru/guide/smart-components/names/). Общие события базового элемента — в главе [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс).

| Событие | `detail` | Когда приходит |
|:---|:---|:---|
| `sf-confirm-change-answer` | `{ id: any, accepted: boolean }` | Человек ответил. Отмените событие, чтобы вопрос остался открытым. |
| `sf-confirm-change-expired` | `{ id: any }` | Открытая карточка прошла `expires-at`; сообщается один раз на каждое время. |
