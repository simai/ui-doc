# Форма

:badge[sf-form]{variant=outline scheme=on-surface size=1/2} :badge[1.16.0]{variant=outline scheme=on-surface size=1/2}

Форма собирается из описаний полей: страница говорит, какие поля и какие
значения, а форма рисует подпись, «*», «?», подсказку и ошибку у каждого
поля, группы, раскладку, сводку ошибок и кнопки. Сами поля рисует общий
модуль полей SIMAI Framework — тот же, что у карточки записи, таблицы и
фильтров. Берите её для правки записи, страницы настроек, параметров блока
и заявки на сайте. Строки меню настроек — это
[Настройки](/ru/smart/navigation/settings/), а форму, свёрстанную полями
вручную, описывает глава [Поля формы](/ru/guide/components/form-fields/).

## Пример

Очистите «Текст» и «Ссылку» и нажмите «Сохранить»: ошибки встают у полей,
над формой — сводка со ссылками. Код — на вкладке JavaScript.

## Разметка

Поля, группы и значения задаёт блок настроек
`<script type="application/json" data-sf-settings>` или свойства из
скрипта; `label` — имя формы для экранного диктора.

```html
<sf-form label="Кнопка">
  <script type="application/json" data-sf-settings>
    {"fields": [{"key": "text", "label": "Текст", "propertyType": "string", "required": true}],
     "value": {"text": "Подробнее"}}
  </script>
</sf-form>
```

Описание поля — тип и параметры из реестра полей (`propertyType`,
`template`, `templateParams`, `required`, `readonly`, `placeholder`,
`options`, `min`, `max`, `step`, `unit`, `decimals`, деньги — `currency`,
`currencies`, `currencyDisplay`) и ключи формы:

| Ключ | Что задаёт |
|:---|:---|
| `key` | Имя значения в `value`. |
| `label` | Подпись над полем; ею же назван элемент управления. |
| `hint` | Подсказка под полем; ошибка встаёт на её место. Экранный диктор читает её вместе с полем. |
| `help` | Пояснение за знаком «?» после подписи. |
| `width` | `short` — не шире 20 знаков, `medium` — 28 знаков, `full` — во всю строку. Без него поле встаёт в пару с соседним. |
| `group` | Ключ группы из `groups`. |
| `when` | Когда поле показано, обязательно и доступно — см. [Условия полей](#условия-полей). |

`groups` — группы `{key, label}` по порядку. От двух групп каждая — набор
полей с заголовком, между группами линия. Короткий выбор, до пяти
вариантов, форма рисует группой радиокнопок или флажков; длинный —
выпадающим списком. `readonly: true` показывает значение текстом, а не
выключенным полем. Поле типа, который модуль полей не рисует, не
показывается.

## Варианты

### Подписи

`labels` • по умолчанию `top` • [справочник](#атрибуты)

| Значение | Когда брать |
|:---|:---|
| `top` | Подпись над полем: заявка, правка записи, форма в окне. |
| `start` | Подпись слева, в трети строки, поле — в остальном: страница настроек, карточка в админке. Работает с 40rem ширины самой формы; уже — подпись снова над полем. |

Раскладку форма выбирает по своей ширине, а не по ширине окна: от 44rem
поля без `width` встают по два в строку, уже — в одну колонку.

## Состояния

### Просмотр

`mode` • по умолчанию `edit` • [справочник](#атрибуты)

`mode="view"` показывает значения текстом, как карточка записи, и кнопку
«Изменить» под ними. «Изменить» открывает поля; «Сохранить» и «Отмена»
возвращают просмотр. Пустое значение — тихое «Не указан».

:::example {id="smart-components/form/view" label="Контакт: просмотр и правка" preview=sandbox log="sf-form-submit sf-form-cancel" log_console=true log_open=false}
:::

### Ответ отправлен

`apply="answer"`, `state` • [справочник](#атрибуты)

Анкета, на которую отвечают один раз: сообщение в чате, запись в ленте.
Кнопки — «Отправить» и «Отмена». Нажатие проверяет поля и переводит форму в
`pending`: поля заперты, строка «Отправляем…», приходит `sf-form-answer`.
Исход ставит страница атрибутом `state`: `accepted` — значения текстом с
отметкой «Отправлено», `declined` — ничего, `expired` — «Время ответа
истекло», `open` — снова поля, если ответ не дошёл. `size="1/2"` делает
поля и кнопки на ступень меньше — для формы в сообщении.

## Поведение

### Сохранение и ошибки

«Сохранить» всегда доступна: форма сама говорит, что не так. Нажатие (и
`Enter` в однострочном поле) проверяет поля. Если всё верно, приходит
`sf-form-submit` с `{value}` — значения всех показанных полей. Не
отменённое событие делает значения сохранёнными; отменённое оставляет форму
как есть, пока сервер не ответит. Ответ сервера с ошибками у полей —
метод `setErrors`:

```js
form.addEventListener('sf-form-submit', async (event) => {
  event.preventDefault();               // ждём ответа сервера
  const answer = await save(event.detail.value);
  if (answer.errors) form.setErrors({errors: answer.errors});
  else form.value = answer.value;       // новое сохранённое состояние
});
```

Ошибка встаёт у неверного поля после «Сохранить», потом — у поля, которое
изменили и покинули, и уходит, как только значение верно. От двух ошибок
над формой встаёт сводка «Исправьте 2 поля» со ссылкой на каждое поле, и
фокус переходит на неё; одна ошибка — фокус сразу в поле. После первого
изменения под кнопками появляется «Есть несохранённые изменения». «Отмена»
возвращает сохранённые значения и присылает `sf-form-cancel`.

### Изменения сразу

`apply="instant"` — каждое изменение действует сразу, кнопок нет: панель
настроек, параметры блока в редакторе. Изменение поля приходит событием
`sf-form-change` с `{key, value}`; «да / нет» по умолчанию —
переключатель.

### Условия полей

`when` в описании поля говорит, когда поле показано (`visible`),
обязательно (`required`) и доступно (`enabled`). Условие читает значения
других полей такими, какие они на экране сейчас:

| Условие | Когда верно |
|:---|:---|
| `{"field": "k", "op": "eq", "value": v}` | значение поля `k` равно `v`; `ne` — не равно |
| `{"field": "k", "op": "in", "value": [v1, v2]}` | одно из перечисленных; `not_in` — ни одно |
| `{"field": "k", "op": "empty"}` | поле пустое; `not_empty` — заполнено |
| `{"field": "k", "op": "gt", "value": 1000}` | число или дата больше; `gte`, `lt`, `lte` — больше или равно, меньше, меньше или равно |
| `{"all": […]}`, `{"any": […]}`, `{"not": {…}}` | все условия, хотя бы одно, условие неверно |

Скрытое поле не проверяется и не отправляется, но форма помнит его
значение: если поле покажется снова, значение вернётся. Недоступное поле
показано текстом, как `readonly`.

:::example {id="smart-components/form/conditions" label="Адрес только для курьера" preview=sandbox log="sf-form-submit sf-form-invalid" log_console=true log_open=false}
:::

### Значения из скрипта

- `value` — значения по ключам. Заданное из скрипта — сохранённое
  состояние: форма показывает его, забывает ошибки и не считается
  изменённой. Прочитанное — то, что в полях сейчас.
- `valid` — все поля сейчас верны, `dirty` — есть несохранённые изменения;
  оба только читаются.
- `checkValidity()` проверяет поля и показывает ошибки без отправки;
  `reset()` возвращает сохранённые значения без событий.
- `fieldHost` — свойство для записи, которая сама листает выбор записей и
  загружает файлы (карточка записи передаёт его форме при правке группы).

### Внешний вид

Открытые переменные: `--sf-form-field-gap`, `--sf-form-group-gap`,
`--sf-form-label-color`, `--sf-form-summary-background-color` и
`--sf-form-footer-background-color`. `footer="sticky"` ставит кнопки в
полосу, которая прилипает к низу прокручиваемого места, пока форма длиннее
его: длинная страница настроек.

## Доступность

- Форма — ориентир «форма» с именем из `label`; лучше всего — заголовок,
  под которым она стоит.
- Подпись называет поле, подсказка и ошибка связаны с полем и читаются
  вместе с ним; группы — наборы полей с заголовком.
- `Tab` идёт по полям по порядку, затем «Сохранить» и «Отмена» (в просмотре
  — «Изменить»).
- После отправки с одной ошибкой фокус в поле, с двумя и больше — на
  сводке (`role="alert"`); ссылка сводки переводит фокус в своё поле.
- «Изменить» переводит фокус в первое поле, возврат в просмотр — на
  «Изменить».

## Справочник

### Атрибуты

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `apply` | строка | `submit` | `submit`, `instant`, `answer` | `submit` — форма сохраняется кнопкой: «Сохранить» и «Отмена» под полями, обязательное «да / нет» — флажок, после изменения под кнопками «Есть несохранённые изменения». `instant` — каждое изменение действует сразу: кнопок нет, событие изменения на каждое поле, обязательное «да / нет» — переключатель (панель настроек, параметры блока). `answer` — форма, на которую отвечают один раз: анкета в сообщении или записи ленты; «Отправить» и «Отмена» под полями, нажатие отправляет ответ (состояние `pending`, «Отправляем…»), исход ставит приложение; `accepted` показывает значения текстом с отметкой «Отправлено» и без «Изменить», снова их не открыть; `mode` не читается. |
| `size` | строка | `1` | `1`, `1/2` | Ступень полей и кнопок на линейке размеров: `1` или `1/2` — для формы в сообщении. Подпись, подсказка и ошибка стоят на ступени текста `1/2` при обоих. |
| `state` | строка | `open` | `open`, `pending`, `accepted`, `declined`, `expired` | Только при `apply="answer"`: где ответ, словами поверхности подтверждения (`sf-confirm`). `open` — поля, «Отправить» и «Отмена». `pending` — ответ в пути, ставится нажатием: поля заперты, нажатая кнопка ждёт, «Отправляем…» («Отменяем…»). `accepted` — отправленные значения текстом с «Отправлено». `declined` — ничего не рисуется: отказ ничего не говорит. `expired` — только «Время ответа истекло». Исход ставит приложение; `open` снова — если ответ не дошёл (с `setErrors` для полей, которые нужно исправить). |
| `labels` | строка | `top` | `top`, `start` | `top` — подпись над полем (по умолчанию). `start` — подпись рядом с полем: подписи группы — одной колонкой шириной в самую длинную подпись, но не больше 40 % строки, и все поля за ней — на одной оси; так выглядят строка страницы настроек, карточка админки и группа записи, которую правят на месте. Переключается, как `layout="auto"` у `sf-list-description`: рядом — в форме шире 20rem, над полем — в более узкой и на телефоне (уже `md`). |
| `footer` | строка | `static` | `static`, `sticky` | `static` — кнопки под последним полем, главная первой в начале. `sticky` — те же кнопки в полосе, которая прилипает к низу прокручиваемого места, пока форма длиннее его: страница настроек. |
| `label` | строка | пусто | — | Доступное имя формы (`aria-label` формы): экранный диктор называет по нему ориентир «форма»; лучше всего — заголовок, под которым стоит форма. |
| `guard` | да/нет | нет | — | Защита от ухода: пока в форме есть несохранённые изменения, закрытие или перезагрузка вкладки задаёт вопрос браузера, а нажатие на ссылку, которая уводит со страницы (на другую страницу или на маршрут, который страница рисует на месте, — адрес на странице, не называющий элемент), задерживается: уходит отменяемое событие `leave`, и форма спрашивает «Уйти без сохранения?» в окне вопроса с ответами «Не сохранять» (красная, первой; поля возвращаются, ссылка нажимается снова) и «Продолжить правку» (тихая, с фокусом; страница и меню остаются). Ссылка внутри формы, ссылка в другую вкладку или на скачивание и нажатие с клавишей-модификатором проходят без вопроса. |
| `readonly` | да/нет | нет | — | Форма, которую человек может прочитать, но не изменить: значения текстом, как их рисует режим `view`, без «Изменить» и «Сохранить»; на месте кнопок стоит строка причины (`readonly-reason`). Не читается при `apply="answer"`. |
| `readonly-reason` | строка | пусто | — | `readonly`: почему форму нельзя изменить — говорится на месте кнопок («Менять настройки сайта может администратор сайта»); по умолчанию «Только чтение». |
| `mode` | строка | `edit` | `edit`, `view` | `edit` — поля. `view` — значения текстом (вид модуля полей для просмотра, как в карточке записи) и «Изменить» под ними; «Изменить» открывает правку, «Сохранить» и «Отмена» возвращают просмотр. |
| `busy` | да/нет | нет | — | Пока приложение сохраняет: «Сохранить» показывает загрузку своим цветом, «Отмена» ждёт, все поля только для чтения, второе нажатие и Enter ничего не делают; у формы `aria-busy`. Приложение, которое отменяет `submit`, чтобы сохранить само, ставит его и отвечает действием `saved`, `set-errors`, новым значением или `busy` false — любое из них его снимает. |
| `saved-at` | строка | пусто | — | Когда значения сохранялись последний раз — дата и время ISO: строка состояния под кнопками говорит «Сохранено в 14:35» по часам читателя до следующего изменения, которое очищает её и говорит «Есть несохранённые изменения». Записывается неотменённым `submit` и действием `saved`; приложение может задать его из кода. |
| `fields` | список | `[]` | — | Поля по порядку: описание поля SIMAI Framework, то же, что передаёт `sf-view-properties`, — тип из реестра свойств, его шаблон и параметры (`propertyType`, `template` и `templateParams`, `required`, `readonly`, `placeholder`, `options`, `min`, `max`, `step`, `unit`, `decimals`, `currency`, `currencies`, `currencyDisplay`, `holder` — для поля ИНН: `any`, `organization` (10 цифр) или `person` (12), `defaultCountry` — для телефона: страна ISO 3166 alpha-2, с которой начинается пустое поле, иначе страна страницы … как их перечисляет `SF.fieldRenderers.registry`) и ключи формы `key`, `label`, `hint`, `help`, `width` и `group`. `width`: `short` (шаг ширины поля в 20 знаков, 160 px при тексте 16), `medium` (28 знаков, 224 px) или `full`; без него поле встаёт в пару с соседним от 44rem ширины самой формы. Поле типа, который модуль полей не рисует, не показывается. |
| `groups` | список | `[]` | — | Группы, которые называют ключи `group` полей, по порядку: `{key, label}`. От двух групп каждая — набор полей с подписью-заголовком, между группами 24 и линия. Поле без группы или с группой не из списка стоит в своей группе после перечисленных. |
| `field-host` | объект | `null` | — | Половина интерфейса хозяина полей, которую держит запись; только свойство. `getFieldOptionsPage`, `getFieldOptionSearch`, `setFieldOptionSearch` и `loadFieldOptions` листают и ищут выбор записи, связи или сотрудника (шаблон `reference_picker`); `getFieldUploads`, `startFieldUpload` и `retryFieldUpload` передают файл (шаблон `upload`: форма рисует поле загрузки, и оно само говорит свою ошибку); `getFieldText` и `formatFieldValue` — слова и формат хозяина; `renderField(field, value, host, {editing, size})` рисует тип, который рисует набор компонентов (`items`, `complex`, `ru.requisites`). Каждый вызывается с аргументами модуля полей и последним аргументом — хозяином формы для этого поля; его `setFieldValue` пишет в значение формы (например, сохранённый файл). Значения, их проверка и отправка остаются формы. Без этого свойства выбор листает собственные `options` поля, а файловое поле держит выбранные файлы в значении (`{name, size, mime, file}`: сам `File` приложение отправляет вместе со значениями). |
| `origin` | объект | `{}` | — | Откуда берутся значения полей — слова, которые говорит каждое поле с происхождением: `own` (подпись своего значения, «Своё для simai.ru»; по умолчанию «Своё значение»), `above` (верхний уровень перед его значением, «у всех сайтов»; по умолчанию «общее»), `inherited` (тихая строка унаследованного значения, «Как у всех сайтов»; по умолчанию нет — отмечаются только своё и закрытое значение) и `locked` (причина, по которой поле закрыто выше; «Закрыто на уровне выше»). Собственные слова происхождения у поля сильнее. |
| `value` | объект | `{}` | — | Значения по ключам полей: `{text: "Подробнее", tone: "accent"}`. Заданное из кода — сохранённое состояние: форма показывает его, забывает ошибки и не считается изменённой. Прочитанное — то, что сейчас в полях и что уйдёт при сохранении: поле, скрытое условием (`when.visible`), в него не входит, но форма помнит его значение, и оно вернётся, когда поле покажется снова. Значения, которое человек не задавал, нет. |

#### Общие для всех компонентов

| Атрибут | Тип | По умолчанию | Значения | Что делает |

| `root-class` | строка | пусто | — | Свои CSS-классы для нарисованного элемента. |
| `root-style` | строка | пусто | — | Свои стили для нарисованного элемента, например `max-width: 20rem`. |

Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `icon-start` — `iconStart`. Свойство атрибута `template` называется `templateName`.

### Методы

| Метод | Возвращает | Что делает |
|:---|:---|:---|
| `checkValidity()` | объект | Проверяет каждое показанное поле и показывает все ошибки, как «Сохранить», но без отправки: `applied`, если всё верно, иначе отказ `{reason: invalid}`. Фокус не переводит. |
| `reset()` | объект | Каждое поле возвращается к сохранённому состоянию, без событий; ошибки и сводка уходят. |
| `refreshFields()` | объект | Ответы хозяина полей изменились — страница вариантов, ход загрузки, сохранённый файл — и поля рисуются заново с тем, что он отвечает сейчас. Когда вызов хозяина отвечает обещанием, форма перерисовывается сама, как только оно выполнено. |
| `setErrors(args: object)` | объект | Ответ приложения на отправку: `{ключ: сообщение}` — каждое названное поле показывает сообщение как свою ошибку, пока человек его не изменит; от двух ошибок сводка получает фокус, как после «Сохранить»; пустой объект снимает ошибки. Форма в просмотре открывает правку. Отказ `{reason: missing}`, если ни один ключ не называет показанное поле. |
| `saved(args?: object)` | объект | Ответ приложения на сохранение, которое оно взяло на себя (отменило `submit`): значения в полях становятся сохранёнными — `dirty` false, `busy` false, `saved-at` — заданное время ISO или сейчас, в строке состояния «Сохранено в ЧЧ:ММ»; форма, открытая из просмотра, возвращается в просмотр. Отказ `{reason: mode}` в просмотре, при `apply="instant"` и `apply="answer"`. |
| `confirmLeave()` | объект | Собственный переход приложения спрашивает, прежде чем уйти: применяется сразу, если в форме нет несохранённых изменений, иначе после вопроса «Уйти без сохранения?» — применяется ответом «Не сохранять» (поля возвращаются к сохранённому), отказ `{reason: stayed}` — ответом «Продолжить правку». |

### События

События приходят на сам элемент и всплывают; глаголы в именах — из [общего словаря](/ru/guide/smart-components/names/). Общие события базового элемента — в главе [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс).

| Событие | `detail` | Когда приходит |
|:---|:---|:---|
| `sf-form-input` | `{ key: string, value: any }` | Человек изменил значение поля: его ключ и новое значение (`undefined`, если поле отказалось от недописанного текста). Приходит как `sf-form-input`, а не `input`: собственные события `input` полей проходят через форму без изменений. |
| `sf-form-change` | `{ key: string, value: any }` | Только при `apply="instant"`: значение поля применено (одно на каждую фиксацию поля): набранный текст — когда элемент управления его фиксирует (его `change`: уход из поля, Enter) или человек уходит из поля; выбор, флажок или файл — сразу; только значение, которое отличается от применённого последним. Отправляется как `sf-form-change`, а не `change`: собственные `change` полей всплывают через форму без изменений. |
| `sf-form-submit` | `{ value: object, inherited: array }` | `apply="submit"`: «Сохранить» (или Enter в однострочном поле) нашла все поля верными; `value` — значения всех показанных полей по ключам (поле, скрытое условием, не отправляется). Не отменённое событие делает значение сохранённым (`dirty` false), и форма, открытая из просмотра, возвращается в просмотр; отменённое — форма остаётся как есть (приложение ответит позже через `set-errors` или новым `value`). Если не отменено, строка состояния говорит «Сохранено в ЧЧ:ММ» (`saved-at`); приложение, которое отменяет событие, чтобы сохранить само, ставит `busy` и отвечает действием `saved`. |
| `sf-form-answer` | `{ accepted: boolean, value?: object }` | `apply="answer"`: «Отправить» нашла все поля верными (`accepted` true, со значением) или нажата «Отмена» (`accepted` false). Приходит в состоянии `pending`; исход ставит приложение в обработчике или позже: `accepted`, `declined` или снова `open`. Отменённое событие — ответ не принят: форма снова открыта, и на неё можно ответить ещё раз. |
| `sf-form-invalid` | `{ fields: array }` | Отправка или `checkValidity()` нашли неверные поля: их ключи по порядку. У каждого поля — его ошибка; от двух ошибок над формой встаёт сводка со ссылкой на каждое поле и получает фокус. Ошибка приложения (`setErrors`) для поля, которое скрыто условием, называется в сводке подписью поля, без ссылки, и не задерживает следующую отправку. |
| `sf-form-cancel` | `{ value: object }` | «Отмена»: поля вернулись к сохранённому состоянию (`value`), ошибки ушли; форма, открытая из просмотра, возвращается в просмотр. |
| `sf-form-reset-field` | `{ key: string, value: any }` | «Вернуть общее» под полем со своим значением: ключ поля и значение верхнего уровня, которое оно берёт. Если не отменено, поле принимает его как изменение человека — `dirty` до «Сохранить», а в форме с `apply="instant"` применяется сразу (`change`), — и фокус переходит на поле; если отменено, ничего не меняется. |
| `sf-form-leave` | `{ href: string }` | `guard`: нажатие на ссылку, которая уводит со страницы, пока в форме есть несохранённые изменения; `href` — куда она ведёт. Нажатие задерживается раньше, чем его услышит кто-то другой. Если не отменено, форма спрашивает «Уйти без сохранения?» и после «Не сохранять» нажимает ссылку снова; если отменено, вопрос берёт на себя приложение (свой вопрос или действие `reset` и свой переход). |
