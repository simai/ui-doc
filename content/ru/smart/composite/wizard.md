# Мастер

:badge[sf-wizard]{variant=outline scheme=on-surface size=1/2} :badge[1.5.5]{variant=outline scheme=on-surface size=1/2} :badge[sf-wizard-step]{variant=outline scheme=on-surface size=1/2} :badge[1.0.8]{variant=outline scheme=on-surface size=1/2}

Мастер — процесс из нескольких шагов, который человек проходит один раз, а
продукт между шагами делает работу: первая настройка сервера, установщик,
импорт CSV, установка пакета, создание сайта. Рамка мастера `sf-wizard`
рисует ход по шагам, заголовок и пояснение шага, тело шага и одну строку
кнопок. Каждый шаг — дочерний `sf-wizard-step`, его дети — тело шага: форма
из полей Framework, картинка, состояние, план изменений.

Мастер ничего не хранит за приложение: состояния шагов — атрибуты шагов,
ответы — его значение `value`, каждое движение и нажатие — событие. Ход
процесса, который идёт сам, без участия человека, показывает
[Ход выполнения](/ru/smart/feedback/progress-run/), а этапы без тела —
[Шаги](/ru/smart/navigation/steps/).

## Разметка

```html
<sf-wizard heading="Новый сайт">
  <sf-wizard-step name="name" label="Название" type="form"
    description="Так сайт будет называться в панели и в заголовке страниц.">
    <form>
      <sf-input name="title" label="Название сайта" required></sf-input>
    </form>
  </sf-wizard-step>
  <sf-wizard-step name="template" label="Шаблон" type="info">
    <p>Шаблон «Магазин»: каталог, корзина и оплата уже настроены.</p>
  </sf-wizard-step>
  <sf-wizard-step name="done" label="Готово" type="result">
    <p>Сайт создан.</p>
  </sf-wizard-step>
</sf-wizard>
```

Атрибуты шага:

| Атрибут `sf-wizard-step` | Что задаёт |
|:---|:---|
| `name` | Ключ шага: его называет `current`, его несут события, под ним ответы шага в `value`. Пусто — `step-1`, `step-2`… |
| `label` | Короткое имя в ходе по шагам. |
| `heading` | Заголовок над телом шага; пусто — `label`. |
| `description` | Зачем этот шаг, одно-два предложения под заголовком. |
| `type` | `info`, `form`, `action`, `review`, `result` — см. ниже. |
| `optional` | Шаг можно пропустить: появляется «Пропустить». |
| `href` | Место `pages`: адрес шага. |
| `action-text` | Подпись главной кнопки на этом шаге вместо слова типа. |
| `message` | Чем кончилось действие шага, одно предложение. |
| `state` | `done`, `skipped`, `running`, `error`; пусто — не начат. |

Заголовок, пояснение, индикатор выполнения, итог и кнопки мастер рисует по
атрибутам: в тело шага их не пишут. Человек вводит данные и запускает
действие внутри мастера; если нужен другой раздел, он открывается окном
поверх мастера или ссылкой с возвратом.

Типы шагов и главная кнопка:

| `type` | Что делает | Главная кнопка |
|:---|:---|:---|
| `info` | показывает текст или картинку | «Далее» |
| `form` | поля Framework, проверка, ошибки у полей; «Далее» сохраняет шаг | «Далее» |
| `action` | запускает долгое действие | «Запустить», пока идёт — ждёт, «Далее» после успеха, «Повторить» после ошибки |
| `review` | сводка введённого с «Изменить» у каждого пункта | «Применить» |
| `result` | что получилось и куда дальше; кнопки «Назад» нет | «Готово» |

На последнем шаге любого типа главная кнопка — «Готово». `action-text`
заменяет слово типа («Выпустить сертификат», «Импортировать»); «Повторить» и
«Далее» после действия остаются своими.

Тело шага-сводки — список `ul.sf-wizard-plan`: строка на изменение, что и на
что слева, «Изменить» (`sf-button` с `data-wizard-step`) справа, тонкая линия
между строками. Так устроен шаг «Проверка» в примере выше.

## Варианты

### Ход по шагам

`progress="auto"` (по умолчанию): до семи шагов — ряд сверху, пока он
помещается в ширину мастера; больше семи шагов или ряд шире своего места —
«Шаг 4 из 12», полоса и «Все шаги», который открывает список всех шагов.
Мастер меряет ряд сам, когда меняется его собственная ширина, и снова
показывает ряд, когда места стало хватать. `progress="row"` и
`progress="count"` выбирают одно из двух: явный ряд, который не помещается,
прокручивается вбок. `progress="column"` — колонка шагов слева внутри рамки,
когда ширина мастера не меньше 40rem; уже 40rem мастер показывает
компактную шапку: текущий шаг и полосу.

:::example {id="smart-components/wizard/count" label="Двенадцать шагов: «Шаг 5 из 12», полоса и список" preview=sandbox}
:::

`navigation` — какие шаги открывает нажатие в ходе по шагам: `linear` (по
умолчанию) — любой шаг до первого не сделанного и не пропущенного; `free` —
любой; `visited` — уже пройденный и текущий. «Далее» и «Назад» всегда идут
по порядку. Любой элемент шага с `data-wizard-step="<name>"` открывает тот
шаг по тем же правилам.

### Где показывается

`place` • по умолчанию `inline` • [справочник](#атрибуты)

- `inline` — мастер стоит в странице. «Далее» проверяет поля, отправляет
  `sf-wizard-submit` и, если его не отменили, отмечает шаг сделанным и
  показывает следующий.
- `modal` — окно ширины формы (36rem, с колонкой шагов 48rem, на телефоне
  весь экран), которое открывает элемент страницы, названный в `for`, или
  метод `open()`. Место для большинства мастеров. После последнего шага окно
  закрывается и приходит `sf-wizard-completed`.
- `drawer` — боковая панель 30rem у конечного края для короткого мастера из
  двух–четырёх шагов внутри записи; открывается так же.
- `pages` — страница сервера на шаг; в браузере ничего не хранится (см.
  [Страница на шаг](#страница-на-шаг)).

:::example {id="smart-components/wizard/modal" label="Импорт CSV в окне" preview=sandbox log="sf-wizard-open sf-wizard-close sf-wizard-completed" log_console=true log_open=false}
:::

## Состояния

### Действие шага

Не начат, текущий, сделан (`done`), пропущен (`skipped`), выполняется
(`running`), ошибка (`error`). Текущий — тот, что называет `current`, какое бы
состояние у него ни было. В местах `inline` и `modal` мастер сам ставит шагу
`done` или `skipped`, когда человек идёт дальше; для действия `state` и
`message` пишет приложение.

Пока шаг выполняется, в нём индикатор и строка `message` или `running-text`,
тело помечено `aria-busy`, главная кнопка показывает свой индикатор, и
второй раз действие не отправить. Итог — уведомление успеха или ошибки. В
примере первый запуск не удаётся, второй проходит.

:::example {id="smart-components/wizard/action" label="Импорт: ошибка, «Повторить» и итог" preview=sandbox log_console=true log_open=false}
:::

```js
wizard.addEventListener('sf-wizard-submit', async (event) => {
  if (event.detail.action !== 'run' && event.detail.action !== 'retry') return;
  event.preventDefault();               // действие выполняет приложение
  const step = wizard.querySelector('sf-wizard-step[name="run"]');
  step.setAttribute('state', 'running');
  try {
    await importContacts(event.detail.value);
    step.setAttribute('message', 'Добавлено 124 контакта.');
    step.setAttribute('state', 'done');  // итог и «Далее»
  } catch (error) {
    step.setAttribute('message', error.message);
    step.setAttribute('state', 'error'); // итог и «Повторить»
  }
});
```

## Поведение

### Проверка полей

«Далее» проверяет поля шага штатной проверкой браузера: `required`, `type`,
`pattern`, `min`, `max`, собственная проверка поля формы. Каждое неверное
поле Framework получает `invalid` и сообщение на языке страницы: пустое
обязательное поле — «Заполните поле», любая другая ошибка — «Проверьте
значение». Первое неверное поле получает фокус, приходит
`sf-wizard-invalid`, шаг остаётся. Когда человек правит поле, мастер снимает
то, что поставил сам; ошибки, которые напечатал сервер, остаются. `Enter` в
поле шага отправляет шаг так же, как главная кнопка.

### Кнопки

Внизу одна строка в постоянном порядке: «Назад» в начале (на первом шаге и
на шаге-итоге её нет), «Пропустить» у необязательного шага и одна главная
кнопка в конце. Все кнопки — `sf-button`; при грубом указателе (палец)
кнопки шапки и низа, шаги ряда и строки списка не ниже 44 px.

В окне и в боковой панели, когда сам мастер уже 30rem (на телефоне, где окно
занимает весь экран, или в узком окне на широком экране), нижняя строка
прилипает к низу окна, пока шаг прокручивается, а «Назад» и главная кнопка
делят строку: «Назад» от начала, главная до конца. Решает ширина мастера, а
не экрана: мастер от 30rem на узком экране так не перестраивается.

### «Продолжить позже» и закрытие

`later` (или `later-href`) рисует «Продолжить позже». Нажатие отправляет
`sf-wizard-close` с `reason: later`, текущим шагом, состояниями всех шагов и
ответами; затем окно закрывается или браузер идёт на `later-href`. Крестик
окна, `Escape` и затемнение работают так же: мастер ничего не спрашивает, а
сначала сохраняет черновик.

Черновик — текущий шаг, состояния шагов и ответы — мастер в местах `inline`,
`modal` и `drawer` сохраняет после каждого перехода и вскоре после каждой
правки ([персональный вид](/ru/guide/smart-components/view-preferences/),
ключ `sf-wizard/<ключ>`). Ключ задаёт `remember`, без него — `id` элемента;
без `id` черновик живёт, пока открыта страница. В следующий раз мастер
открывается там же, а тихая строка под кнопками говорит «Черновик сохранён
в …». После завершения запись удаляется.

### Одно значение

`value` — все ответы всех шагов по имени шага и имени поля:

```json
{"address": {"host": "panel.example.ru"}, "backups": {"keep": "7", "daily": "1"}}
```

Мастер собирает его из именованных полей шагов; имя, данное дважды, —
список. `value` только читается; его несут `change`, `submit`, `close` и
`completed`. В месте `modal` шаги на время открытого окна стоят в окне:
находите шаг по `id`, а не через `wizard.querySelector`.

## Применение

### Страница на шаг

С `place="pages"` каждый шаг — своя страница сервера. Сервер печатает мастер
со всеми шагами (`name`, `label`, `href`, `state`), а тело — только у
текущего; `current` называет текущий:

```html
<sf-wizard place="pages" heading="Настройка сервера" current="protection" later-href="/" focus-title>
  <sf-wizard-step name="address" label="Адрес панели" href="/setup/address" state="done"></sf-wizard-step>
  <sf-wizard-step name="notify" label="Уведомления" href="/setup/notify" optional state="skipped"></sf-wizard-step>
  <sf-wizard-step name="protection" label="Защита" type="action" href="/setup/protection"
    action-text="Выпустить сертификат" state="error"
    message="Let’s Encrypt не ответил: домен пока не указывает на этот сервер.">
    <form method="post" action="/setup/protection">…</form>
  </sf-wizard-step>
  <sf-wizard-step name="backups" label="Копии" href="/setup/backups"></sf-wizard-step>
</sf-wizard>
```

- Главная кнопка — кнопка отправки формы шага: `sf-button` с
  `native-type="submit"`, `form` формы шага, `name="wizard-action"` и
  `value` — `next`, `run`, `retry`, `apply` или `done`. Браузер отправляет
  форму шага со словом нажатой кнопки; скрытых полей мастер не добавляет. Имя
  меняет `action-name`. Форме без `id` мастер даёт свой.
- «Пропустить» отправляет форму со словом `skip` без проверки полей.
- «Назад» и ход по шагам — ссылки на `href` шагов.
- Шаг без формы идёт по `href` следующего шага, последний — по `done-href`.
- Сервер отвечает той же страницей мастера: тот же шаг с ошибками у полей
  (`invalid`, `error-message`) или с итогом (`state`, `message`), либо
  следующий шаг. `focus-title` даёт фокус заголовку шага.

Чтобы страница не мигала, сервер печатает рамку, ход по шагам и кнопки
статической разметкой (`data-sf-static`), а шаги — один раз внутри рамки, в
контейнере `data-sf-live`. Мастер забирает шаги оттуда живыми в том же кадре,
в котором рисует себя: форма шага на странице одна, её поля и ошибки сервера
сохраняются (см. [Коробка до кода](/ru/guide/smart-components/first-paint/#коробка-до-кода)).

## Доступность

- Мастер — область (`role="region"`), названная `heading`; без него —
  `label`, иначе «Пошаговая настройка».
- Текущий шаг в ряду и в списке отмечен `aria-current="step"`, состояние
  шага входит в его имя.
- После перехода фокус получает заголовок шага, а скрытая строка состояния
  говорит «Шаг 3 из 6: Уведомления».
- Пока шаг выполняется, тело помечено `aria-busy`.
- Все кнопки — нативные кнопки и ссылки `sf-button`.

## Справочник

### `<sf-wizard>`

#### Атрибуты

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `place` | строка | `inline` | `inline`, `modal`, `drawer`, `pages` | Где показывается мастер: inline — в странице; modal — окно, которое открывает триггер (for или действие open), ширина формы 36rem (48rem с колонкой шагов, весь экран на телефоне) — место для большинства мастеров; drawer — боковая панель 30rem у конечного края (sf-drawer size 2) для короткого мастера из двух–четырёх шагов внутри записи, открывается так же; pages — страница на шаг для долгого установщика: сервер печатает мастер с телом текущего шага, форма шага отправляется, и сервер отвечает тем же мастером с ошибками или следующим шагом; в браузере ничего не хранится. |
| `navigation` | строка | `linear` | `linear`, `free`, `visited` | Какие шаги открывает нажатие в ходе по шагам: linear — любой шаг до первого не сделанного и не пропущенного; free — любой; visited — уже сделанный, пропущенный или с ошибкой и текущий. «Далее» всегда идёт по порядку. |
| `progress` | строка | `auto` | `auto`, `row`, `count`, `column` | Как рисуется ход по шагам: row — шаги рядом сверху (sf-steps); count — «Шаг 4 из 12», полоса и список всех шагов по запросу; column — колонка шагов слева внутри рамки у широкого мастера (от 40rem собственной ширины, иначе count). auto — ряд до 7 шагов, пока он помещается в ширину мастера, иначе count: мастер меряет ряд в одну строку и рисует count, когда ряд шире своего места, и снова — когда меняется его ширина. Узкий мастер (уже 40rem) всегда рисует компактную шапку: текущий шаг и полосу. |
| `size` | строка | `1` | `1/2`, `1` | Ступень лестницы размеров: ей следуют ход по шагам, кнопки, тексты и отступы. |
| `heading` | строка | пусто | — | Что делает мастер («Настройка сервера») — строка над ходом по шагам; пусто — строки нет. |
| `label` | строка | — | — | Имя области: heading, иначе «Пошаговая настройка» / «Step-by-step setup». |
| `level` | целое число | `2` | от 1; до 6 | Уровень заголовка шага (role heading, aria-level). |
| `for` | строка | пусто | — | Места modal и drawer: id элемента страницы (или несколько через пробел), нажатие на который открывает окно. |
| `later` | да/нет | нет | — | Рисует «Продолжить позже»: close {reason: later} с местом и ответами, затем окно закрывается или браузер идёт на later-href; черновик сохраняется (remember). В окне так же работает ×. |
| `later-href` | строка | пусто | — | Куда ведёт «Продолжить позже»; тоже рисует кнопку. |
| `remember` | строка | пусто | — | Места inline, modal и drawer: ключ, под которым хранится черновик, — текущий шаг, состояния шагов и ответы, после каждого перехода и вскоре после каждой правки, в SF.Preferences (в этом браузере — localStorage sf-pref:sf-wizard/&lt;ключ&gt;; продукт, который хранит настройки человека, получает их тоже). В следующий раз мастер открывается там же, а тихая строка под кнопками говорит, когда черновик сохранён. После завершения запись удаляется. Пусто — ключом служит id элемента; без id черновик живёт, пока открыта страница. Место pages ничего не хранит: место знает сервер. |
| `done-href` | строка | пусто | — | Куда ведёт «Готово» на последнем шаге, когда у шага нет формы. |
| `action-name` | строка | `wizard-action` | — | Место pages: имя, под которым кнопки отправки в нижней строке отправляют своё слово (next, run, retry, apply, done, skip), чтобы сервер знал, какая нажата. |
| `running-text` | строка | — | — | Строка у индикатора, пока шаг выполняется и у него нет своего message; «Выполняется…» / «Working…». |
| `focus-title` | да/нет | нет | — | Место pages: заголовок шага получает фокус, когда мастер нарисован, как после перехода на одной странице. Сервер печатает его на страницах, которыми отвечает на форму шага. |
| `current` | строка | пусто | — | Имя показанного шага. Пусто — первый шаг, который не сделан и не пропущен, иначе первый. Переход человека пишет его и отправляет change. |
| `open` | да/нет | нет | — | Место modal: окно открыто. |
| `value` | объект | `{}` | — | Все ответы всех шагов по имени шага и имени поля: {address: {host: "panel.example.ru"}, notify: {email: "…"}}. Только для чтения: мастер собирает его из полей шагов по мере изменения; его несут change, submit, close и completed. |

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `template` | строка | `default` | — | Имя шаблона отрисовки; `default` — встроенный. |
| `root-class` | строка | пусто | — | Свои CSS-классы для нарисованного элемента. |
| `root-style` | строка | пусто | — | Свои стили для нарисованного элемента, например `max-width: 20rem`. |

Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `icon-start` — `iconStart`. Свойство атрибута `template` называется `templateName`.

#### Методы

| Метод | Возвращает | Что делает |
|:---|:---|:---|
| `open()` | объект | Место modal: открывает окно на текущем шаге; отказ, если страница отменила sf-wizard-open или место не modal. |
| `close()` | объект | Место modal: закрывает окно (reason api); отказ, если окно закрыто или страница отменила sf-wizard-close. |
| `goToStep(args: object\|string)` | объект | Показывает шаг с этим именем независимо от правила navigation: refused {reason: missing} для имени, которого у мастера нет, {reason: current} для показанного шага. change не отправляет: это переход приложения, а не человека. |
| `next()` | объект | Нажимает главную кнопку, как человек: проверка, submit, переход. refused {reason: busy}, пока шаг выполняется, {reason: invalid}, когда поля неверны, {reason: prevented}, когда submit отменён. |

#### События

События приходят на сам элемент и всплывают; глаголы в именах — из [общего словаря](/ru/guide/smart-components/names/). Общие события базового элемента — в главе [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс).

| Событие | `detail` | Когда приходит |
|:---|:---|:---|
| `sf-wizard-change` | `{ previous: string, current: string, value: object }` | Человек перешёл на другой шаг («Далее», «Назад», «Пропустить», шаг в ходе по шагам, «Изменить» в сводке); current — шаг, который показан теперь. Не приходит при goToStep и когда приложение пишет current. |
| `sf-wizard-submit` | `{ step: string, action: "next" \| "run" \| "retry" \| "apply" \| "done" \| "skip", values: object, value: object }` | Человек нажал главную кнопку или «Пропустить», и поля шага верны: values — ответы шага, value — все ответы. Запрос: отменённый — работу делает приложение (у шага-действия — state running, затем done или error со своим message); не отменённый — место pages отправляет форму шага, inline и modal отмечают шаг сделанным (пропущенным) и показывают следующий, а последний отправляет completed. |
| `sf-wizard-invalid` | `{ step: string, fields: array }` | Нажата главная кнопка, а поля шага неверны: у каждого неверного поля — его сообщение, первое получает фокус, fields — их имена. Ничего не отправлено. |
| `sf-wizard-navigate` | `{ id: string, href: string }` | Место pages: человек идёт по адресу шага («Назад», шаг в ходе по шагам, «Далее» или «Готово» без формы); id — имя шага. Запрос: отменённый — страница переходит сама; не отменённый — браузер идёт туда. |
| `sf-wizard-open` | пустой объект | Место modal: окно вот-вот откроется (кнопка-триггер или действие open). Отменённое — окно остаётся закрытым. |
| `sf-wizard-close` | `{ reason: "later" \| "close" \| "escape" \| "outside" \| "api", current: string, steps: array, value: object }` | Человек уходит из мастера, чтобы продолжить позже: «Продолжить позже» (later), × окна, Escape, затемнение или действие close. Ничего не спрашивается: сначала сохраняется черновик (remember); steps несёт {name, state} каждого шага, value — ответы, чтобы продукт хранил ход там же, где свои черновики. |
| `sf-wizard-completed` | `{ steps: array, value: object }` | Места inline и modal: последний шаг отправлен; окно после этого закрывается. |

### `<sf-wizard-step>`

#### Атрибуты

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `name` | строка | пусто | — | Ключ шага: его называет current, его несут события, под ним ответы шага в value мастера. Пусто — его место (step-1, step-2 …). |
| `label` | строка | пусто | — | Короткое имя шага в ходе по шагам («Адрес панели»). |
| `heading` | строка | пусто | — | Заголовок шага над телом; пусто — label. |
| `description` | строка | пусто | — | Зачем этот шаг — одно-два предложения под заголовком. |
| `type` | строка | `info` | `info`, `form`, `action`, `review`, `result` | Что делает шаг и, значит, его главная кнопка: info показывает («Далее»); form принимает поля и проверяет их («Далее» сохраняет шаг); action запускает долгое действие («Запустить», затем «Далее»; «Повторить» после ошибки); review показывает, что будет сделано, с возвратом к каждому шагу («Применить»); result говорит, что получилось («Готово»). |
| `optional` | да/нет | нет | — | Шаг можно пропустить: мастер рисует «Пропустить», а пропущенный шаг читается как пропущенный. |
| `href` | строка | пусто | — | Место pages: собственный адрес шага. Туда ведут «Назад» и нажатие на шаг в ходе по шагам. |
| `action-text` | строка | пусто | — | Подпись главной кнопки на этом шаге («Выпустить сертификат», «Импортировать»); пусто — слово типа шага. «Повторить» и переход после действия сохраняют свои слова. |
| `message` | строка | пусто | — | Чем кончилось действие шага, одно предложение: рисуется уведомлением sf-alert в шаге — успеха, пока шаг done, ошибки, пока error. Пока шаг выполняется — строка у индикатора. |
| `state` | строка | пусто | пусто, `done`, `skipped`, `running`, `error` | Где стоит шаг: пусто (не начат), done, skipped, running (его действие идёт) или error. Пишет приложение; в местах inline и modal мастер сам пишет done и skipped, когда человек идёт дальше. |
