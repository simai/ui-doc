# Требует внимания

:badge[sf-list-attention]{variant=tonal scheme=primary size=1/2} :badge[1.3.1]{variant=outline scheme=on-surface size=1/2}

Список проблем, которые ждут человека, на обзорном экране: здоровье сервера,
проверки сайта, ошибки импорта и переноса, готовность к обновлению,
целостность хранилища, сводка ошибок формы. Сверху заголовок с их числом,
ниже каждая проблема — состояние, название, строка текста и одно действие,
самые серьёзные первыми. Когда проблем нет, список не рисует ничего и не
занимает места.

Состояние, которое требует действия сейчас и видно на всех страницах,
показывайте [Плашкой уведомлений](/ru/smart/feedback/alert-bar/); одно
сообщение в потоке страницы — [Уведомлением](/ru/smart/feedback/alert/).

## Разметка

Список проблем передайте JSON-блоком, который печатает сервер, или
свойством `items`. Ставьте список на страницу как есть, не в карточку:
пустой список места не занимает.

```html
<sf-list-attention label="Здоровье сервера">
  <script type="application/json" data-sf-settings>
    {"items": [
      {"id": "down", "status": "error", "title": "demo-php.test не отвечает",
       "text": "12 минут, код 502", "action": {"label": "Перезапустить", "event": "restart"}},
      {"id": "cert", "status": "warning", "title": "Сертификат истекает через 6 дней",
       "action": {"label": "Продлить", "href": "/sites/demo-static/ssl/"}}
    ]}
  </script>
</sf-list-attention>
```

Поля проблемы:

| Поле | | Значение |
|:---|:---|:---|
| `id` | обязательно | Имя проблемы у хоста; приходит в событиях. |
| `title` | обязательно | Что случилось, коротко. |
| `status` | | `error`, `warning`, `info` или `success`; `danger` читается как `error`, другое значение — как `info`. |
| `text` | | Одна строка подробностей под названием. |
| `action` | | `{label, href}` — ссылка; `{label, event}` — кнопка, нажатие которой отправляет событие. |

Проблема без `id` или `title` пропускается. Список сортирует, считает и
рисует. Проблемы — забота хоста: он проверяет, выполняет действия и задаёт
весь список заново, когда проблема появилась или прошла.

## Варианты

### Заголовок

`label`, `heading-level` • по умолчанию «Требует внимания», уровень `3` • [справочник](#атрибуты)

`label` — заголовок списка, рядом с ним стоит число проблем. Без него — «Требует
внимания» на русской странице и «Needs attention» на остальных.
`heading-level` — уровень заголовка в структуре страницы, от `2` до `6`.

:::example {id="smart-components/list-attention/heading" label="Заголовок по умолчанию и свой" preview=sandbox}
:::

### Размер

`size` • по умолчанию `1` • [справочник](#атрибуты)

`1` — для основной колонки страницы, `1/2` — для боковой панели. От размера
зависят текст, иконка, кнопка действия и высота строки: строка в одну линию
высотой с поле того же размера.

## Состояния

### Нет проблем

`empty`, `empty-text` • по умолчанию `none` • [справочник](#атрибуты)

С `empty="none"` пустой список не рисует ничего. С `empty="line"` — одну тихую
строку с галочкой: «Всё в порядке» или текст из `empty-text`.

## Поведение

### Порядок

Проблемы идут по серьёзности: ошибка, предупреждение, сведения, успех;
внутри одного состояния — в порядке хоста. Хост может узнать самое серьёзное
показанное состояние из атрибута `data-status` на элементе, а пустой ли
список — из `data-empty`.

В колонке уже 360 px действие уходит под текст.

### Действия и события

Нажатие на ссылку действия отправляет `sf-list-attention-navigate` с
`{id, status, href}`. Это просьба: страница с маршрутизатором отменяет
событие и переходит сама; без отмены браузер переходит по `href`. Нажатие с
клавишей-модификатором или средней кнопкой открывает ссылку в другом месте и
ничего не спрашивает.

Нажатие на кнопку действия отправляет `sf-list-attention-apply` с
`{action, scope, ids, id, status}`: `action` — `event` из действия, `scope` —
`entry`, `ids` — `[id]`. Хост выполняет действие и задаёт список заново. В
примере в начале страницы обе ссылки отменены и показаны в журнале, а
«Перезапустить» убирает проблему из списка.

```js
const list = document.querySelector('sf-list-attention');
list.addEventListener('sf-list-attention-apply', async (event) => {
  await restartSite(event.detail.id);
  list.items = await loadProblems();
});
```

## Доступность

- Список — область страницы, названная своим заголовком; проблемы —
  список.
- Каждая проблема говорит своё состояние словом перед названием: «Ошибка: …».
  Иконка — не единственный признак.
- `Tab` проходит по действиям по порядку; `Enter` открывает ссылку, `Enter`
  или `Пробел` нажимают кнопку.
- Список не забирает фокус и не объявляет новые проблемы сам: если новую
  проблему нужно прочитать вслух, хост объявляет её сам.

## Справочник

### Атрибуты

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `label` | строка | — | — | Заголовок; если не задан — «Требует внимания» / «Needs attention» на языке страницы. Рядом стоят значки итога, по одному на степень важности. |
| `heading-level` | целое число | `3` | от 2; до 6 | Уровень заголовка в структуре страницы. |
| `frame` | строка | `card` | `card`, `none` | `card` (по умолчанию) рисует список карточкой на поверхности: тонкий край, скругление поверхности, шапка и низ — её полосы; `none` — голый список, строки по краю текста страницы. |
| `triage` | да/нет | нет | — | У каждой проблемы есть меню «⋯»: «Отложить на день», «Отложить на неделю» и, где человеку можно, «Не напоминать». Выбор запрашивает `snooze {id, until}` или `dismiss {id}`, затем откладывает проблему с уведомлением, в котором «Вернуть» отправляет `undo`. Проблема с `help` получает меню и без этой настройки (только «Подробнее о проверке»). |
| `dismissible` | да/нет | нет | — | Этот человек может убирать проблемы («Не напоминать»): разрешение страницы, и только оно его даёт; `dismissible: false` у пункта забирает его у этого пункта, а `dismissible: true` ничего не даёт. |
| `checked-at` | строка | пусто | — | Когда проверки шли в последний раз (дата-время ISO или миллисекунды): внизу написано «Проверено 5 мин назад» / «в 14:05» / «9 ноября в 14:05» с кнопкой «Проверить снова», которая отправляет `recheck`; пустая строка говорит «Всё в порядке · проверено …». |
| `limit` | целое число | `5` | от 0 | Не больше стольких строк; остальные — за «Все проблемы (N)» (`more-href`) или «Показать все (N)» на месте. `0` показывает все строки. В режиме групп видны все строки. |
| `more-href` | строка | пусто | — | Страница всех проблем: «Все проблемы (N)» внизу — ссылка на неё, а нажатие — отменяемый запрос `all {href}`. |
| `group` | строка | `none` | `none`, `severity` | `severity` — полная страница проверок: раскрывающаяся группа на каждую степень важности («Ошибки», «Предупреждения», «Рекомендации») открыта, «Пройдено» закрыта, выровненная колонка с числом затронутых объектов; время проверок в шапке. |
| `empty` | строка | `line` | `none`, `line` | Без пунктов: `line` (по умолчанию) рисует шапку и одну тихую строку — `empty-text` с галочкой, с `checked-at` после неё «· проверено …» и кнопку «Проверить снова»; `none` не рисует ничего (место не занято). |
| `empty-text` | строка | — | — | Текст тихой строки при `empty="line"`; без него — «Всё в порядке» на русской странице и «All is well» на остальных. |
| `items` | список | `[]` | — | Проблемы, которым нужен человек, каждая — `{id, status error\|warning\|info\|success, title, text?, object?: {label, href?}, since?, source?, affected?, help?, dismissible?, action?: {label, href} или {label, event}}`. `object` — то, чего касается проблема (ссылка с `href`), `since` — с какого момента она есть (дата-время ISO или миллисекунды; строка показывает, сколько она длится), `source` — раздел или проверка, откуда она, `affected` — сколько объектов она затрагивает (колонка в режиме групп), `help` — ссылка о проверке (меню «⋯»), `dismissible: false` убирает «Не напоминать» у этого пункта (разрешение даёт `dismissible` приложения; пункт может его забрать, но не дать). Свойство или JSON-остров, который печатает сервер; приложение задаёт весь список заново, когда проблема появляется или уходит. Список упорядочен по важности (`error`, `warning`, `info`, `success`), внутри статуса первыми идут самые давние, где задан `since`, затем — порядок приложения. Пункт без `id` или `title` пропускается; другой статус читается как `info`. |
| `passed` | список | `[]` | — | «Пройдено» в режиме групп: проверки, которые прошли, — строки или `{id?, title, text?}`; закрытая группа после проблем. |

#### Общие для всех компонентов

| Атрибут | Тип | По умолчанию | Значения | Что делает |
|:---|:---|:---|:---|:---|
| `template` | строка | `default` | — | Имя шаблона отрисовки; `default` — встроенный. |
| `root-class` | строка | пусто | — | Свои CSS-классы для нарисованного элемента. |
| `root-style` | строка | пусто | — | Свои стили для нарисованного элемента, например `max-width: 20rem`. |

Каждому атрибуту соответствует свойство элемента с тем же именем в camelCase: `icon-start` — `iconStart`. Свойство атрибута `template` называется `templateName`.

### Методы

Публичных методов нет.

### События

События приходят на сам элемент и всплывают; глаголы в именах — из [общего словаря](/ru/guide/smart-components/names/). Общие события базового элемента — в главе [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс).

| Событие | `detail` | Когда приходит |
|:---|:---|:---|
| `sf-list-attention-navigate` | `{ id: string, status: string, href: string, part: string }` | Человек нажал ссылку пункта: его действия (часть `action`), его объекта (часть `object`) или «Подробнее о проверке» в меню «⋯» (часть `help`); в событии `{id, href}`. Это запрос: страница отменяет его, чтобы перейти сама (роутер); не отменили — браузер переходит по `href`. Нажатие с клавишей-модификатором или средней кнопкой открывает ссылку в другом месте и ничего не спрашивает. |
| `sf-list-attention-apply` | `{ action: string, scope: string, ids: array, id: string, status: string }` | Человек нажал кнопку действия проблемы (действие без `href`): `action` — `event` из действия, `ids` — `id` проблемы. Хост выполняет действие, например перезапускает задание или открывает окно, и задаёт список заново. |
| `sf-list-attention-snooze` | `{ id: string, until: string }` | Человек выбрал «Отложить на день» или «на неделю» в меню «⋯» пункта: `until` — момент ISO через один или семь дней. Это запрос: отменили — ничего не меняется; не отменили — пункт сразу откладывается, а уведомление говорит об этом и предлагает «Вернуть». Отсрочку хранит ваше приложение и до её конца не показывает пункт в списке. |
| `sf-list-attention-dismiss` | `{ id: string }` | Человек выбрал «Не напоминать» (только там, где это разрешает `dismissible`). Это запрос: отменили — ничего не меняется; не отменили — пункт откладывается с уведомлением и кнопкой «Вернуть»; хранит выбор ваше приложение. |
| `sf-list-attention-undo` | `{ id: string, action: string }` | Человек нажал «Вернуть» в уведомлении об отсрочке или отказе (`action` — `snooze` или `dismiss`): пункт вернулся в список, приложение забывает сохранённый выбор. |
| `sf-list-attention-recheck` | пустой объект | Человек нажал «Проверить снова» (кнопка видна вместе с `checked-at`). Приложение запускает проверки и задаёт `items` и `checked-at` заново. |
| `sf-list-attention-all` | `{ href: string }` | Человек нажал «Все проблемы (N)»: с `more-href` это ссылка, и сначала идёт запрос (роутер его отменяет); без него — «Показать все (N)», и если запрос не отменён, все строки показываются на месте. |
