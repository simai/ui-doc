# Всплывающие сообщения

`<sf-toast>` показывает одно короткое сообщение о результате действия:
статус, заголовок, пояснение, необязательное действие и кнопку закрытия. Для
постоянного текста внутри страницы берите
[уведомление](/ru/smart/feedback/alert/), для выбора, без которого
работу не продолжить, — модальное окно.

То же на классах — [Всплывающие сообщения](/ru/components/feedback/toast/):
сообщения на классах без смарт-элемента и область уведомлений страницы
`SF.notify`.

## Разметка

Сообщению нужен заголовок; пояснение, иконка и действие добавляются по задаче:

```html
<sf-toast status="success" icon="check_circle" title="Изменения сохранены"
  supporting-text="Новая версия доступна участникам проекта."></sf-toast>
```

`title` — короткий заголовок результата, `supporting-text` — пояснение
обычным размером текста, `icon` — декоративная иконка.

## Варианты

### Статус

`status` принимает общий словарь статусов: `neutral`, `info`, `success`,
`warning`, `error`. Выбирайте его по смыслу сообщения, а не по желаемому цвету.
Иконку статус не добавляет: её задаёт атрибут `icon`.

:::

## Поведение

### Время жизни

По умолчанию сообщение остаётся до закрытия. `duration` задаёт время жизни в
миллисекундах; отсчёт приостанавливается, пока указатель или фокус находится
внутри сообщения. Сообщение с действием оставляйте без `duration`: пользователь
должен успеть его выполнить.

```html
<sf-toast status="success" title="Ссылка скопирована" duration="5000" role="status"></sf-toast>
```

### Действие и закрытие

`action-text` показывает одну кнопку действия, `action` — машинное значение,
которое приходит в событии. Нажатие отправляет `sf-toast-action` с
`detail.action`; закрытие отправляет `sf-toast-close` и удаляет элемент.
Бизнес-действие выполняет приложение.

```js
const toast = document.querySelector('sf-toast');
toast.onAction((action) => {
  if (action === 'undo') restoreFile();
});
toast.onClose(() => console.log('Сообщение закрыто'));
```

`closable="false"` убирает кнопку закрытия; закрыть такое сообщение может
только таймер или метод `close()`.

### Размещение

Результат действия показывайте через
[`SF.notify`](/ru/components/feedback/toast/#уведомления-страницы-sf-notify):
у страницы одна область уведомлений, и она лежит выше открытого модального
окна. Свой контейнер с `<sf-toast>` нужен, когда приложение само управляет
местом и набором сообщений.

Toast отвечает за одно сообщение. Позицию на экране, порядок и число
одновременно показанных сообщений задаёт контейнер приложения. Обычный
контейнер — фиксированный столбец в углу экрана:
`fixed block-end-b6 inline-end-b6 z-9 flex flex-col gap-2`. Сообщения
добавляются в него через `append()` и сами удаляются при закрытии или по
истечении `duration`.

:::example {id="smart-components/toast/container" label="Контейнер сообщений"}
:::

Это правило — только для своего контейнера. Открытое модальное окно лежит
выше слоя `z-9`, поэтому сообщение из своего контейнера окажется под окном:
результат действия в окне показывайте из него после `close()`. `SF.notify`
можно вызывать и при открытом окне — его область лежит выше окна.

## Доступность

- Сообщению, которое вставляется динамически, нужна живая область.
  Надёжнее всего контейнер, который есть на странице с первой загрузки и
  несёт `role="status"`, как в примере: вставленное в него сообщение
  зачитывается, и своя роль сообщению не нужна. Живую область, которая
  появляется на странице сразу с текстом, не все программы чтения экрана
  озвучивают. Без такого контейнера задайте самому сообщению
  `role="status"` для обычного результата и `role="alert"` для срочной
  ошибки. Сообщению, которое есть на странице с первой загрузки, живая роль
  не нужна.
- `close-label` задаёт доступное имя кнопки закрытия; по умолчанию оно на
  языке страницы («Закрыть сообщение»), передавайте его, только чтобы
  заменить текст.
- Не помещайте в исчезающее сообщение обязательный шаг или сведения, которые
  легко пропустить: таймер приостанавливается при фокусе и наведении, но не
  ждёт, пока пользователь доберётся до сообщения.
- Кнопки действия и закрытия — нативные кнопки в обычном порядке `Tab`.

### Методы

| Метод | Возвращает | Что делает |
|:---|:---|:---|
| `close()` | объект | То же, что dismiss: отправляет sf-toast-close и удаляет уведомление. |
| `show(text: string, code: string, count: number, tone: any)` | объект | Действие show. |
| `setState(nextState: object)` | объект | Записывает каждый ключ как атрибут в kebab-case: false, null, undefined или пустое значение удаляет его, true устанавливает пустым, всё остальное приводится к строке. |
| `onAction(handler: function, options?: object\|boolean)` | объект | Добавляет обработчик sf-toast-action; обработчик вызывается с (action, detail, event). Обработчик, не являющийся функцией, игнорируется. |
| `onClose(handler: function, options?: object\|boolean)` | объект | Добавляет обработчик sf-toast-close; обработчик вызывается с (detail, event). Обработчик, не являющийся функцией, игнорируется. |

### События

События приходят на сам элемент и всплывают; глаголы в именах — из [общего словаря](/ru/guide/smart-components/names/). Общие события базового элемента — в главе [Модель компонента](/ru/guide/smart-components/model/#базовый-интерфейс).

| Событие | `detail` | Когда приходит |
|:---|:---|:---|
| `sf-toast-action` | `{ action: string }` | Отправляется один раз при активации необязательного доступного действия. |
| `sf-toast-close` | `{ reason: any }` | Отправляется один раз, перед тем как закрытие по токену удалит владельца уведомления. |
| `sf-toast-closed` | `{ reason: any }` | — |
