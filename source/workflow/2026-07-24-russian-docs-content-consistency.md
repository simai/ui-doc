# Workflow: согласованность русской документации SIMAI Framework

Дата: 2026-07-24
Статус: completed

## Goal

Проверить разделы «Старт», «Основы» и «Утилиты» на визуальные и
содержательные разрывы, восстановить полезные изображения из исходного
описания и гарантировать, что примеры остаются читаемыми при сбое
необязательной подсветки синтаксиса.

## Done When

- код во всех fenced-блоках видим до и после загрузки подсветки;
- 30 встроенных изображений исходного Markdown инвентаризированы;
- в сайт перенесены только актуальные и полезные иллюстрации;
- у каждого добавленного изображения есть содержательный alt-текст;
- изображения палитры, ролей и радиусов находятся рядом с соответствующим
  объяснением, а не образуют отдельный несвязанный архив;
- локальная production-сборка проходит проверку ссылок и ассетов;
- репрезентативные страницы проверены визуально по HTTP;
- GitHub и удалённая production-версия не изменяются.

## Scope

- русские разделы `start`, `fundamentals`, `utilities`;
- общий CSS документации, влияющий на читаемость примеров;
- изображения из файла
  `SIMA Framework UI Utilities v5.3 (полное описание).docx (1).md`;
- актуальность по исходникам `ui` версии 5.4.

Компоненты и Smart Components не изменяются.

- 28 изображений — палитры, роли и примеры их применения;
- 1 изображение — схема шкалы радиусов;

- токен-таблицы на изображениях не заменяют source-backed таблицы в
  документации и не переносятся как единственный источник значений.

## Constraints

- не переносить логотип и дублирующие скриншоты таблиц ради самого количества;
- не подменять точные таблицы токенов растровыми изображениями;
- не восстанавливать старые URL или архивные страницы;
- не исправлять репозиторий `ui` в рамках документационного batch;
- не выполнять push, merge или удалённый deploy.

## Known upstream issue

`component/highlight` формирует неверный URL динамического chunk. Документация
должна оставаться читаемой и без этого необязательного улучшения; отдельная
рекомендация по исправлению runtime уже зафиксирована в плане развития
фреймворка.
