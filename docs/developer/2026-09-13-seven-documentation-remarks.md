# Исправление семи замечаний к документации

Цель: читатель находит элемент по задаче, понимает устройство Smart-компонентов и проверяет примеры без Studio. ИИ получает те же исходные сведения с привязкой к пакетам.

Решения:
- «Комплексный Smart-компонент» — канонический термин для составного сценария. Это не отдельный базовый класс и не автоматическая поддержка JSON-композиции.
- Каталоги сгруппированы по задачам; config/catalog-groups.json содержит полный состав. Старые адреса перенаправляются в новый каталог.
- Последовательный переход остаётся в стандартной навигации Docara; ручные «Что дальше» удалены.
- Учебные примеры используют настоящий SF.smart и SF.Composition из зафиксированной пары. Уроки о создании, свойствах, событиях, шаблонах, слотах и проектном подключении отделены.
- AI First 0.1 для русского раздела экспортируется штатной командой docs:build: корневой и постраничные ai.json, полные Markdown с кодом и framework-lock. Это не механизм автоматического доступа внешнего ИИ к локальному домену.
- Цвет навигационной цепочки исправлен в изолированной ветке Docara и поставляется проверяемым compatibility patch. Проверяющий скрипт Docara также принимает отдельный список генерируемых демонстраций: все файлы перечислены с хешами и проходят общую проверку ссылок. Необъявленный HTML по-прежнему вызывает ошибку. Незавершённый основной checkout Docara сохранён.

Проверки: docs:check проверяет структуру и контракты, docs:ai:check обнаруживает дрейф экспорта; check-ai-schema.py проверяет совместимость со схемой AI First и целостность представлений. Браузерная проверка должна подтвердить действия примеров, мобильную ширину, темы, RTL, навигацию и цвета.

Границы: это не полная продуктовая приёмка всех Smart-компонентов. Экспериментальные или неполные элементы сохраняют свои статусы. Декларативные типы и браузерные классы имеют разные контракты. CSS предпросмотра макетов намеренно минимален, внешние данные демонстрируются без сетевого доступа.

Улучшение процесса: общий CI теперь запускает docs:check целиком. Изменения исходного поведения должны сопровождаться пересмотром привязанного урока и выполнением его примера, а не только генерацией справочных таблиц.

## Проверяемость

`contracts/documentation/smart-lessons.json` фиксирует исходную ревизию и пару Core/Smart. Изменение пары останавливает проверку уроков до нового содержательного ревью. Экспорт AI разбит на небольшие каталоги одной ревизии; проверяется не только схема, но и чтение эталонной реализацией AI First.

Локальный browser smoke: `PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core/index.mjs DOCS_BASE_URL=https://ui-doc.test node scripts/qa/documentation-review.mjs`. Проверка выполняет действия, проверяет перенаправления, группы меню, мобильную ширину, темы и RTL. Путь к Chrome задаётся через CHROME_PATH.

ИКР: теория читается последовательно, справочник ищется по задаче, а поведение видно и проверяемо в одном месте. Переиспользованы базовый класс Framework, штатный internal_preview Docara, общий источник examples и формат AI First. Удалены повторные переходы и ошибочные адреса старых ассетов. Новая сложность ограничена генераторами демонстраций и AI-выдачи; отдельный реестр файлов нужен для строгой проверки сборки. Идеальность: пользователь получает работающий пример и его исходник без запуска Studio, а CI обнаруживает дрейф версий и материалов.

## Приёмка реализации

- `composer docs:check`, проверка мигратора, `composer validate`, `git diff --check`: pass.
- Production: 960 обычных страниц; verify-static: 2066 HTML с перенаправлениями и демонстрациями, 382957 локальных ссылок, broken = [].
- AI First: 530 русских страниц; JSON Schema и эталонный читатель: structure/publication pass. Выполнение capabilities не заявлено. Повреждение Markdown обнаруживается проверкой; исходный файл восстановлен.
- Browser: счётчик, событие через три уровня, реальный внешний шаблон, три макета, неверный JSON и неизвестный тип; старые адреса, мобильное меню, темы и RTL: pass.
- Compatibility patch проверен с чистой закреплённой версией Docara и с предыдущим локальным кандидатом.
- Сборка сохраняет предупреждения существующих отчётов: 92 authoring, 755 translation, 226 documentation-tracking. Они не представлены как закрытая полная ревизия всего корпуса.
