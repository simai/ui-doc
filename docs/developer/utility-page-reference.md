# Эталон страницы утилиты SIMAI Framework

Этот эталон применяется к русским страницам в `content/ru/utilities`. Его цель
— сделать каждое утверждение проверяемым по зафиксированному комплекту
SIMAI Framework и дать читателю пример, который работает через Loader без
подключения полного набора утилит.

## Обязательная структура

1. **Назначение.** Одним абзацем объяснить пользовательский результат и назвать
   CSS-свойство, которым управляет утилита.
2. **Наглядный пример.** Разместить переиспользуемый `:::example` до длинной
   справочной части. Пример должен быть самостоятельным HTML-фрагментом.
3. **Классы и значения.** Для каждого публичного шаблона класса указать точное
   CSS-значение или токен. Диапазоны допустимо объединять только тогда, когда
   правило едино для всего диапазона.
4. **Варианты.** Явно перечислить responsive- и state-варианты. Отрицательные
   значения описывать только для семейств, где они есть в CSS и Loader rule.
5. **Псевдонимы.** Отделить канонические имена от совместимых устаревающих
   псевдонимов. Если псевдонимов нет, написать об этом прямо.
6. **LTR/RTL.** Для логических сторон объяснить переключение `inline-start` и
   `inline-end`; для независимых от направления свойств зафиксировать это.
7. **Ограничения.** Указать отсутствующие варианты, границы шкалы, требования
   браузера и конфликтующие сочетания классов.
8. **Копируемый фрагмент.** Привести минимальный HTML без проектного CSS и без
   ручного подключения полного utility bundle.

## Источники истины и проверка

Для каждой документируемой семьи проверяются пять связанных поверхностей:

| Поверхность | Что подтверждает |
|:---|:---|
| Accepted registry | Публичную семью, readiness, asset root и список Loader rules |
| `distr/rule/rule.json` | Что класс будет обнаружен Loader и какой variant загрузится |
| `distr/utility/<family>/<variant>/css/<variant>.css` | Реальный селектор и декларацию |
| Markdown и `examples/` | Полноту объяснения и копируемый HTML |
| Собранная страница | Что Docara запросила точечные модули, а не полный набор утилит |

Проверка всегда привязана к `simai-framework.lock.json`. Коммит Core и SHA-256
registry в проверяемом архиве должны совпадать с lock; проверять moving branch
или другой checkout вместо зафиксированной ревизии нельзя.

## Минимальный пример страницы

```markdown
# Название утилиты

Кратко: какую задачу решает и каким CSS-свойством управляет.

## Наглядный пример

:::example {id="utilities/group/name" label="Понятный результат"}
:::

## Классы и значения

| Класс | Значение |
|:---|:---|
| `name-{value}` | `property: var(--sf-token-{value});` |

## Адаптивность и состояния

Поддержаны `sm`, `md`, `lg`, `xl`; state- и negative-варианты не выпускаются.

## Направление, псевдонимы и ограничения

Поведение в LTR/RTL, канонические имена, aliases и реальные ограничения.
```

## Критерий готовности примера

Пример принят, если его целевые классы одновременно:

- присутствуют в HTML и совпадают с подписью `aria-label`, когда она задана;
- распознаются точным Loader rule;
- имеют селектор и ожидаемую декларацию в CSS той же семьи и варианта;
- относятся к публичной записи accepted registry;
- появляются среди точечно предзагруженных модулей собранной страницы;
- дают ожидаемый computed style в браузере на применимых desktop/mobile и
  LTR/RTL сценариях.

Сборка, static verification и browser acceptance остаются отдельными
состояниями. Успех одного из них не заменяет остальные.
