# Эталон страницы компонента SIMAI Framework

Эталон применяется к русским страницам `content/ru/components`. Он помогает
разработчику выбрать компонент, скопировать рабочую разметку и проверить её по
точному комплекту SIMAI Framework, не превращая документацию в копию исходника.

## Обязательная структура

1. **Назначение.** Какую пользовательскую задачу решает компонент и когда нужен
   другой элемент.
2. **Быстрый старт.** Минимальная семантическая разметка и исполняемый
   `:::example` до длинной справочной части.
3. **Состав и ответственность.** Что принадлежит нативному control, оболочке,
   field/group или сложной композиции.
4. **Публичные классы и API.** Только классы, параметры, методы и события,
   подтверждённые exact source и generated runtime.
5. **Варианты, размеры и состояния.** Значения, допустимые сочетания и
   отсутствие неподдерживаемых вариантов.
6. **Доступность.** Семантика, доступное имя, клавиатура, фокус, error/loading и
   reduced motion, когда они применимы.
7. **Responsive и LTR/RTL.** Что меняется на узкой ширине и какие стороны
   являются логическими либо физическими.
8. **Ограничения и проверка.** Readiness registry, внешние обязанности
   приложения и известные source defects без выдуманного обхода.

## Источники истины

Для каждого компонента проверяется одна цепочка:

| Поверхность | Что подтверждает |
|:---|:---|
| exact source | Публичное поведение, методы, события и ограничения |
| `distr/rule/rule.json` | Условие обнаружения Loader и связанные модули |
| `distr/component/<name>` | Фактические CSS и JavaScript generated Core |
| Framework contract registry | Владелец, readiness, asset root и зависимости |
| Markdown и `examples/` | Объяснение и копируемый сценарий |
| Собранная страница и браузер | Загрузку модулей, состояние, keyboard, responsive, темы и LTR/RTL |

Source, Builder, Core и Smart фиксируются полными Git revisions в evidence
батча. Moving branch, произвольный локальный checkout и имя версии без commit
не доказывают тот же runtime. Если registry или generated-артефакт содержит
другую lineage, расхождение оформляется как source defect; документация не
исправляет owner source или Framework lock.

## Control, field и group

Для элементов формы действуют три независимые области:

- нативный control владеет значением, фокусом, нативной проверкой и отправкой;
- field связывает control с подписью, пояснением и сообщением ошибки;
- group задаёт общий вопрос и правила для нескольких controls.

CSS-класс не должен подменять нативный атрибут, доступное имя или серверную
проверку.

## Критерий готовности примера

Пример принят, если:

- его корневой маркер распознаётся Loader rule;
- registry разрешает компонент хотя бы как `discoverable` и ведёт к
  существующему asset root;
- generated CSS и JavaScript существуют в exact Core;
- используемые классы, методы и состояния подтверждены исходником;
- HTML имеет корректную структуру и не подключает полный component bundle;
- keyboard, focus, responsive, light/dark и LTR/RTL проверены в применимых
  сценариях;
- любое расхождение имеет минимальное воспроизведение и владельца исправления.

## Ограниченная проверка эталонного батча

```bash
node scripts/audit-component-reference-batch.mjs \
  /absolute/path/to/exact-core \
  /absolute/path/to/exact-source \
  /absolute/path/to/exact-smart \
  --source-revision=<full-commit> \
  --builder-revision=<full-commit> \
  --core-revision=<full-commit> \
  --smart-revision=<full-commit> \
  --documentation-status=/absolute/path/to/component-status.json \
  --json
```

Успех component audit, сборки, static verification и browser acceptance —
разные состояния. Ни одно из них не заменяет остальные.

## Контракт актуальности страницы

Для компонента с файлом в `contracts/documentation/components/` действует ещё
одна проверка. Контракт хранит хеши просмотренных source и generated файлов и
ссылки на обязательные примеры. Изменение этих файлов останавливает CI до того,
как автор пересмотрит текст, примеры и явно обновит хеши через `--refresh`.

```bash
node scripts/audit-component-documentation-contracts.mjs \
  --source-root=/absolute/path/to/ui-source \
  --core-root=/absolute/path/to/ui
```

Новый компонент подключается добавлением одного JSON-контракта. Поэтому этот
же механизм можно постепенно распространить на весь каталог компонентов без
создания отдельного проверочного скрипта для каждой страницы.
